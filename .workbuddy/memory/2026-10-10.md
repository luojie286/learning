### 关键教训（重要，防再犯）

- **会话中断恢复后，千万别直接 `git restore -- .`**：它会用 index 覆盖工作区，把"修改过的已跟踪文件"全部回滚。本次就因此回滚了 java/00、java/18、java/23 三处未提交的增强，只能从归档源文件重建。正确做法：`git restore` 只针对具体误删路径，或先 `git stash` 保存工作区。
- **大改前先 commit**：分阶段提交（每波整合一次）能避免中断丢失。
- 乱码文件名根因：之前某次会话用错误编码写文件名，UTF-8 中文变成 `Java90E7AF…` 十六进制形态。本次已按内容重命名为可读名（如 `Java后端学习笔记_从HTTP请求到SpringBoot.md`），新笔记「来源」行同步更新。
- git push 仍用可靠解法：`GIT_TERMINAL_PROMPT=0 git -c credential.helper= -c credential.helper=store push origin main`（本次成功 `9cab0ff..d3f396e`）。
