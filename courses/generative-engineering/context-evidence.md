# 模型上下文、注意力与证据边界

## 注意力是计算，不是人的心理资源

Transformer 的缩放点积注意力可写为 `softmax(QKᵀ/√dₖ)V`，用 query 与 key 的关联分数加权 value。多头、多层、残差和前馈网络共同参与计算，不能只凭一个比喻断言“某类文字一定抢走注意力”。注意力权重也不是输出正确性的直接证明。

原始 Transformer 论文是特定模型结构与任务的研究，不披露所有后续商业模型的内部实现。“GPT5 之后注意力收敛机制完善”“逻辑太强必然污染注意力导致幻觉”没有可核验来源，本课程不将其作为事实，也不以架构术语替代观察证据。

角色描述、示例、格式约束是否有效取决于模型、任务与评价方式。可明确任务对象和验收标准，而不是认定“专家”称号必有用或已永远没用。若要判断提示效果，用同一组任务对照，记录模型版本、输入、设置和指标，避免从一次对话得出普遍规律。

## 长上下文研究支持怎样的结论

Lost in the Middle 在其所测多文档问答和键值检索任务中观察到信息位置会影响表现，长上下文能力不保证有效使用全部信息。其结果有研究模型、任务和年份范围，不能直接宣称所有当前模型都遵守相同曲线，也不能推出“上下文越短必定越好”。

工程上的合理启发是优先提供相关、可定位资料，删去过期或矛盾记录，并保留必要的约束和证据。这是可测试的工作方法，不是对未知内部机制的确定解释。

## 例子：让模型修登录接口

输入至少包含预期行为、复现请求、实际错误、入口代码及认证链相关实现。仅说“登录坏了”信息不足，把整个仓库和过期讨论全部贴入也不保证解决。先定位 Controller→Service→认证组件的数据流，再补充缺失文件。

可用以下上下文结构：

```text
目标：合法凭据返回会话，非法凭据返回约定错误。
复现：具体测试输入、实际响应、环境版本。
约束：密码不得明文保存，保持现有接口兼容。
证据：相关文件路径、日志与最小调用链。
验收：成功、错误密码、锁定账户、会话过期测试。
未知：哪些行为尚未核实，允许通过什么方式核实。
```

这里是工程示例，不是某产品专用提示语。模型提出修复后仍需检查代码与测试，解释流畅不代表诊断正确。

## 读论文时区分作者主张和个人推断

先写问题、既有方法、增量贡献，再检查数据集、指标、对照与消融、限制。请模型指出支持结论的具体章节或表格，再人工核对原文；无法访问全文时不能冒充已经阅读。论文改进某个基准，不等于你的生产任务同样获益。

记录三栏：原文证据、由证据可支持的结论、个人待验证假设。对“强化学习让模型一味附和”的笼统说法，已有研究讨论迎合行为，但单一训练环节不是所有模型所有输出的充分解释，需具体实验。

## 长任务的上下文管理

阶段记录保存已完成内容、当前约束、未解问题与下一步证据入口。重复读取巨大材料会增加处理成本，具体费用还取决于输入输出长度、缓存、模型与工具，不能写成固定增长公式。摘要可能丢细节，关键需求仍链接可追溯原文；切换阶段时更新记录，而不是让陈旧判断无限累积。

## 模拟面试问题

1. 基础理解：注意力的 Q、K、V 分别参与什么计算？
2. 实际应用：为什么不能用注意力比喻证明某种提示总是有效？
3. 实际应用：修登录接口应提供哪些最小充分上下文？
4. 深入追问：论文在特定基准上的结论如何迁移到工程任务验证？
5. 深入追问：阶段摘要怎样保持证据可追溯而避免过期信息？
