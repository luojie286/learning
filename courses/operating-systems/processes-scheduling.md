# 进程、线程与调度：谁在等待什么

## 隔离资源与保存执行现场

进程是地址空间和资源管理的重要单位，线程是其中执行流。一个进程的线程通常共享代码、堆和文件描述符，各自有寄存器现场与栈。PCB/TCB 是教材抽象名，真实内核组织可能不同，不必寻找和教材表格完全一一对应的结构。

函数调用的栈帧可能保存返回信息、局部数据、溢出参数与寄存器；确切布局由 ABI、架构与优化决定，不是所有参数都必须先放栈上。递归深度大可能耗尽栈，Java StackOverflowError 与 Python RecursionError 是不同运行时表现。尾调用优化也不能在 Java/Python 中一概假定。

用户态不能任意修改页表、直接操控全部硬件。程序经系统调用请求内核服务，但“进入内核唯一途径是系统调用”不准确，异常与外部中断也会进入内核处理。普通内存清零不是普遍意义的特权指令，IO 指令权限也依赖架构和配置，不能将教材例子推广为所有 CPU 事实。

## 就绪和阻塞：缺的是哪种资源

三态模型中，就绪只等 CPU；运行正在执行；阻塞在等 IO、锁或定时事件，给 CPU 也无法继续。唤醒先成为可调度状态，再获得 CPU；实际可能立即被调度，图里的中间步骤是逻辑区分。

Spring Boot 一个请求线程调用阻塞数据库查询，在网络/驱动等待期间可能不占 CPU。此时把线程池开得更大不一定更快，还会增加栈、调度与数据库连接压力。CPU 密集任务则需要匹配核数与资源限制，不能用同一固定线程数公式覆盖全部负载。

Java Thread.State 与 OS 状态不一一对应，Java RUNNABLE 可覆盖就绪或正在执行等情况。不能仅凭线程转储的 RUNNABLE 就断定它一直消耗 CPU，应结合线程 CPU 时间和栈。

## 切换与用户线程映射

上下文切换保存当前 PC/寄存器等，恢复另一个执行流；跨地址空间还可能影响地址翻译与缓存。用户级线程能否多核并行，取决于是否映射到多个内核可调度线程：多对一通常不能，M:N 可以。某个阻塞调用是否拖住全部协程取决于运行时调度、调用适配与承载线程，不是“用户线程”四字决定。

系统调用不必然发生线程切换，线程切换也不必然跨进程。后端增加异步并不让 CPU 计算消失，而是改变等待时怎样复用执行资源。

## 调度算法是目标之间的取舍

FCFS 可能让短任务排在长任务后；SJF 依赖运行时长信息，在特定理想模型下优化平均等待，在线持续短任务可能饿死长任务。RR 时间片过大接近先来先服务，过小使切换比例变高。MLFQ 根据消耗 CPU 的行为调整优先级，常配周期提升缓解饥饿；原稿“反复用不完时间片就降级”写反，应是消耗完配额且仍需执行时降级，具体规则随实现。

教材高级/中级/低级调度分别描述作业接纳、挂起/激活与 CPU 分派。现代 Linux 常规服务并不总按“整个进程搬到外存”的三层模型实现。公平调度 CFS 与后来的 EEVDF 有实际版本演进，不能说当前所有 OS 都是某一种教材算法。

实时调度关注截止期：EDF 比较 deadline；LLF 看 `deadline-now-remaining`，松弛度为负代表在该模型下已不能按时完成。算法名字不等于任意任务集都有保证；需满足可调度性、执行预算及抢占模型等假设。

## IPC 的开销与同步责任

共享内存让进程映射同一内存区域，减少某些复制，但初始化、缓存一致性、同步仍有成本，不保证在每种负载下最快。消息传递可通过管道、消息队列或 socket，发送接收并不天然保证全部业务操作互斥；仍需协议、顺序和一致性设计。本机共享内存不可直接当跨机器普通内存使用，分布式共享内存是额外系统。
