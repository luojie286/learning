# 归并与基数排序：稳定性是一条约束

## 稳定性究竟保持什么

相同排序键的记录，排序后相对顺序不变，称为稳定。按提交时间排好的订单再稳定地按用户分组，同一个用户的订单仍保持时间顺序。键是完整记录的一部分，只排序整数常常观察不出稳定性。

归并将数组拆成互不重叠的半开区间，再合并两个有序段。辅助数组避免写回时覆盖未比较的数据；两边值相同时优先取左边，才能保持原来的相对次序。普通数组归并用 O(n) 辅助空间，递归深度 O(log n)，总时间 O(n log n)。链表归并或复杂原地归并是不同实现，不能因此说所有 merge 都必须申请同样的数组。

```python
def merge_sort(a):
    if len(a) <= 1:
        return a[:]
    m = len(a) // 2
    left, right = merge_sort(a[:m]), merge_sort(a[m:])
    out = []; i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    out.extend(left[i:]); out.extend(right[j:])
    return out
```

这是便于验证的教学实现；切片和临时列表会增加常数和分配次数。高频排序优先用标准库，手写用于理解与特殊定制。

## 按位排序为何需要上一轮的成果

LSD 基数排序从低位到高位，每一轮稳定地按当前位分桶。例 `[21,12,11]`：个位稳定排序得到 `[21,11,12]`，十位得到 `[11,12,21]`。十位相同的 11、12 必须保留上一轮个位顺序。

使用累计桶终点的写法时，从输入末尾向前放置并递减桶终点才能稳定。另一种正确写法是计算各桶起点后从前向后放置并递增起点；因此“基数排序必须倒序遍历输入”过于绝对，必须连同桶下标含义一起说。

LSD 不是唯一基数排序；MSD 从高位递归划分桶，同样可以正确。复杂度为 O(d(n+b))，d 是位数，b 是基数；它突破比较排序下界是因为使用关键字结构，并未违反下界的前提。

## 实际开发：批量日志的排序选择

多个文件各自按时间有序，可以分块排序后再多路归并，控制内存峰值。固定宽度非负事件编号可考虑按字节基数排序，但编号含负数时不能直接用原十进制取位模板；偏移可能在固定宽度整数溢出。处理有符号位的专门实现要说明其位表示和大小顺序。

不要把“归并最坏不退化”推成“所有场景最快”。对象比较成本、缓存、数据接近有序与库实现均影响性能。归并中若顺便数逆序对，在右值小于左值时加上左边尚未取出的数量；相等不算严格逆序。

## 边界与修订

递归终止使用长度小于等于 1，包含空数组，不能只判断 `l==r` 却允许空闭区间进入。按位循环还要防止 offset 乘基数溢出；全零数组与重复键可检查稳定性。Python 的中点计算不会发生 Java int 式溢出，不必将固定宽度风险照搬。
