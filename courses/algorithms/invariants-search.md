# 用不变量理解复杂度、二分与双指针

## 从正确的暴力法出发

算法优化不是换一个更复杂的数据结构，而是消除重复工作。对十万条订单逐条比较需要约百亿次比较；排序后扫描约为 n log n，但“某个复杂度一定能过”只是经验，还受常数、语言、总数据量与时限影响。分析空间时分别记录输入、输出和辅助空间；Python 切片会复制列表，不能把 `prices[1:]` 视为零成本。

不变量是循环开始与结束都成立的条件。例如寻找第一个大于等于 x 的位置时，维护半开区间 `[lo, hi)`：左侧已知小于 x，右侧已知大于等于 x，答案只在中间。结束时 lo==hi 就是插入边界，而不一定存在等于 x 的元素。

```python
def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

在 `[1,3,3,7]` 找 3：区间 `[0,4)` → `[0,2)` → `[0,1)` → `[1,1)`，结果 1。找 9 返回 4；找空数组返回 0。只有下标在范围内且值相等才能认定查找成功。时间 O(log(n+1))，空间 O(1)。

## 两个有序数组的中位数

在较短数组 A 二分切割 i，由 `j=(m+n+1)//2-i` 推出 B 的切割。左半总数固定，交叉满足 `Aleft <= Bright` 和 `Bleft <= Aright` 即可。若 Aleft 过大向左移，若 Bleft 过大向右移。空侧用无穷边界；两数组都空时拒绝输入，偶数平均前在 Java 中转 long 或 double，避免相加溢出。复杂度 O(log(min(m,n)+1))，不需要把全部数据合并。

## 开发场景：有序数据怎样省工作

行列分别递增的价格矩阵从右上角搜索：当前值大于目标，整列下方更大，左移；小于目标，当前行左边更小，下移。最多 O(m+n) 步。不能把它直接当一维有序数组；最后一列不一定小于下一行第一列。

三数之和先排序、固定一个下标，再让左右指针夹逼：和过小只需增大左值，和过大只需减小右值。固定值以及命中后的左右值都去重，三处规则解决的是不同重复来源；总计 O(n²)，排序辅助空间按语言实现计算。

单次买卖股票只需保留历史最低买价：先用今天价格计算利润，再更新最低价，保证时间方向。历史完整序列被一个充分统计量替代。空输入返回 0；不能用“全局最大减全局最小”忽略日期顺序。

## 适度拓展与自测边界

二分也可搜索单调可行性，但必须先证明“某个阈值可行后，更大的阈值仍可行”等单调关系。`bisect` 查找是对数时间，而 Python 列表中间插入仍需线性搬移；不要把查找加插入整体写成 O(log n)。检查重复值、全部相等、空数组、目标落在两端之外。
