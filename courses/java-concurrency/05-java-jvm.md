# 类加载、栈帧与运行时排障

> 课程基线：Java 17＋／Spring Boot 3.x（涉及 Spring 时采用 6.x、Jakarta 命名空间）。代码中标注的业务片段需要应用依赖与上下文，不等同于完整生产系统。

## 类的身份与阶段

类在 JVM 中的身份与二进制名、定义它的类加载器共同相关。加载取得定义，链接包括验证、准备和解析，初始化执行类初始化逻辑；解析可延迟，不要把简图当成所有类严格同步经历的时间线。

准备通常为静态字段分配存储并设默认值，常量变量按规范特殊处理。主动使用可能触发初始化，读取被内联的编译期常量未必触发其声明类初始化。父类通常先初始化；接口规则不能直接套“所有父接口都先初始化”。

## 运行时数据与方法调用

堆主要容纳对象与数组，线程私有栈包含方法调用帧，帧具有局部变量表、操作数栈、动态链接和返回支持。局部引用变量在线程栈里，不表示它指向的对象线程私有；多个线程完全可以通过各自引用访问同一堆对象。

方法区是规范概念，HotSpot 元空间是某些相关实现，不要把所有类元数据、静态字段和字符串都机械画进同一“永久代”。具体对象布局与分配优化也不能只靠语言层示意推断。

```java
static int total(int price, int quantity) {
    return price * quantity;
}
```

用 javap -c 查看 iload、imul、ireturn 等字节码，可理解栈式执行：加载值到操作数栈，再消费栈顶操作。JIT 后的机器码可以不同，字节码不等于每一步最终硬件指令。

## 实际开发：三类故障

- 启动 ClassNotFoundException：查依赖是否打包、运行类路径与模块路径。
- StackOverflowError：查递归终止条件、对象 toString 循环引用和调用链；增大栈通常不能修复无限递归。
- 堆持续增长：看对象数量、保留路径和缓存边界，区分泄漏、合法增长和短期分配压力。

GC 回收不可达对象，不是按“离开方法立即回收”。静态集合、监听器、ThreadLocal 值和未关闭资源可能长期保留对象。不要把每次 Full GC 都直接归因于“内存太小”。

## 排障路径

先记录 JDK 版本、启动参数、负载与错误时间，再用 jcmd、线程转储、GC 日志或堆转储寻找证据。转储可能包含用户数据，实验使用脱敏环境。CPU 高时先找热点线程与堆栈，而不是盲目改 GC 参数。
