# 回文链表：O(1) 空间算法学习笔记

> 核心目标：理解**快慢指针定位、后半段原地反转、双指针比较**的组合思想，而不是死记整题代码。

## 一、题目与约束

给定单链表头节点 `head`，判断从头到尾的节点值是否构成回文序列。

- 例如：`1 → 2 → 3 → 2 → 1` 是回文；`1 → 2 → 3` 不是。
- 目标：**时间 O(n)，额外空间 O(1)**。

### 为什么 O(1) 空间是关键？

单链表只能沿 `next` 向前访问，不能像数组一样从尾部倒着走。

若将节点值复制进数组、栈，再从两头比较，思路简单，却需要 O(n) 额外空间。

因此转换问题：**不额外保存后半段，而是改变其指针方向，使它能够从尾部向前遍历。**

## 二、核心思路：把“对称比较”转成“同向比较”

对于回文序列：

```text
1 → 2 → 3 → 2 → 1
|   |       |   |
└───────────────┘
    └───────┘
```

只要把链表后半部分反转，就可以让两个指针都沿 `next` 向前遍历，逐个比较。

三个步骤：

1. **快慢指针找中点**：确定从哪里开始处理后半段。
2. **原地反转后半段**：让后半段从尾节点向中间访问。
3. **双指针比较**：一根从原链表头走，一根从反转后的后半段头走；值不同则不是回文。

本质是：**用链表结构的局部修改，换取无需额外存储的反向访问能力。**

## 三、快慢指针：奇偶长度要分清

初始 `slow = fast = head`，循环中：

- `slow` 每次走一步；
- `fast` 每次走两步；
- 当 `fast == null` 或 `fast.next == null` 时结束。

| 链表 | 结束时 `slow` | 结束时 `fast` | 后半段如何处理 |
| --- | --- | --- | --- |
| `1 → 2 → 3 → 4` | 节点 `3` | `null` | 从 `3` 开始反转 |
| `1 → 2 → 3 → 2 → 1` | 中间节点 `3` | 最后一个节点 | 跳过 `3`，从其后开始反转 |

判断技巧：**循环结束后 `fast != null` 说明长度为奇数。** 奇数长度下，正中间的那个值不需要和任何值配对，应先执行 `slow = slow.next`。

注意：也可以从奇数链表的中点直接反转，只要比较逻辑以**后半段较短的一侧**为准并正确处理中心节点；但入门时统一“跳过奇数中点”的写法更容易推理。

## 四、原地反转：三个指针各司其职

反转链表的难点在于：一旦执行 `cur.next = prev`，原本通向后面节点的链接就被覆盖。因此必须**先保存后继，再修改指向**。

```text
prev       cur       next
 null       A   ───→  B   ───→  C

先保存 B，再把 A.next 改为 null；
然后 prev 移到 A，cur 移到 B。
```

三个指针的职责：

- `prev`：已经反转完成那一段的头节点；
- `cur`：本轮需要反转的节点；
- `next`：暂存未处理部分的入口，防止断链。

每轮遵循四步：**存后继 → 改方向 → 推进 prev → 推进 cur**。

反转结束时：

- `cur == null`；
- **`prev` 是反转后新链表的头节点**。

### 常见错误：指针在移动，但链表根本没反转

错误思路：

```java
ListNode pre = low;
while (low != null) {
    ListNode t = low;
    low = low.next;
    pre = low;
}
```

问题：

1. 从未修改任何节点的 `next`，所以链表结构没有变化。
2. `t` 没有被用来保存并重新连接指针。
3. 循环结束后 `pre` 和 `low` 都是 `null`，不是新头节点。

**检查反转代码是否真的反转：看有没有修改 `cur.next`，以及是否保留了原后继。**

## 五、比较阶段：只遍历反转后的那一半

设置：

- `first = head`，从链表开头出发；
- `second = 反转后半段的新头节点`，从原链表尾部出发。

两者同步向前走：

```text
原序列：  1 → 2 → 3 → 2 → 1
前半段：  1 → 2
反转后：  1 → 2
          ✓   ✓
```

终止条件是 **`second == null`**，因为只需对称比较长度为 `floor(n / 2)` 的两侧。

不要将“是否走回原中点”当作比较终止条件。中点并不总是比较边界，且反转后指针方向已变化，容易引发空指针异常或漏判。

> 严谨性提醒：原地反转会改变链表结构。如果题目或调用方要求链表保持原状，比较完毕后应该**再反转一次后半段并重新接回**。为了避免提前 `return false` 导致无法恢复，可以先记录比较结果，再统一恢复并返回。

## 六、可复用的轻量代码模板（Java）

### 模板 A：快慢指针找中点

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
// fast != null：奇数长度；slow 位于正中间
// fast == null：偶数长度；slow 位于右半段第一个节点
```

### 模板 B：单链表原地反转

```java
ListNode prev = null, cur = start;
while (cur != null) {
    ListNode next = cur.next; // 保存
    cur.next = prev;          // 反转
    prev = cur;               // 推进
    cur = next;
}
// prev 是反转后的头节点
```

### 模板 C：回文链表主流程（伪代码）

```text
快慢指针找到 slow
如果 fast 非空：slow 后移一步（跳过奇数中点）
second = reverse(slow)
first = head
while second 非空：
    如果 first.val != second.val：不是回文
    first、second 都后移
否则：是回文
```

这三份模板分别对应：**定位、变换、检验**。真正需要记忆的是它们的职责和边界，而不是整题实现。

## 七、易错点速查

| 易错点 | 原因 | 正确做法 |
| --- | --- | --- |
| 把 `pre = low` 误认为反转 | 变量赋值不会改变节点链接 | 必须执行 `cur.next = prev` |
| 反转前未保存 `cur.next` | 改指针后会丢失剩余链表入口 | 按“存、改、移、移”的顺序 |
| 反转结束却使用 `cur` 当新头 | 此时 `cur == null` | 用 `prev` 接收新头 |
| 奇数长度直接比较两侧 | 中心节点无需配对 | 在本方案中跳过中点 |
| 比较时按原中点停下 | 反转改变结构，中点未必是合适边界 | 以 `second != null` 为准 |
| 从 `null` 读取 `.val` | 终止条件或新头保存错误 | 先保证指针非空再访问 |
| 提前返回后未恢复链表 | 如果要求不修改输入，将留下结构变化 | 保存结果，恢复后返回 |

## 八、复杂度与更一般的算法思想

- 找中点 O(n)，反转后半段 O(n)，比较 O(n)，合计 **O(n) 时间**。
- 只使用有限数量的节点指针，不依赖链表长度，额外空间 **O(1)**。

虽然分了三趟处理，但常数趟线性扫描仍是 O(n)。

可以迁移到其他题的思想：

1. **快慢指针定位**：找链表中点、拆分链表、判断环及寻找环入口。
2. **指针重定向**：反转链表、K 个一组翻转、重排链表。
3. **局部结构变换**：当链表不支持反向遍历，可以通过原地反转，把难以直接比较的关系变成同方向比较。
4. **边界统一化**：对奇偶长度作一次显式处理，简化后面的主逻辑。

## 九、复盘时应该能独立回答的问题

1. 为什么数组或栈容易解决回文，但不满足 O(1) 空间？
2. 快慢指针结束时，奇偶长度的 `slow` 为什么落点不同？
3. 为什么 `cur.next = prev` 之前必须先保存 `cur.next`？
4. 为什么反转结束后新头是 `prev` 而不是 `cur`？
5. 为什么比较循环以反转后的半段结束为条件？
6. 如果必须保持原链表不变，最后要补哪一步？

**一句话总结：快慢指针划分前后半段，原地反转把尾部变成可向前遍历的链表，再同向逐个比较；通过修改链接而非开辟容器，实现 O(n) 时间、O(1) 额外空间。**
