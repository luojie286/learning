> 范围：本次聊天中实际涉及的算法知识。**按思想而非题号组织**；保留高频可迁移模板，其他内容重点讲推理方式、边界和错误模式。
>
> 核心主线：**识别结构 → 定义状态/不变量 → 决定遍历顺序 → 正确传递信息 → 控制重复访问 → 验证边界与复杂度。**

## 0. 先建立一套通用的解题思维

拿到一道树或网格题，先问六个问题：

1. **对象是什么？** 节点、格子、连通块，还是一段连续的有序区间？
2. **要求什么结果？** 布尔判断、一个值、一组节点、路径、最少步数，还是修改原结构？
3. **什么信息必须记住？** 祖先约束、深度、上一访问值、访问标记、连通块代表元等。
4. **访问顺序有没有要求？** 前序、中序、层序；先左后右还是先右后左？
5. **什么时候可以停止？** 空节点、越界、非法状态、找到第 k 个、所有目标处理完成。
6. **信息如何流动？** 参数自顶向下传递、返回值自底向上汇总，或者共享状态持续更新。

| 观察到的题目特征 | 优先联想的思维 |
|---|---|
| 要按距离/层数/分钟扩散 | BFS；多个起点则多源 BFS |
| 要枚举同一片区域的所有成员 | DFS/BFS 连通块搜索 |
| 重复合并、询问是否连通 | 并查集 |
| 有序数组要构造高度平衡结构 | 取中点 + 分治递归 |
| 二叉搜索树（BST），涉及大小顺序 | 上下界约束或中序有序性 |
| 第 k 小 / 按序访问 | 中序遍历 + 计数 + 提前终止 |
| 要修改树的指针而非生成新值列表 | 明确指针重接顺序，防止丢失子树 |

## 1. 递归的本质：函数契约与信息流

### 1.1 递归不是“同时向下执行”

每次调用都会产生新的调用帧。某一层运行到 `dfs(child)` 时，会**暂停当前层**，先执行子调用；子调用返回后，才继续当前层后面的语句。

递归里有两条不同的信息流：

- **自顶向下：通过参数传约束。** 如节点的合法范围 `(low, high)`、当前深度 `depth`、当前路径累计值。
- **自底向上：通过返回值传结果。** 如“这棵子树是否合法”、子树的高度、找到的节点值。

另有一种方式：**共享状态**，例如 `cnt`、`ans`、`visited`。用它时要明确谁负责更新、何时终止。

### 1.2 写递归前先写清“函数契约”

不要先写 `dfs`，要先说清：

- `dfs(node, ...)` **负责解决什么子问题**？
- 返回值**是什么含义**？例如“是否合格”或“找到的答案；没找到返回 `None`”。
- **空节点返回什么**？验证性质时通常返回 `True`；求高度/某些路径贡献时常用 `0`；查找时可用 `None`。
- 左右子问题之间是 **and / or / 求和 / 取最大 / 连接结构** 中的哪一种？

**重要：`return` 只结束当前这一层函数。** 如果答案需要沿着调用栈向上传递，上一层必须接住它并继续 `return`。

例：寻找值时，左子树返回非 `None` 说明已找到，应立即向上返回；否则再检查当前节点或右子树。若忽略子调用的返回值，就会出现“深处找到了、最外层仍拿不到答案”。

### 1.3 布尔递归的短路特性

`dfs(left) and dfs(right)` 会先算左侧；只要左边为 `False`，右边不执行。它既是**正确性语义**（两边必须都满足），也是**剪枝**（发现非法就停止）。

判断是否使用 `and`，取决于需求：

- **两个条件都成立**：`and`
- **有一个成立就够**：`or`
- **必须拿到最优值/数量**：不能直接拿布尔短路代替汇总

### 1.4 Python 中递归的三个常见坑

- **嵌套函数**：内部 `dfs` 可以直接读取外层的 `nums`、`grid`，适合一次性辅助函数；重新绑定外层整数 `cnt += 1` 时需要 `nonlocal cnt`。
- **类实例方法**：若辅助函数定义为 `Solution.build(self, ...)`，内部递归要调用 `self.build(...)`；直接写 `build(...)` 会找不到该名称。
- **递归深度**：Python 对调用栈有深度限制，网格长链、退化树可能触发 `RecursionError`。迭代 DFS/BFS 可以规避这类风险。

> 易混淆：修改外层列表内容 `ans.append(x)` 不等于重新绑定 `ans`，通常不需要 `nonlocal`。

## 2. 二叉树遍历：顺序就是解题工具

### 2.1 前序、中序、后序分别适合做什么

| 顺序 | 访问顺序 | 常见思维用途 |
|---|---|---|
| 前序 | 根 → 左 → 右 | 先处理当前节点，再递归处理子树；传递深度/边界；记录先序链表顺序 |
| 中序 | 左 → 根 → 右 | **BST 升序**；验证排序性质；第 k 小 |
| 后序 | 左 → 右 → 根 | 必须先拿到左右子树结果，再计算父节点；高度、路径贡献、树形 DP |
| 层序 | 按深度由浅到深 | 每层统计、右视图、最短层数、同步扩散 |

**关键不是背顺序，而是判断“什么时候需要当前节点的信息”。**

### 2.2 BFS 分层的关键不变量

队列中保存**已经发现、尚未处理**的节点；先进先出保证按层向外推进。

**高频模板 ①：分层 BFS**

```python
from collections import deque

q = deque([root]) if root else deque()
while q:
    size = len(q)            # 本轮开始时的当前层节点数
    for _ in range(size):
        node = q.popleft()
        # 处理 node
        if node.left:
            q.append(node.left)
        if node.right:
            q.append(node.right)
    # 一层结束：可以统计本层结果或更新层数
```

必须在 `for` 之前固定 `size`，因为循环中加入的是**下一层节点**。这使得“每轮恰好处理一层”成为明确不变量。

由此举一反三：

- **层序结果**：每层建一个局部 `level` 收集值，循环结束后附加到总答案。
- **右视图**：正常先左后右入队，则每层**最后出队**的值是这一层的最右侧值。也可以 DFS **先右后左**，首次到达某深度时记录节点。
- **按时间扩散**：每处理完一层代表过去一个时间单位，前提是队列初始层与计时约定清楚。

### 2.3 `deque` 与栈在思维上的差异

- 队列 FIFO：`append` 入队，`popleft` 出队；适合 BFS。
- 栈 LIFO：`append` 入栈，`pop` 出栈；适合迭代 DFS / 中序遍历。
- `list.pop(0)` 虽然可用，但一般是 `O(n)`；`deque.popleft()` 为 `O(1)`。
- 处理节点时通常直接 `cur = q.popleft()`，别忘出队导致死循环。
- **空节点不要随便入队**：比如二叉树中不存在的孩子 `None`，否则下一轮访问 `.val` 会报错。

### 2.4 中序迭代的“挂起现场”思维

当需要中序遍历但不想用递归，可以用栈保存“左边还没处理完，之后要回来的节点”：

**高频模板 ②：迭代中序**

```python
stack = []
cur = root
while cur or stack:
    while cur:
        stack.append(cur)
        cur = cur.left
    cur = stack.pop()       # 此刻才算访问 cur
    # 在这里处理当前节点，如检查是否严格递增或 k -= 1
    cur = cur.right
```

`stack.pop()` 才是中序意义上的“访问当前节点”；之前不断往左走只是保存回溯位置。

## 3. BST：从全局约束与有序性寻找突破口

### 3.1 BST 的性质是“整棵子树”，不只是直接孩子

普通 BST 要求：左子树的**所有值**小于当前节点，右子树的**所有值**大于当前节点；子树自身也满足 BST 性质。

不能只检查：

```text
root.left.val < root.val < root.right.val
```

因为右子树深处可能出现比根还小的值。BST **不要求高度平衡**；只有“平衡 BST”才要求额外的高度约束。

### 3.2 验证 BST：两种不同的证明方式

**方法 A：范围约束，自顶向下。**

递归时携带合法开区间 `(low, high)`：

- 当前节点须满足 `low < val < high`。
- 左子树区间变成 `(low, val)`。
- 右子树区间变成 `(val, high)`。
- 空树合法。

祖先施加的边界**不能丢失**。例如根为 `10`，右子树根为 `15`，其左孩子必须满足 `10 < x < 15`，而不只是 `x < 15`。

**高频模板 ③：BST 上下界验证**

```python
def valid(node, low, high):
    if node is None:
        return True
    if not low < node.val < high:
        return False
    return (valid(node.left, low, node.val)
            and valid(node.right, node.val, high))

answer = valid(root, float('-inf'), float('inf'))
```

**方法 B：中序有序，自左向右。**

BST 的中序遍历必须**严格递增**：每访问一个节点，都要求 `cur.val > prev`。不必先生成整个数组，只保留上一次访问的值就能判断；使用迭代中序可避免递归栈过深。

两种方法背后的思想不同：前者是**维护合法区间**，后者是**把结构性质转化为序列单调性**。

### 3.3 第 k 小：利用顺序，边遍历边停

不必先把所有节点放进数组再取 `a[k-1]`：

- 中序每访问到一个实际节点，`k -= 1`。
- 当 `k == 0` 时，当前值就是答案，立即终止。
- 迭代中序尤其适合这种“找到即返回”的流程。

如果用递归：要么使用共享的 `cnt/ans` 并设计停止标记；要么让 `dfs` 返回一个**有意义的结果或未找到标记**，并将结果逐层向上返回。`0` 可能是合法答案，因此“未找到”通常用 `None` 更安全。

复杂度：访问到第 k 小通常只需 `O(h+k)` 时间、`O(h)` 辅助空间，其中 `h` 为树高；相较于先存全部中序序列的 `O(n)` 附加存储更省。

## 4. 分治构造：中点、子问题与连接

将严格递增数组构造成**高度平衡**的 BST：

1. **选中点作为根**：使左右元素数尽可能均匀。
2. **划分两个互不重叠的子问题**：左 `[left, mid-1]`，右 `[mid+1, right]`。
3. **递归得到子树根节点**：分别接到 `root.left` 和 `root.right`。
4. **空区间返回 `None`**：`left > right` 时没有节点可建。

这里最值得学的是**递归构造的返回值契约**：`build(l, r)` 返回“由这段区间构造出的子树根节点”，而不是仅仅执行一些构造动作。

常见错误是写成 `build(left, mid)`：中点被重复包含，可能导致无限递归；另一个错误是调用左右递归却**没有把返回值赋给 `root.left/right`**，最终只建出一个根节点。

`mid = (left + right) // 2` 与 `left + (right-left)//2` 都对。后者在 Java/C++ 等固定宽度整数语言中有防溢出优势；Python 整数不存在相同的固定宽度溢出问题。

**复杂度**：每个元素建一次节点，时间 `O(n)`；递归栈 `O(log n)`，结果树自身需要 `O(n)` 节点空间。

## 5. 树的原地修改：先想指针会不会丢

把树按先序顺序展开为 `right` 单链表，可以有两种思维：

**思维一：遍历顺序与重构分离。**

先用先序遍历收集**节点引用**（不是仅存数值），再按顺序将每个节点的 `left = None`、`right = 下一个节点`。好处是容易验证，代价是 `O(n)` 额外空间。用栈模拟先序时，注意**先压右孩子，再压左孩子**，才能先处理左孩子。

**思维二：原地拼接，保持结构不断链。**

对于有左子树的当前节点：找到左子树最右侧的节点，将原右子树接过去，再把原左子树移到 `right`，最后 `left = None`，然后沿 `right` 继续处理。

要掌握的不是某个固定解法，而是两个检查原则：

- **修改前先确定哪些旧指针需要保留。** 错误的赋值顺序可能覆盖还没用过的子树入口。
- **保持遍历不变量**：已经处理过的节点 `left` 全部为空，`right` 链段符合先序顺序。

这类题特别适合手画 4～6 个节点的小树，逐次验证断链、漏节点、重复连接问题。

## 6. 网格 DFS：连通块与访问标记

### 6.1 如何把网格看成图

每一个非水格可以视为图上的一个节点；上下左右相邻的陆地之间有边。岛屿数就等于这张图中**连通块的数量**。

最常用的计数套路：

1. 扫描全部格子。
2. 遇到**尚未访问的有效格子**，答案加一。
3. 从这个格子 DFS/BFS，访问它所在连通块的全部格子，避免下一次重复计数。

核心不变量：**一次搜索消耗掉一个完整连通块**，所以下次遇到新的未访问陆地时，一定属于新连通块。

### 6.2 标记时机是正确性的关键

DFS 应该在继续探索邻居**之前**，先标记当前格子已访问（例如把 `"1"` 改为 `"0"`）。否则 A 访问 B、B 再访问 A，可能反复递归。

网格 DFS 中的终止条件通常是“越界 **或** 不属于待访问状态”；进行索引读取前必须先检查边界，利用 Python `or` 短路避免越界访问。

**高频模板 ④：四方向网格 DFS**

```python
n, m = len(grid), len(grid[0])

def dfs(x, y):
    if x < 0 or x >= n or y < 0 or y >= m:
        return
    if grid[x][y] != "1":
        return
    grid[x][y] = "0"            # 先标记，再访问邻居
    dfs(x + 1, y)
    dfs(x - 1, y)
    dfs(x, y + 1)
    dfs(x, y - 1)

components = 0
for i in range(n):
    for j in range(m):
        if grid[i][j] == "1":
            components += 1
            dfs(i, j)
```

这份写法会**原地修改输入**；不允许修改输入时，应使用额外 `visited` 集合/数组。连通块搜索时间一般为 `O(nm)`，递归栈在最坏情况下可达 `O(nm)`，需要注意 Python 的递归深度。

### 6.3 Python 网格题易错点

- 二维列表是 `grid[i][j]`，不是 `grid[i, j]`。
- 必须区分字符串格子 `"1"` / `"0"` 与整数格子 `1` / `0`。
- `n, m = len(grid), len(grid[0])`；如输入可能为空，先判断 `if not grid or not grid[0]`。
- 斜对角算不算连通，要服从题目定义；岛屿类常见的是四联通。
- BFS/迭代 DFS 建议**入队/入栈时**就标记 visited，防止多个邻居重复加入同一位置。

## 7. 多源 BFS：把“同时开始”变成同一层

### 7.1 单源与多源的本质差别

- **单源 BFS**：初始队列只有一个起点。
- **多源 BFS**：把**所有初始起点**同时加入队列；它们都位于第 0 层。

例如腐烂扩散：所有最初腐烂的橘子必须在第 0 分钟同时作为起点，而不是一个扩散完再处理另一个。

### 7.2 分层就是时间

入队顺序遵守“先处理第 t 层，再产生第 t+1 层”。于是第 t 层代表距离源点 t 步、或传播经过 t 分钟的状态。

最容易错的地方是：

- 把已处理过的橘子、空格子再次入队；应**只允许新鲜状态入队**，且入队时立即改成腐烂状态。
- 时间多算 1：初始队列已经是第 0 分钟。可以采用 `time = -1` 后在每轮开始加一；或 `time = 0`，只要还存在新鲜橘子才做一轮扩散，每轮结束加一。**不要机械背起始值，要先定义“一层代表哪个时刻”。**
- 不可达状态：搜索结束后还有目标未被访问，要返回失败标记。

### 7.3 进一步优化：用剩余目标数量维护进度

初始化时统计 `fresh`：

- 每感染一个新鲜橘子，`fresh -= 1`。
- `fresh == 0` 时可以提前停止。
- 搜索结束若 `fresh > 0`，说明仍存在不可到达的橘子。

这是一个通用技巧：**与其最终再次扫描全图，不如搜索中维护一个可更新的计数不变量。** 它主要改善代码结构和常数成本，整体时间复杂度仍为 `O(nm)`。

多源 BFS 适用情形：多起点最短距离、病毒/火焰/水流传播、最近设施距离、同时扩散的网格问题。前提通常是**每条边的代价相同**；若边权不同，应另选最短路算法。

## 8. 并查集：从“遍历区域”转换成“维护集合”

### 8.1 一次性连通块统计 vs 动态合并

DFS/BFS 通过实际走遍区域确定一个连通块；并查集不保存搜索路径，而维护“哪些点属于同一个集合”。

并查集有两个核心操作：

- `find(x)`：找到 x 所属集合的代表元。
- `union(x, y)`：如果代表元不同，把两个集合合并。

**常用优化**：路径压缩 + 按大小/按秩合并，让操作均摊近乎常数时间。

### 8.2 二维映射成一维

有 `m` 列时：

```text
id(i, j) = i * m + j
```

这样二维格子就可以映射到 `parent` 一维数组。对每个有效格子，只需要检查**右边和下边**，就能覆盖全部无向相邻边，避免重复处理。

### 8.3 用“合并成功次数”统计连通块

思路非常重要：

1. 初始把每一块陆地当作独立集合，`components = 陆地格子数`。
2. 当两个**原本不同集合**的陆地成功合并时，`components -= 1`。
3. 如果本来就是同一集合，不能减一，否则会重复统计。

这是一种常见的不变量：**连通块数量 = 初始独立点数量 − 有效合并次数**。

并查集总体适合维护动态连通性，特别是“陆地持续增加、每次加入后都要问岛屿数量”的变体；如果仅做一次静态统计，DFS/BFS 往往更直接。

并查集算法近似时间 `O(nm · α(nm))`，额外空间 `O(nm)`，`α` 为增长极慢的反阿克曼函数。

## 9. 把聊天里的错误提炼成可迁移的排错清单

| 错误表现 | 根因 | 通用检查方法 |
|---|---|---|
| `while not q` 导致不循环 | 把“空”和“非空”弄反 | 明确 `while q` 才是队列有元素 |
| 队列反复处理一个节点 | 取 `q[0]` 却没出队；`continue` 跳过 `popleft` | 尽量直接 `cur = q.popleft()` |
| `NoneType` 属性错误 | 空孩子入队 | 入队前检查有效性 |
| 递归创建了子树，结果却没有连接 | 忽略递归返回值 | `root.left = dfs(...)` 等显式连接 |
| 找到目标值却最终返回无效值 | 递归结果没逐层传回 | 定义返回值契约并逐层 `return` |
| `UnboundLocalError` | 嵌套函数对外层数字赋值 | 使用 `nonlocal` 或改为返回值 |
| `NameError: build` | 类中的实例方法调用没加 `self` | `self.build(...)` |
| 递归无限循环 | 子问题没有缩小或访问状态未标记 | 检查区间严格缩小；先标记再扩展 |
| BST 校验漏掉祖先条件 | 只比较直接孩子 | 继承上下界或检查全局中序严格递增 |
| 网格搜索始终找不到目标 | 字符串 `"1"` 与整数 `1` 混用 | 检查题目输入类型 |
| 网格索引异常 | `grid[i,j]` 或先访问后判界 | 写 `grid[i][j]`，先判界 |
| BFS 时间多一层 | 初始源点计时语义不清 | 明确源点是第 0 层，什么时候 `time += 1` |
| 并查集数量越减越少 | 重复合并也减计数 | **仅合并不同根成功后才减一** |

## 10. 复杂度：更关注“每个状态会处理几次”

| 典型操作 | 时间 | 辅助空间 | 关键原因 |
|---|---|---|---|
| 二叉树完整 DFS / BFS | `O(n)` | DFS `O(h)`；BFS 最坏 `O(n)` | 每个节点至多处理一次 |
| BST 中序找第 k 小并提前停止 | `O(h+k)` | `O(h)` | 只走到第 k 个中序节点 |
| 有序数组建平衡 BST | `O(n)` | 递归栈 `O(log n)` | 每个元素创建一次节点 |
| 网格四联通 DFS / BFS | `O(nm)` | 最坏 `O(nm)` | 每格至多被标记处理一次 |
| 多源 BFS | `O(nm)` | 最坏 `O(nm)` | 起点虽多，但每状态仍只入队一次 |
| 并查集合并邻格 | `O(nm α(nm))` | `O(nm)` | 每格至多检查常数条边 |

注意：**辅助空间**不一定包含题目要求输出的结构。例如“构建一棵树”的结果节点空间是 `O(n)`，但额外递归栈仍可为 `O(log n)`。

## 11. 一页速记：最值得带走的思想

1. **递归先定函数契约**，清楚参数传什么、返回什么，找到答案要不要逐层返回。
2. **子树性质靠参数向下传**（BST 上下界），**子树结果靠返回值向上传**（是否合法、构造好的子树）。
3. **利用题目结构，而不是蛮力**：BST 中序严格升序，有序数组取中点可平衡构造。
4. **遍历顺序本身能减少状态量**：中序找第 k 小不必存全部数组；右视图每层只记一个值。
5. **BFS 分层先固定 `size`**；初始多个源点一起入队就是多源 BFS。
6. **访问标记尽早完成**，通常入队/进入 DFS 时标记，防止重复和死循环。
7. **计数连通块有两种视角**：DFS/BFS 每发现新块加一；并查集每成功合并两个块减一。
8. **指针题先保留结构再修改**，确认不会丢失节点或断链。
9. **Python 写算法要警惕语言细节**：`deque`、`self`、`nonlocal`、`grid[i][j]`、`"1"` 与 `1`、递归深度。
10. **复杂度从状态处理次数推导**：能保证每个节点/格子只处理一次，树和网格题通常能做到线性复杂度。
