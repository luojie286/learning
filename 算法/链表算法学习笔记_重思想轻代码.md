# 链表算法学习笔记：重思想，轻代码

> 覆盖：两数相加、删除链表倒数第 N 个节点、两两交换链表节点、K 个一组翻转链表。
> 核心目标：理解指针为什么这样移动，而不只是记住某份代码。

## 一、链表题的统一思维框架

链表题的难点不在循环，而在**改变一条 `next` 时，是否还留有通往后续节点的路径**。

每次动手前先问四个问题：

1. **会不会改变头节点？** 会，就优先引入虚拟头节点 `dummy`，让原头节点和普通节点受到统一处理。
2. **当前操作的边界是什么？** 是一个节点、一对节点，还是一组 K 个节点？先确认够不够处理。
3. **哪些指针必须提前保存？** 常见的是当前组的旧头节点（反转后成为尾节点）和下一组的起点。
4. **循环结束后谁来衔接？** 必须确保上一段、当前段、下一段重新连成一条链，并让用于下一轮的指针真正前进。

### 常见指针角色

| 名称 | 作用 | 典型使用场景 |
|---|---|---|
| `dummy` | 统一头节点的特殊情况 | 删除、插入、交换、分组反转、构造答案 |
| `pre` | 待操作区间之前的节点 | 删除目标节点、连接新的一组 |
| `cur` | 正在处理的节点，也可作为局部反转后的尾节点 | 顺序遍历、头插法 |
| `next` / `nxt` | 保存后续链表入口 | 防止改 `next` 时断链 |
| `tail` | 当前组原来的头，反转后变成尾 | K 个一组翻转 |
| `carry` | 加法的进位状态 | 两数相加 |

**重要区分：** `pre` 不是固定指向什么位置，它在不同模板中有不同意义；变量名不能代替不变量的定义。

## 二、两数相加：利用逆序表示，模拟竖式加法

### 题目本质

链表按**个位、十位、百位……**的顺序存储数字。例如：

```text
2 → 4 → 3    表示 342
5 → 6 → 4    表示 465
7 → 0 → 8    表示 807
```

### 解题思想

最初考虑先反转两个链表，但**没有必要**：逆序链表的遍历方向恰好就是竖式加法从低位到高位的方向。

同时遍历两条链表：

- 当前位相加时加上上一位的 `carry`。
- 当前结果位是 `sum % 10`。
- 下一位进位是 `sum / 10`。
- 一条链表先结束，就把该位视为 `0`。
- 即使两个链表都结束，只要 `carry != 0` 仍要创建一个节点。

**关键模板（只展示核心）：**

```java
while (l1 != null || l2 != null || carry != 0) {
    int x = l1 == null ? 0 : l1.val;
    int y = l2 == null ? 0 : l2.val;
    int sum = x + y + carry;

    cur.next = new ListNode(sum % 10);
    carry = sum / 10;
    cur = cur.next;

    if (l1 != null) l1 = l1.next;
    if (l2 != null) l2 = l2.next;
}
```

### 本次易错点

- 使用 `while (l1 != null || l2 != null)`，却直接读取 `l1.val + l2.val`：**只要有一个为 `null` 就可能空指针**。
- 另一个合法方案是：先 `&&` 同步遍历，再分别处理剩余节点，最后处理进位；但三个循环比统一循环更繁琐。
- 不要把整个链表先转换成 Java 整数：可能溢出，而且没有必要。

**复杂度：** 时间 `O(max(m,n))`；辅助空间 `O(1)`，输出链表占 `O(max(m,n))`。

## 三、删除倒数第 N 个节点：前驱节点比目标节点更重要

### 思路 A：两次遍历

1. 第一遍求链表长度 `L`。
2. 目标是**从头开始第 `L - n + 1` 个节点**（1 下标）。
3. 找到目标的前驱，让 `pre.next = pre.next.next`。

### 本次易错点

使用 `pre = null`，当 `n == L` 时目标就是头节点，前驱不存在，直接执行 `pre.next` 会空指针。

解决方法：

- 特判删除头节点，返回 `head.next`；或
- **更推荐：用 `dummy → head`，让头节点也有前驱。**

### 思路 B：快慢指针，一次遍历

关键不是两个指针都移动，而是**让它们保持固定的距离**。

- `fast` 和 `slow` 都从 `dummy` 出发。
- `fast` 先走 `n + 1` 步，或用等价的其他边界约定。
- 两者再同步前进，直到 `fast == null`。
- 此时 `slow` 恰好是待删除节点的前驱。
- 删除 `slow.next`。

```java
ListNode dummy = new ListNode(0, head);
ListNode fast = dummy, slow = dummy;
for (int i = 0; i <= n; i++) fast = fast.next;
while (fast != null) {
    fast = fast.next;
    slow = slow.next;
}
slow.next = slow.next.next;
return dummy.next;
```

> 上述模板依赖题目保证 `1 <= n <= 链表长度`。

**为什么有时先走 n 步、有时走 n+1 步？** 看初始位置和终止条件。不要孤立背数字，要保证慢指针最终**停在待删除节点之前**。

**复杂度：** 时间 `O(L)`，辅助空间 `O(1)`；双指针版单趟扫描。

## 四、两两交换节点：按组操作，始终维护上一组的尾部

### 核心思想

不用交换节点的 `val`，而是改三条连接。

```text
交换前：pre → first → second → rest
交换后：pre → second → first → rest
```

逻辑顺序：

1. `first.next = second.next`：保存后半段通路，让 `first` 接上 `rest`。
2. `second.next = first`：第二个节点转而指向第一个。
3. `pre.next = second`：将上一段接到新头。
4. `pre = first`：旧 `first` 已是当前组的尾部，也是下一组的前驱。

```java
ListNode dummy = new ListNode(0, head), pre = dummy;
while (pre.next != null && pre.next.next != null) {
    ListNode first = pre.next;
    ListNode second = first.next;
    first.next = second.next;
    second.next = first;
    pre.next = second;
    pre = first;
}
return dummy.next;
```

### 本次优化经验

- 不必提前声明过多需要频繁同步更新的指针。
- 每一轮再取本组的 `first`、`second`，更清楚。
- 把“是否剩两个节点”写进循环条件，避免循环内部额外 `break`。
- `dummy` 使首组交换与后续交换一致。

**复杂度：** 时间 `O(L)`，辅助空间 `O(1)`。

## 五、K 个一组翻转：先锁边界，再反转，再拼接

这是前面所有技巧的综合题。相比两两交换，额外难点在于：**剩余数量不足 K 时必须保持原顺序**。

### 推荐的五步框架

1. **定位边界：** 从 `pre` 出发往后数 K 个节点，确认这一组完整存在；不够就结束。
2. **记住连接：** 保存 `tail = pre.next`（旧头、未来的尾）；保存 `nextGroup`（下一组开头）。
3. **局部反转：** 只改变本组内部指向，始终保存尚未反转部分的入口。
4. **拼接结果：** `pre.next` 接反转后的新头；旧头 `tail` 接下一组（若反转方式已自动接好就不用重复接）。
5. **推进下一组：** `pre = tail`，而不是指向新头。

### 模板 A：三指针局部反转（更适合理解）

设 `nextGroup` 是本组最后一个节点的 `next`；把反转部分的初始前驱设为 `nextGroup`，可以**在反转时顺手接回后续链表**。

```java
ListNode tail = pre.next;
ListNode p = nextGroup;
ListNode f = tail;
while (f != nextGroup) {
    ListNode next = f.next;  // 先保存
    f.next = p;              // 再反转
    p = f;
    f = next;
}
pre.next = p;                // 新头
pre = tail;                 // 旧头变新尾
```

这段循环必须记住两个**不变量**：

- `p`：已反转部分的头节点。
- `f`：尚未反转部分的第一个节点。

注意：`nextGroup` 是**反转终止边界**，不是正在处理的节点；在操作过程中必须保证该边界仍可达。

### 模板 B：头插法（指针操作更紧凑）

保持每组第一个节点 `cur` 不动，连续把它后面的节点一个个插到组头：

```text
1 → 2 → 3 → 4  （k=3）
2 → 1 → 3 → 4  （把 2 插到组头）
3 → 2 → 1 → 4  （把 3 插到组头）
```

```java
ListNode cur = pre.next;
for (int i = 1; i < k; i++) {
    ListNode next = cur.next;
    cur.next = next.next;
    next.next = pre.next;
    pre.next = next;
}
pre = cur;
```

### 本次反复踩到的坑

**① 外层循环不退出。** `while (j)` 中一直不修改 `j`，自然无限执行；更简洁的处理是检查不够 K 个节点后直接 `return dummy.next`。

**② `break` / `continue` 的层级。** 写在 `for` 内只作用于 `for`，不会直接跳出外层 `while`。即使把 `j` 改为 `false`，也必须确保停止本轮后续的反转代码。

**③ 判断前先改了待判断的链接。** 例如刚执行 `f.next = cur`，下一行又判断 `f.next != cur`，条件一定是假；写链表循环前明确哪个指针代表“未处理区间”。

**④ 先改 `next`，再试图沿旧 `next` 前进。** 这会丢失原后续节点、制造环或使指针跑偏。规则是：**先保存 `next`，再改链。**

**⑤ 局部反转不等于完整重接。** 即使方向反过来了，也要检查：上一段能否到新头、新尾能否到下一段、有没有环、有没有丢失节点。

**⑥ `pre` 推进到错误节点。** 反转后应当推进到**旧头（新尾）**，不是新头，否则下一轮的分组起点不对。

### 一个真实的反例（来自本次调试）

对 `[1,2,3]`、`k=3`，之前的多指针代码在一次循环中先修改 `s.next`，又依赖变化后的指针推进，最终可能得到 `[3,1]`，节点 `2` 丢失。问题不在语法，而在没有维护“已反转部分连续”这一不变量。

**复杂度：** 时间 `O(L)`，辅助空间 `O(1)`。

## 六、通用模板速查

### 模板 1：虚拟头节点

```java
ListNode dummy = new ListNode(0, head);
ListNode pre = dummy;
// 操作链表
return dummy.next;
```

适用：头节点可能发生变化，或删除/交换/插入需要统一处理。

### 模板 2：局部反转

```java
ListNode prev = boundary; // 反转区间后一个节点
ListNode cur = first;
while (cur != boundary) {
    ListNode next = cur.next;
    cur.next = prev;
    prev = cur;
    cur = next;
}
// prev 是反转后的新头；first 是新尾
```

适用：整段反转、K 组反转、链表局部反转。前提：`boundary` 是区间外的确定终点。

### 模板 3：固定间距双指针

```java
ListNode fast = dummy, slow = dummy;
// 先让 fast 领先合适的步数
// 再同步移动：fast = fast.next; slow = slow.next;
```

适用：倒数第 K 个、删除倒数第 N 个。**先画图确定终点，再定步数。**

### 模板 4：一次处理一组

```text
pre → [本组 K 个节点] → nextGroup
        ↓ 反转/交换
pre → [处理后的 K 个节点] → nextGroup
                              ↑
                    下一轮从新尾之后继续
```

适用：两两交换、K 个一组反转、分段调整。

## 七、链表 Debug 清单

写完代码后，不必只看复杂样例。优先手动运行：

- **空 / 单节点**：是否直接安全返回？（以题目允许为准）
- **恰好一组**：如 `[1,2]`、`k=2`。
- **不足一组**：如 `[1,2]`、`k=3`，应原样保留。
- **多组且有余数**：如 `[1,2,3,4,5]`、`k=2`。
- **首节点变化**：`dummy.next` 是否更新？
- **最后一组**：末尾是否仍指向 `null`，有没有环？
- **遍历边界**：访问 `x.next` 前，`x` 是否一定非空？
- **进度**：每次外层循环是否真正走向终止条件？

手工模拟时，把每一步写成 `节点 A.next = 节点 B`，**记录实际链接**，不要仅凭变量名想象结构。

## 八、最终浓缩：最值得记住的 6 条规则

1. **逆序数字直接从头加，进位是状态，不需要反转链表。**
2. **删除节点要找前驱；dummy 让删除头节点不特殊。**
3. **交换/反转是改链接，不是交换数值。**
4. **改 `next` 前，先保存下一段入口。**
5. **分组操作先检查 K 个够不够，再处理；处理后 `pre` 移到新尾。**
6. **始终检查三件事：不断链、不成环、下一轮能推进。**

> 一句话总结：**链表题就是维护区间边界和指针不变量；模板可以帮助少犯错，但画清楚修改前后的连接关系才是根本。**
