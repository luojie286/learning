# 算法学习笔记：重思想、轻代码

> 基于本次聊天中的算法题与讨论整理。重点不是背题解，而是总结**为什么想到这种方法、核心不变量是什么、什么时候能迁移到其他题**。语言以 Java 为主，只保留少量高频模板。

## 一、先建立一套通用解题思维

遇到题目时，建议按下面顺序思考：

1. **题目有什么结构？** 有序、连续、链式、嵌套、需要枚举全部答案……这些词往往直接决定数据结构。
2. **暴力法是什么？** 先找到一个一定正确的方法，再想哪里做了重复工作。
3. **能不能只保存“足够的信息”？** DP 状态、双指针间距、堆顶候选等，都是信息压缩。
4. **每次操作能排除多少可能？** 二分靠单调性，二维矩阵从角落搜索靠整行或整列排除，回溯靠提前剪枝。
5. **能不能统一边界？** 链表的 `dummy`、反转链表的 `pre = null`、空区间等，通常能减少特判。

贯穿这些题的四个高频思想：

- **维护不变量**：算法每一步都保持一个正确的条件，例如快慢指针的固定间距。
- **利用已有顺序**：输入本身有序，就尽量不要重新排序或全部放入堆中。
- **尽早排除无效情况**：能在搜索中剪枝，就不要等生成完整答案再验证。
- **状态不能丢关键的信息**：记录“最大长度”未必能回答“某个指定区间是否满足条件”。

## 二、有序数组与矩阵

### 1. LeetCode 4：寻找两个正序数组的中位数

**关键词：二分切割、四个边界值、长度约束。**

把两个有序数组各切一刀，形成整体的左半边和右半边：

```text
A: [ 左半部分 ] | [ 右半部分 ]
B: [ 左半部分 ] | [ 右半部分 ]
```

令四个边界值为 `Aleft`、`Aright`、`Bleft`、`Bright`。

一个合法的切割同时满足：

1. **数量正确**：左边总元素数为 `(m+n+1)/2`，因此左边在 A 中取 `i` 个，B 中就必须取 `j=(m+n+1)/2-i` 个。
2. **顺序正确**：`Aleft <= Bright` 且 `Bleft <= Aright`。

为什么只检查交叉的两个不等式？因为**两个数组内部本来就有序**，`Aleft <= Aright`、`Bleft <= Bright` 已天然成立。

**二分的关键改进**：不是让两个数组各自二分，而是只在**较短数组**上二分切割位置 `i`，由左半边总数直接推出 `j`。

- `Aleft > Bright`：A 左侧取多了，`i` 应减小。
- `Bleft > Aright`：A 左侧取少了，`i` 应增大。
- 切割合法后：总长度为奇数，中位数是 `max(Aleft, Bleft)`；为偶数，中位数是 `max(左边界)` 与 `min(右边界)` 的平均值。

**边界处理**：某侧为空时，左边界视作负无穷，右边界视作正无穷。Java 可用 `Integer.MIN_VALUE` / `Integer.MAX_VALUE` 作哨兵；求平均时注意加法溢出，可先转 `long` 或 `double`。

**复杂度**：时间 `O(log(min(m,n)+1))`，空间 `O(1)`。

**迁移思维**：当你要找的不是某个具体元素，而是“满足左右有序关系的一条分界线”，可以尝试**二分答案的位置**。

### 2. LeetCode 240：搜索二维矩阵 II

**关键词：从右上/左下角出发、每步排除一行或一列。**

题目条件：每行从左到右升序，每列从上到下升序。

从**右上角**开始，有两个相反的单调方向：向左更小，向下更大。

- 当前值 `> target`：当前列从此位置往下都不可能，**左移一列**。
- 当前值 `< target`：当前行从此位置往左都不可能，**下移一行**。
- 相等：找到答案。

```java
int i = 0, j = matrix[0].length - 1;
while (i < matrix.length && j >= 0) {
    int x = matrix[i][j];
    if (x == target) return true;
    if (x > target) j--;
    else i++;
}
return false;
```

**为什么左上角不合适？** 左上角的右侧和下侧都更大；当目标比当前值大时，不能决定排除哪边。右上角则能在一次比较后确定排除整行或整列。

**左下角也完全可以**：当前值小于目标则右移，大于目标则上移。两个角对称，没有谁更“正确”。

**复杂度**：`O(m+n)` 时间、`O(1)` 空间，因为每一步只增加行号或减少列号，最多走 `m+n-1` 步。

**迁移思维**：遇到“行、列各自有序但整个矩阵不保证一维整体有序”的情况，寻找能让两个方向一大一小的**边界起点**。

## 三、回文串：状态是否保留了足够信息

### 3. LeetCode 5：最长回文子串

**关键词：区间 DP、中心扩展、状态信息不能丢失。**

#### 先纠正一个很自然的想法

设 `dp[i]` = “以 `i` 结尾的最长回文串长度”，再根据这个长度找回文串前面的字符尝试扩展。

这个信息**不够**：下一位置的最长回文可能来自一个**更短的回文后缀**，而不是上一位置最长的那个。

例如 `abbb`：在 `abb` 的末尾，最长回文后缀是 `bb`；要得到后面的 `bbb`，需要从较短的 `b` 扩展。只保存最长长度，会丢掉这个候选。

**核心教训：DP 状态必须能支撑下一步转移，不能只保存看似最有价值的最优值。**

#### 方法 A：区间 DP

定义：`dp[i][j]` 表示 `s[i...j]` 是否为回文。

转移理由：外层两个字符相等，并且内部区间是回文，那么整个区间就是回文。

```text
dp[i][j] = (s[i] == s[j]) && dp[i+1][j-1]
```

边界：长度 1 一定回文；长度 2 只看两端；长度 3 也只需判断两端，因为中间单字符天然回文。因此实现时通常合并成 `j-i <= 2 || dp[i+1][j-1]`。

**遍历顺序很关键**：大区间依赖小区间，所以优先**按区间长度从小到大**遍历（也可以选用保证依赖先算出的其他顺序）。

复杂度：时间 `O(n²)`、空间 `O(n²)`。

#### 方法 B：中心扩展（更推荐掌握）

一个回文串总能从中心向外扩展；中心有两种：

- 奇数回文：中心在字符上，例如 `aba`。
- 偶数回文：中心在两字符之间，例如 `abba`。

对每个位置分别尝试 `(i,i)`、`(i,i+1)`，两端相等就继续向两边扩。扩展停止前最后一个合法区间是候选答案。

**为什么是 `O(n²)` 而非 `O(n³)`？** 中心只有 `2n-1` 个，每个中心最坏扩展 `O(n)` 次，故时间 `O(n²)`，额外空间 `O(1)`。

更高阶的 Manacher 可做到 `O(n)` 时间，但不是入门阶段必需内容。

**选型**：训练 DP 状态设计写区间 DP；实际解决最长回文子串，优先用中心扩展，代码短、空间低。

## 四、回溯：从暴力枚举到边生成边剪枝

### 4. LeetCode 17：电话号码的字母组合

**关键词：多叉树 DFS、映射表、路径回退。**

初始思路“定义八个数组 + 递归枚举”可行，但八个数组没有必要。用一个 `String[]` 维护数字到字母串的映射：

```java
String[] map = {"", "", "abc", "def", "ghi", "jkl",
                "mno", "pqrs", "tuv", "wxyz"};
```

**搜索树如何构建？**

- 第 `i` 层对应第 `i` 个数字。
- 每层遍历这个数字能映射到的每个字母。
- 放入路径，递归下一层，然后撤销刚才的选择。
- 路径长度等于数字串长度时，收集结果。

通用回溯动作：

```java
path.append(c);            // 做选择
dfs(i + 1, path);         // 递归
path.deleteCharAt(path.length() - 1); // 撤销选择
```

**边界注意**：`digits` 为空时返回空列表，而不是包含一个空字符串的列表。

**复杂度**：长度为 `n`，组合总数最坏为 `4^n`，生成结果字符串的时间为 `O(n·4^n)`；递归栈和单条路径为 `O(n)`，如果包含答案存储则最多 `O(n·4^n)`。

**迁移思维**：“从每一组选一个选项，返回所有组合”，优先想到**按位置逐层 DFS**。

### 5. LeetCode 22：括号生成

**关键词：前缀合法性、回溯剪枝。**

暴力方案：对 `2n` 个位置分别填 `(` 或 `)`，总共 `4^n` 个候选，然后逐个检查是否合法。正确，但生成了大量根本不可能成功的前缀。

优化：边生成边维护两个计数：

- `left`：已使用左括号数。
- `right`：已使用右括号数。

只有在满足以下条件时才允许继续生成：

```java
if (left < n) { /* 尝试 '(' */ }
if (right < left) { /* 尝试 ')' */ }
```

两个条件的含义：

1. 左括号总共不能超过 `n` 个。
2. **任意前缀**的右括号数都不能超过左括号数，否则这个前缀之后无论添加什么都无法修复。

当 `left == n && right == n` 时，路径就是一个合法答案，不必额外检查。

**复杂度**：合法答案数是第 `n` 个卡特兰数 `C_n`；输出全部字符串所需时间 `O(n·C_n)`，不含答案的辅助空间 `O(n)`。

**迁移思维**：一个局部前缀已经违反“以后也无法修复”的约束时，立即剪掉。**剪枝的关键是证明这个分支不可能产生合法答案。**

### 6. 一个通用 DFS/回溯骨架

```java
void dfs(状态, StringBuilder path) {
    if (达到终点) {
        ans.add(path.toString());
        return;
    }
    for (选择 : 当前可选项) {
        if (不合法) continue; // 剪枝
        做选择;
        dfs(下一状态, path);
        撤销选择;
    }
}
```

这四个位置要能脱口而出：**终止条件、枚举选择、递归推进、撤销选择**。

## 五、栈：处理最近的未匹配元素

### 7. LeetCode 20：有效的括号

**关键词：后进先出、右括号匹配栈顶。**

最初想法 `Set + Stack` 是可行的：用 Set 判断左括号，再用栈处理匹配。但只有三种左括号时，Set 可以省略，直接比较字符即可。

**为什么必须是栈？** 例如 `([{}])`，最后出现的 `{` 必须最先由 `}` 闭合，这就是“后进先出”。

处理规则：

- 左括号：入栈。
- 右括号：如果栈为空，立即失败；否则弹出栈顶，要求类型匹配。
- 遍历结束：栈必须为空，防止 `(((` 这种只有左括号的字符串被误判。

复杂度：时间 `O(n)`、空间 `O(n)`。

**迁移思维**：看到嵌套结构、最近未完成操作、需要逆序匹配时，优先想到**栈**。

## 六、链表：统一边界与指针不变量

### 8. LeetCode 19：删除链表的倒数第 N 个结点

**关键词：倒数转正数、快慢指针、dummy。**

#### 方法 A：两遍扫描（直观）

先遍历得到长度 `L`，倒数第 `n` 个就是正数第 `L-n+1` 个；第二遍找到其**前一个节点**，修改 `next` 删除。

时间仍为 `O(L)`，不是 `O(L²)`；空间 `O(1)`。遍历两遍影响常数，不改变复杂度阶数。

#### 方法 B：一趟快慢指针（更经典）

先创建 `dummy -> head`，`fast` 和 `slow` 均从 `dummy` 出发：

1. `fast` 先走 `n` 步。
2. 然后两者一起移动，始终保持 **fast 比 slow 领先 n 条边**。
3. 当 `fast.next == null` 时，`slow` 正好在待删除节点的前一个位置。
4. 执行 `slow.next = slow.next.next`。

```java
ListNode dummy = new ListNode(0, head);
ListNode fast = dummy, slow = dummy;
for (int i = 0; i < n; i++) fast = fast.next;
while (fast.next != null) {
    fast = fast.next;
    slow = slow.next;
}
slow.next = slow.next.next;
return dummy.next;
```

**为什么用 dummy？** 删除原头节点时，它也有“前一个节点”（即 dummy），删除规则就不需要特判。

**边界理解**：需要的是待删节点的**前驱**，而不是待删节点本身；`fast` 走几步、循环何时停止，都要围绕这个目标来定。

复杂度：时间 `O(L)`、空间 `O(1)`。

**迁移思维**：不知道链表总长度，却要定位倒数第 `n` 个位置，建立两个指针之间的**固定距离**。

### 9. LeetCode 206：反转链表

**关键词：三个指针、先保存后继、让空边界参与普通循环。**

原来的写法把首节点单独处理、循环故意留下尾节点、最后再特判，因此结构冗长。可以通过 `pre = null` 消除全部特殊逻辑。

把链表分为两段：

```text
pre：已经反转完成的前缀
cur：尚未处理部分的头节点
```

每轮操作只做四件事：

```java
ListNode next = cur.next; // ① 保存后继，防止断链
cur.next = pre;          // ② 反转当前边
pre = cur;               // ③ 扩大已反转部分
cur = next;              // ④ 处理下一个节点
```

初始化 `pre = null, cur = head`，循环条件 `cur != null`，最终返回 `pre`。空链表、单节点、尾节点无需额外判断。

复杂度：时间 `O(L)`、空间 `O(1)`。

**迁移思维**：链表改指针前，先问“是否还保存着原来的后继？”；能让空状态成为普通状态，就不要把首尾单独拆开。

### 10. LeetCode 23：合并 K 个升序链表

**关键词：多路归并、最小堆只维护各路当前候选。**

你的想法是对的：维护所有链表当前头节点的最小堆，每次取出最小节点，接入结果，再让原链表下一节点补入堆。

为什么不必把所有节点一次性入堆？每条链表内部已升序，**在尚未取出的部分中，只有它的第一个节点可能成为全局最小**。因此堆内最多保留 `k` 个节点。

主要流程：

```text
初始化：每条非空链表的头节点入堆
循环：取最小节点 → 原节点 next 入堆 → 接到答案尾部
```

Java 最小堆比较器：

```java
PriorityQueue<ListNode> pq =
    new PriorityQueue<>((a, b) -> Integer.compare(a.val, b.val));
```

使用 `Integer.compare` 比 `a.val - b.val` 更稳妥，可避免整数相减溢出。

**断链问题**：不必显式把取出的节点从原链表断开。只要在改写链接前已经保留/入堆了它的原 `next`，后续对结果链表 `tail.next` 的赋值会覆盖旧指向。最后可设置 `tail.next = null` 来确保尾部断开。

复杂度：设全部节点数 `N`、链表数量 `k`。每个节点进出堆各一次，堆规模至多 `k`，时间 `O(N log(k+1))`、辅助空间 `O(k)`。

**对比方案**：分治两两合并也可达 `O(N log k)`；依次把结果与下一链表合并，最坏可能到 `O(Nk)`。

**迁移思维**：多个**各自有序的数据流**需要统一按序输出时，每一路只维护一个“下一候选”，再用最小堆做全局选择。类似多路归并、外部排序。

## 七、常用模板速查（只记结构）

| 模式 | 核心状态/操作 | 适用信号 | 常见陷阱 |
| --- | --- | --- | --- |
| 二分切割 | 一个切割位置二分，另一个由数量推出 | 两个有序数组求分位点 | 忘记左右数量及空切割边界 |
| 矩阵角落搜索 | 右上角：大则左移，小则下移 | 行列各自有序 | 从左上角无法明确排除方向 |
| 区间 DP | `dp[i][j]` 依赖 `dp[i+1][j-1]` | 指定区间性质由内部决定 | 状态信息不足、遍历顺序错误 |
| 中心扩展 | 枚举奇/偶中心，双指针外扩 | 回文类连续区间 | 漏掉偶数长度 |
| DFS 回溯 | 做选择 → 递归 → 撤销 | 输出全部组合/方案 | 少撤销、重复加入可变路径 |
| 剪枝 | 前缀已不可能成功则停 | 有明确合法性约束 | 错剪本可修复的状态 |
| 栈 | 新的左括号入栈，右括号匹配栈顶 | 嵌套、最近未匹配 | 忘记空栈检查或遍历结束检查 |
| 快慢指针 | 保持距离 `n` 不变 | 链表倒数定位 | 差一问题、删除头节点 |
| 链表反转 | 存 `next` → 改边 → 移动两指针 | 反向重连链表 | 先改 `next` 导致后继丢失 |
| 最小堆 | 每路一个候选，取最小后补位 | K 路有序流合并 | 不必要地把所有元素入堆 |

## 八、最值得复盘的思想与题目顺序

### 第一优先级：掌握“为什么”

1. **最长回文子串**：理解一维“最长长度”为什么会丢掉下一步需要的状态；比较区间 DP 与中心扩展。
2. **搜索二维矩阵 II**：自己证明一次比较为什么能排除整行/整列；区分右上角与左上角。
3. **删除链表倒数第 N 个**：明确 fast、slow 的距离不变量；解释为何 `fast.next == null` 时 slow 停在前驱。
4. **括号生成**：先想暴力，再证明 `right < left` 这个剪枝条件。
5. **合并 K 个链表**：思考“各路有序”为什么允许堆中只放 `k` 个候选。

### 第二优先级：形成肌肉记忆

- **反转链表**：`next → cur.next → pre → cur` 四步顺序。
- **有效括号**：左括号入栈、右括号与栈顶匹配、最后判空。
- **电话号码字母组合**：按层 DFS，做选择和撤销选择成对出现。
- **两个有序数组的中位数**：四个边界值 + 左边数量约束 + 二分移动方向。

### 做题时的自问清单

- 我现在保存的状态，足不足以决定下一步？
- 有没有哪条单调性可以让我直接排除一批候选？
- 遇到非法中间状态，能否证明继续搜索也没有意义？
- 是否必须先完整扫描一遍，还是可以通过两个指针的相对位置获得信息？
- 输入已经有序的部分，能不能让我只维护一个候选？
