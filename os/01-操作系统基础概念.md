# 01 · 操作系统基础概念

> 一句话概括：操作系统用**特权级**划出用户态/内核态的边界，进程靠**状态机**切换，进程之间靠**共享内存或消息传递**通信。
>

## 一、进程的状态与迁移

> 原始记录：`状态迁移`、`状态机`

进程不是一直「在跑」，它在几种状态间来回切换——**进程调度本质上就是一台状态机**。

```text
        新建
         ↓ 创建完成
   ┌→ 就绪 ──被调度──→ 运行 ──执行结束──→ 终止
   │   ↑               │
   │   └──时间片用完───┘
   │                   │ 等待事件（如 IO 完成、等待锁）
   │                   ↓
   └─────事件发生──── 阻塞
```

| 迁移 | 触发条件 |
|------|----------|
| 就绪 → 运行 | 被调度器选中，分配 CPU |
| 运行 → 就绪 | 时间片耗尽，或被更高优先级抢占 |
| 运行 → 阻塞 | 主动请求某个尚未就绪的事件（**等待 IO**、等待锁、`sleep`） |
| 阻塞 → 就绪 | 等待的事件发生了（IO 完成、锁被释放） |

> 关键理解：**阻塞 → 运行是不存在的**。被唤醒的进程只能先回到就绪队列，等调度器再选中它。

## 二、特权指令与用户态 / 内核态

> 原始记录：`特权指令`、`等待io指令`

CPU 至少有两种运行状态，用来保护系统不被用户程序破坏：

| 状态 | 能做什么 |
|------|----------|
| **用户态**（目态） | 只能执行非特权指令，访问受限的内存空间 |
| **内核态**（管态） | 可执行全部指令，访问所有内存与外设 |

**特权指令** = 只允许在内核态执行的指令，典型如：

- **IO 指令**（直接操作外设）
- 修改程序状态字 PSW、设置时钟
- 开关中断、清内存、修改页表基址

> 这解释了你记的「等待 IO 指令」：普通程序**不能直接发 IO 指令**（它是特权指令），只能通过**系统调用**请内核代劳——用户程序进入内核态的唯一合法入口就是系统调用（以及中断、异常）。

```text
用户程序发起 IO
   ↓ 系统调用（陷入内核，切换为用户态 → 内核态）
内核代它执行特权 IO 指令
   ↓ 若需要等待设备，该进程转入阻塞态
IO 完成 → 中断 → 进程回到就绪态
```

## 三、进程间通信（IPC）

> 原始记录：`共享内存`、`信息传递 (可在不同机器实现)`

进程之间彼此隔离（各有独立地址空间），所以想交换数据必须借助操作系统提供的通道。两大基本方式：

| | 共享内存 | 消息传递 |
|---|---|---|
| 机制 | 把同一块物理内存映射进两个进程的地址空间 | 通过 `send` / `receive` 由内核转发数据 |
| 速度 | **最快**（无需内核拷贝） | 较慢（有拷贝开销） |
| 同步 | **要自己处理**（需配信号量/互斥量） | 由通信机制天然提供 |
| 跨机器 | ❌ 仅限同一台机器 | ✅ **可在不同机器实现** |

> 你笔记里特意标注的「**可在不同机器实现**」正是消息传递的关键优势——**这是网络编程与分布式系统的起点**：把消息传递从「本机内核转发」换成「通过网络发送」，就得到了 socket。

## 四、函数调用与栈帧

> 原始记录：`stack frame`

每发生一次函数调用，系统就在**调用栈**上为它分配一个**栈帧（stack frame）**，里面通常包含：

```text
┌──────────────┐
│ 传入的参数    │
│ 返回地址      │  ← 函数执行完跳回哪里
│ 上一层栈帧基址│  ← 用于恢复调用者的栈
│ 保存的寄存器  │
│ 局部变量      │
└──────────────┘
```

- 函数返回时整个栈帧被弹出，内存自动回收（所以局部变量不用手动释放）
- 递归每深入一层就多一个栈帧，**深度过大就会 `StackOverflowError`**——这也是「递归改迭代」的根本原因

## 五、把这几件事串起来

```text
程序要读文件
   ↓
不能直接发 IO 指令（特权指令）→ 只能系统调用
   ↓
陷入内核态，内核代为执行
   ↓
等待设备期间，进程从「运行」转「阻塞」
   ↓
IO 完成触发中断 → 进程回到「就绪」
   ↓
若此时要与别的进程交换数据 → 共享内存 或 消息传递
（消息传递还能扩展到跨机器 → 网络）
```

---

## 📌 易错点

1. **以为「阻塞 → 运行」存在**——被唤醒的进程必须先回到就绪队列。
2. **以为用户程序可以直接操作硬件**——IO 是特权指令，必须走系统调用。
3. **把「阻塞」和「就绪」混为一谈**——就绪只是等 CPU，阻塞是在等事件；两者的等待对象完全不同。
4. **认为共享内存什么都能干**——它最快，但**要自己加锁同步**，且**不能跨机器**。
5. **把栈帧理解成「函数代码的存储」**——栈帧存的是运行时数据（参数、返回地址、局部变量），代码存在代码段。
6. **递归太深当异常处理就能解决**——`StackOverflowError` 属于 `Error`，不该 catch，应该改算法（把递归改迭代或加深度限制）。

## 🧠 速记口诀

```text
进程三态：就绪等 CPU、运行占 CPU、阻塞等事件
阻塞唤醒只回就绪，不能直接上 CPU
特权指令只在内核态跑，用户程序进内核唯一合法入口 = 系统调用
共享内存最快但要自己同步、不能跨机器
消息传递要拷贝但天然同步、可跨机器（→ 网络 socket 的起点）
栈帧 = 参数 + 返回地址 + 旧基址 + 局部变量；递归深了必爆栈
```
