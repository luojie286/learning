# 03 · 线程与处理机调度

> 一句话概括：操作系统用 **TCB** 记录每个线程的执行现场；**三级调度**决定谁能用 CPU；**调度算法**是公平、效率、实时性之间的取舍方案。
> （线程/进程的基础概念与 Java 视角见 → `java/14-多线程与锁.md`，本篇是操作系统理论视角。）

---

## 一、线程的三种基本状态

| 状态 | 含义 |
|---|---|
| **就绪态 Ready** | 万事俱备，只差 CPU |
| **运行态 Running** | 正在 CPU 上执行 |
| **阻塞态 Blocked / Waiting** | 在等某个事件或资源，**给它 CPU 也跑不了** |

```text
就绪态 --获得CPU--> 运行态
运行态 --时间片用完/被抢占--> 就绪态
运行态 --等待资源或事件--> 阻塞态
阻塞态 --资源/事件满足--> 就绪态   ← 不直接回运行态！
```

**核心判断法**：

> 只缺 CPU = 就绪态；缺其他资源或事件 = 阻塞/等待态。

```text
等 CPU   → 就绪
等锁     → 阻塞 / 等待
等磁盘IO → 阻塞 / 等待
```

Java 把状态分得更细：`BLOCKED`（竞争 `synchronized` 锁）、`WAITING`、`TIMED_WAITING`，考试里的三态/五态是 OS 层面的抽象。

## 二、TCB 与上下文切换

**TCB（Thread Control Block）**＝操作系统为每个线程保存的「线程档案」：线程 ID、状态、程序计数器 PC、寄存器现场、栈信息、调度信息。

线程切换（A 时间片用完 → 切到 B）：

```text
保存 A 的 PC、寄存器现场 → TCB_A
从 TCB_B 恢复 B 的现场
B 继续运行
```

### TCB 与 PCB

| | 描述 | 进程内共享（放 PCB） | 每线程独有（放 TCB） |
|---|---|---|---|
| `PCB` | 进程档案 | 地址空间、代码、全局数据、打开的文件 | — |
| `TCB` | 线程档案 | （用进程的） | 线程 ID、状态、PC、寄存器、栈 |

> 同一进程的线程共享地址空间等进程级资源，但**栈和执行现场必须各有一份**——所以每个线程仍需独立 TCB。

## 三、线程的实现模型

| 模型 | 谁管理线程 | 特点 |
|---|---|---|
| 用户级线程 | 用户态线程库 | 创建/切换不进内核，开销小；内核看不见这些线程 |
| 内核级线程 | 内核直接管理 | 内核可分别调度、可多核并行；创建/切换成本高 |
| 混合实现 | 两者结合 | 用户线程映射到多个内核线程 |

三种映射关系：

```text
多对一：A B C ──→ K1        切换轻，但不能多核并行；一个线程阻塞调用可能拖住全部
一对一：A──→K1，B──→K2，C──→K3   可多核并行，阻塞互不影响；内核线程多了管理成本高
多对多：A B C D E ──→ K1 K2 K3   兼顾轻量与多核，实现复杂
```

> **纠错提醒**：「用户线程不能利用多核」这个说法**不严谨**——真正决定能否多核并行的是**底层有没有多个可被内核调度的内核线程**。多对一 → 不能；一对一、多对多 → 能。

## 四、处理机调度的三个层次

| 层次 | 别名 | 做什么 | 频率 |
|---|---|---|---|
| 高级调度 | 作业调度 | **外存的作业 → 内存的进程**（作业变进程） | 最低 |
| 中级调度 | 内存调度 | 已有进程在**内存 ↔ 外存**间换出（挂起）/换入（激活） | 中 |
| 低级调度 | 进程/线程调度 | **就绪队列 → CPU**（Ready → Running） | 最高 |

**高级 vs 中级的区分**（易混）：

```text
高级：对象是「还没成为进程的作业」——创建
中级：对象是「已存在、被挂起的进程」——搬进搬出
```

> 中级调度可以把进程从外存**激活**回内存，但**激活 ≠ 直接运行**：挂起就绪 → 激活 → 就绪 → 还要等低级调度才运行；挂起阻塞 → 激活 → 仍阻塞（继续等原来的事件）。

## 五、常见调度算法

| 算法 | 规则 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **FCFS** 先来先服务 | 按到达顺序 | 简单 | **护航效应**：长任务堵住短任务 | 批处理 |
| **SJF** 短作业优先 | 预计运行时间最短先 | 平均等待时间最短（理想情况） | 运行时间难预知；长任务**饥饿** | 批处理 |
| **SRTF** 最短剩余时间优先 | SJF 的抢占版：新来的更短就抢占 | 响应更好 | 同上 | — |
| **优先级调度** | 优先级高先跑（抢占/非抢占） | 灵活 | 低优先级**饥饿**；数字大小含义看题目 | 通用 |
| **RR** 时间片轮转 | 每人轮流一个时间片 | 公平、响应快 | 切换开销 | **分时/交互系统** |
| **MLQ** 多级队列 | 固定分队列，各队列可用不同算法 | 分类管理 | 队列间可能饿死 | — |
| **MLFQ** 多级反馈队列 | 新进程进最高优先级队列；用完时间片没跑完就**降级**（高队列时间片短，越低越长） | 兼顾短任务与交互 | 实现较复杂 | 通用 OS 常用 |
| 公平调度 | 按（加权）比例分 CPU 时间 | 保证份额 | — | — |

关键细节：

- **护航效应**：长任务排前面，后面一堆短任务干等。
- **饥饿的解药——老化 Aging**：等得越久优先级越高。
- **RR 的时间片**：太大 → 退化成 FCFS；太小 → 上下文切换开销淹没有效工作。要折中。
- **MLFQ 的智慧**：新进程先当短任务对待（高优先级短时间片）；反复用不完时间片就逐步降级——用行为自动「识别」长任务。

## 六、实时调度：EDF 与 LLF

实时调度的目标不是平均等待最短，而是**保证在截止时间（Deadline）前完成**。

### EDF：最早截止时间优先

谁 Deadline 最早谁先跑。A=20、B=8、C=15 → 执行顺序 `B → C → A`。

属于**动态优先级**调度：谁最紧急谁的优先级此刻最高。

### LLF：最低松弛度优先

**松弛度** = 还能拖多久：

> `L = 截止时间 − 当前时间 − 剩余运行时间`

例：截止 10，当前 2，还需跑 5 → `L = 10 − 2 − 5 = 3`（最多还能等 3 个时间单位）。

- `L = 0`：现在必须马上跑，一秒不能再等。
- `L < 0`：就算立刻开始也来不及了（调度失败）。

### EDF vs LLF

| | EDF | LLF |
|---|---|---|
| 依据 | 截止时间的**绝对值** | 剩余**余量**（考虑了还需跑多久） |
| 记法 | 谁最早交卷？ | 谁最来不及了？ |

## 七、优先级倒置与优先级继承

### 倒置是怎么发生的

三个线程 H（高）、M（中）、L（低）：

```text
1. L 拿到锁
2. H 要这把锁 → H 阻塞，等 L 释放
3. M 到达，M 优先级 > L → M 抢占 L 的 CPU
4. 结果：L 没法运行去放锁，H 被与锁无关的 M 间接拖住
```

最高优先级的 H，实际效果排在 M 后面——**优先级倒置**。

### 为什么 H 不能直接把锁抢过来

> **CPU 使用权可以抢占，锁保护的是临界区数据的一致性。**

L 正持锁改数据，改到一半被抢走锁，H 会看到中间状态的数据，互斥性和一致性全毁。

### 解法：优先级继承

> 持锁的 L **临时继承** H 的优先级 → M 抢不动 L → L 赶紧跑完临界区放锁 → L 恢复原优先级 → H 拿锁。

一句话：**不是把锁抢过来，而是让持锁的人赶紧把活干完。**

## 📌 易错点

1. **阻塞结束直接回运行态** ✗——只能回**就绪态**，还要等调度。
2. **「用户线程不能多核」当教条**——只在多对一模型成立；一对一/多对多可以多核。
3. **中级调度「激活」后立即运行** ✗——激活只是回内存，状态照旧（挂起就绪→就绪）。
4. **优先级数字大小想当然**——有的题数字越大优先级越高，有的相反，**必须看题面**。
5. **RR 时间片越小平滑越好** ✗——切换开销是纯损耗，过小反而整体变慢。
6. **优先级倒置当成「优先级分错了」**——它是锁依赖 + 抢占共同造成的结构性问题，分再对也可能发生。

## 🧠 速记口诀

```text
只缺 CPU 就绪，缺别的阻塞；唤醒回就绪，不上 CPU
TCB 存现场：ID、状态、PC、寄存器、栈；切换 = 存 A 恢复 B
多对一不能多核，一对一、多对多可以
高级造进程，中级换内存，低级给 CPU
FCFS 护航，SJF 饥饿，RR 分时，MLFQ 跑不完就降级
优先级饥饿用老化；EDF 谁先交卷，LLF 谁最来不及（L = 截止 − 现在 − 剩余）
倒置：H 等 L 的锁，M 插队抢 L；继承：L 借 H 的优先级赶紧放锁
```
