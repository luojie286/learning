# 13 · IO 与资源管理

> 一句话概括：**文本用字符流、二进制用字节流；套娃是为了叠加能力，try-with-resources 负责自动关流。**

---

## 一、四个核心抽象类

Java IO 全部围绕这四个抽象基类展开：

| | 输入 | 输出 |
|---|---|---|
| **字节流** | `InputStream` | `OutputStream` |
| **字符流** | `Reader` | `Writer` |

选择依据：

```text
文本数据   → 字符流（Reader / Writer）
二进制数据 → 字节流（InputStream / OutputStream）
```

> 严格来说，一切底层都是字节。字符流只是**帮你按字符集完成编解码**的包装层。

---

## 二、字节流

典型实现：`FileInputStream` / `FileOutputStream`。

适合处理**图片、视频、音频、压缩包、PDF 等二进制数据**。

```java
try (FileInputStream fis = new FileInputStream("a.txt")) {
    byte[] buffer = new byte[1024];
    int len;
    while ((len = fis.read(buffer)) != -1) {
        System.out.println(new String(buffer, 0, len));
    }
}
```

三个必须记住的点：

1. `read()` 返回 **`-1`** 表示读完了
2. `read(byte[])` 返回的是**本次实际读取的字节数**，不是数组长度
3. 最后一次读取通常**不会填满**整个数组，所以必须写 `new String(buffer, 0, len)`——**直接用 `buffer` 会把上一轮的残留数据带出来**

---

## 三、字符流

典型实现：`FileReader` / `FileWriter`，专门读写文本。

```java
try (FileReader reader = new FileReader("a.txt")) {
    char[] buffer = new char[1024];
    int len;
    while ((len = reader.read(buffer)) != -1) {
        System.out.println(new String(buffer, 0, len));
    }
}
```

注意：`FileReader` 使用**平台默认字符集**。要指定编码，请走下面的转换流。

---

## 四、转换流：字节 ↔ 字符的桥

```java
InputStreamReader    // 字节 → 字符（解码）
OutputStreamWriter   // 字符 → 字节（编码）
```

它们的作用是**搭桥 + 指定字符集**：

```java
InputStreamReader reader = new InputStreamReader(
        new FileInputStream("a.txt"),
        StandardCharsets.UTF_8
);
```

名词统一一下，避免混淆：

```text
编码 encode：char → byte
解码 decode：byte → char
```

> 中文乱码 90% 源于「写入时用的字符集」与「读取时用的字符集」不一致。

---

## 五、缓冲流：减少磁盘访问

`BufferedInputStream` / `BufferedOutputStream` / `BufferedReader` / `BufferedWriter`。

作用是**加一层内存缓冲区**，把零散的小读写攒成批量的大读写，显著减少系统调用。

`BufferedReader` 最常用的是**按行读取**：

```java
String line;
while ((line = br.readLine()) != null) {   // 注意：结束标志是 null，不是 -1
    System.out.println(line);
}
```

> ⚠️ 结束标志要分清：
> `InputStream.read()` → **`-1`**
> `BufferedReader.readLine()` → **`null`**

---

## 六、装饰器模式：IO 的「套娃」

Java IO 最典型的写法就是层层包装：

```java
BufferedReader br = new BufferedReader(
        new InputStreamReader(
                new FileInputStream("a.txt"),
                StandardCharsets.UTF_8
        )
);
```

每一层只负责**增加一种能力**：

```text
FileInputStream     → 从文件读字节
InputStreamReader   → 字节按 UTF-8 解码成字符
BufferedReader      → 加缓冲 + 提供 readLine()
```

这就是**装饰器模式**：不改变原对象，通过包装叠功能。理解了这一点，IO 的类名就不需要死记了——**从里到外读名字，能力是累加的**。

---

## 七、try-with-resources：自动关流

```java
try (FileInputStream fis = new FileInputStream("a.txt")) {
    // 使用资源
}
// 离开 try 块自动 close()
```

- 适用于所有实现了 `AutoCloseable` 的资源（流、`Connection`、`Scanner` 等）
- 多个资源可写在同一个括号里，用 `;` 分开，**关闭顺序与声明顺序相反**
- 即使抛异常也会关，比手写 `finally { close(); }` 安全得多（且能正确处理「关闭时也抛异常」的抑制场景）

> 凡是「打开后必须关闭」的东西，一律优先用 try-with-resources，不要再手写 finally。

---

## 📌 易错点

1. **`new String(buffer, 0, len)` 忘了带 `len`**——最后一次读取不满时，会把上一轮的残留数据也读进来。
2. **结束标志混用**——`read()` 用 `-1` 判断，`readLine()` 用 `null` 判断，写反了就是死循环或提前退出。
3. **`FileReader` / `FileWriter` 用平台默认编码**——跨平台或 Windows 上处理中文容易乱码，请显式用 `InputStreamReader` + `StandardCharsets.UTF_8`。
4. **不关流**——文件句柄泄漏，Windows 上还会导致文件被占用无法删除。
5. **搞混「字节流读文本」的场合**——用 `FileInputStream` 读中文文本，很可能读出半个字符（UTF-8 一个汉字 3 字节），必须经过转换流。
6. **`flush()` 与 `close()` 的区别**——缓冲流不 `flush`/`close`，数据可能还留在内存里没落盘。

## 🧠 速记口诀

```text
文本用字符流，二进制用字节流
四个基类：InputStream / OutputStream / Reader / Writer
read() 完了返回 -1，readLine() 完了返回 null
转换流搭桥定编码，缓冲流攒批提性能
套娃从里往外读：文件 → 解码 → 缓冲，能力层层叠加
打开必关：try-with-resources
```
