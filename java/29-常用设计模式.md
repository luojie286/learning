# 29 · 常用设计模式

> 一句话概括：设计模式是针对常见代码设计问题总结出的成熟套路，核心目的是降耦合、提扩展性、提可维护性——不是 Java 语法，也不是框架。

## 一、创建型

**Singleton（单例）**：保证一个类通常只有一个实例。

```java
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() { return INSTANCE; }
}
```

**Factory（工厂）**：把对象创建交给专门的工厂，`Payment p = PaymentFactory.create("ali")`，调用方不直接 new。

**Builder（建造者）**：方便创建属性较多的对象。每个 setter 返回 `this` 所以能链式调用：

```java
EmployeeLoginVO vo = EmployeeLoginVO.builder()
        .id(employee.getId())
        .name(employee.getName())
        .token(token)
        .build();
```

## 二、结构型

**Proxy（代理）**：在调用真实对象前后增加额外逻辑（日志、权限、事务、耗时统计）。**Spring AOP 大量使用代理思想**（见 `25`）。

**Adapter（适配器）**：两个接口不兼容时中间加一层转换。Spring MVC 的 `HandlerAdapter` 就是典型——"怎样调用它"。

**Decorator（装饰器）**：不修改原类地给对象增加功能。Java IO 的套娃就是装饰器：

```java
InputStream in = new BufferedInputStream(new FileInputStream("a.txt"));
```

## 三、行为型

**Strategy（策略）**：把不同方案封装成独立实现可自由替换，适合拆解大型 `if-else`。

**Observer（观察者）**：一个对象变化时通知多个对象。

**Template Method（模板方法）**：固定整体流程，部分步骤由子类决定。Spring 的 `JdbcTemplate`、`RedisTemplate`、`RestTemplate` 都体现这一思想。

## 📌 易错点

- 设计模式不是背 23 个名字——先理解"解决什么问题"，再看结构。
- Builder 不是必须的——属性少时直接构造器/setter 更简单，别过度设计。
- 代理 ≠ 装饰器：代理控制访问（AOP），装饰器叠加功能（IO 套娃）。
- `hashCode()` 不是设计模式话题，别和"哈希/摘要"混淆（见 `16`）。

## 🧠 速记口诀

```text
创建三件套：单例一个例、工厂造对象、Builder 链式建
结构三件套：代理加前后、适配做转换、装饰叠功能
行为三件套：策略拆 if-else、观察做通知、模板定流程
Spring 里到处是模式：AOP 用代理，Mvc 有适配，Template 全家桶
```
