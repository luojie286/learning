# 08 · 异常

> 一句话概括：Checked 异常编译器强制处理，RuntimeException / Error 不用。

---

## 一、Java 异常的分类

```
Throwable
├── Error（严重错误，程序一般无法处理）
│   └── OutOfMemoryError, StackOverflowError ...
└── Exception
    ├── Checked Exception（必须捕获或声明抛出）
    │   └── IOException, SQLException, ParseException ...
    └── RuntimeException（运行时异常，不需要强制捕获）
        └── NullPointerException, IndexOutOfBoundsException, NumberFormatException ...
```

### 强制处理 vs 不强制处理

| 类别 | 必须捕获？ | 典型例子 |
|------|----------|----------|
| **Checked Exception** | ✅ 必须 `try-catch` 或 `throws` 声明 | `IOException`, `SQLException`, `ParseException` |
| **RuntimeException 及其子类** | ❌ 不强制 | `NullPointerException`, `IndexOutOfBoundsException`, `NumberFormatException` |
| **Error 及其子类** | ❌ 不强制（也无法处理） | `OutOfMemoryError`, `StackOverflowError` |

### 一句话记忆

> **必须捕获的叫 Checked Exception；Error / RuntimeException 不用捕获。**

## 二、try-catch-finally 基础

### 例 1：不处理，编译失败

```java
import java.io.UnsupportedEncodingException;

public class Main {
    public static void main(String[] args) {
        byte[] bs = toGBK("中文");   // ❌ 编译错：Unhandled exception
    }

    static byte[] toGBK(String s) {
        return s.getBytes("GBK");    // 抛出 UnsupportedEncodingException
    }
}
```

### 例 2：调用方捕获

```java
public class Main {
    public static void main(String[] args) {
        try {
            byte[] bs = toGBK("中文");
        } catch (UnsupportedEncodingException e) {
            e.printStackTrace();
        }
    }

    static byte[] toGBK(String s) {
        try {
            return s.getBytes("GBK");
        } catch (UnsupportedEncodingException e) {
            throw new RuntimeException(e);   // 包装成 RuntimeException 抛出
        }
    }
}
```

### 例 3：方法声明抛出，由调用方处理

```java
public class Main {
    public static void main(String[] args) {
        try {
            byte[] bs = toGBK("中文");
        } catch (UnsupportedEncodingException e) {
            e.printStackTrace();
        }
    }

    static byte[] toGBK(String s) throws UnsupportedEncodingException {
        return s.getBytes("GBK");   // 自己不处理，甩给调用方
    }
}
```

## 三、catch 顺序：子类必须在前

```java
try {
    ...
} catch (IOException e) {          // 子类先
    ...
} catch (Exception e) {            // 父类后
    ...
}
```

> 反过来写的话，子类 catch 永远不会被执行——因为父类 catch 先把它拦截了，编译器通常会直接报错（unreachable catch block）。

---

## 四、finally 块

> **无论是否捕获异常，finally 块的语句都会执行**——而且是「最后」执行。

```java
try {
    return 1;
} finally {
    System.out.println("finally");  // 仍然会执行
}
// 输出：finally
```

**finally 唯一的例外**：在 try 或 catch 里调用 `System.exit()`，JVM 直接退出，finally 不会执行。

## 五、自定义异常

```java
public class MyException extends Exception {
    public MyException(String message) {
        super(message);          // 调用父类构造器
    }
}

// 使用
throw new MyException("出错了");
```

## 六、常见异常类层级

```
Exception
├── RuntimeException
│   ├── NullPointerException          // 空指针
│   ├── IndexOutOfBoundsException     // 下标越界
│   ├── SecurityException             // 安全异常
│   └── IllegalArgumentException      // 参数非法
│       └── NumberFormatException     // 数字格式
├── IOException
│   ├── UnsupportedCharsetException   // 不支持的字符集
│   ├── FileNotFoundException         // 文件未找到
│   └── SocketException               // 网络异常
├── ParseException                    // 解析异常
├── GeneralSecurityException          // 通用安全
├── SQLException                      // SQL 异常
└── TimeoutException                  // 超时
```

---

## 📌 易错点

1. **Checked Exception 必须处理**——不 `try-catch` 也不 `throws` 就编译失败。
2. **catch 子类在前，父类在后**——否则子类的 catch 是 unreachable，编译器报错。
3. **`finally` 里的 `return` 会覆盖 try / catch 里的 `return`**——非常隐蔽的坑。
4. **`finally` 不保证一定执行**——JVM 退出（`System.exit`）或系统断电时不会执行。
5. **不要用异常做正常控制流**——异常处理有性能开销，应在「真正的异常情况」用。
6. **自定义异常通常继承 `Exception`（Checked）或 `RuntimeException`**——按需选择。

## 🧠 速记口诀

```
Checked 要处理，Runtime / Error 不处理
catch 子类在前，父类在后
finally 一定执行（除非 JVM 死掉）
自定义异常：extends Exception + super(message)
```
