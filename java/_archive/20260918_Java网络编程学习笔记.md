# Java 网络编程学习笔记

> 整理自本次关于 Java 网络编程的学习对话。主线：**IP/端口 → TCP → Socket → IO → 多线程/线程池 → BIO/NIO → HTTP/Spring Boot**。

## 1. 网络编程解决什么问题？

网络编程让**不同进程通过网络交换数据**。例如聊天室中的客户端与服务器：

```text
客户端 A ──网络──┐
                ├── 服务器 ── 转发消息 ── 客户端 B
客户端 B ──网络──┘
```

通信通常需要确定：

- **IP 地址**：定位目标主机，如 `127.0.0.1` 是本机回环地址。
- **端口号（Port）**：定位主机上提供服务的网络端点，如 `8080`。
- **协议**：规定怎样通信；入门优先理解 TCP。

注意：IP + 端口的说法是便于入门的简化模型。实际识别一条 TCP 连接通常使用源 IP、源端口、目的 IP、目的端口的组合。

## 2. Socket 与 ServerSocket

| 类 | 作用 | 常用操作 |
|---|---|---|
| `ServerSocket` | 在指定端口监听并接受 **TCP** 连接 | `new ServerSocket(8080)`、`accept()` |
| `Socket` | 表示 TCP 通信的一端，负责连接及数据收发 | `new Socket(host, port)`、`getInputStream()`、`getOutputStream()` |

建立连接：

```text
服务器：ServerSocket(8080)
          │
          └── accept() 等待连接（阻塞）
                          ▲
客户端：Socket("127.0.0.1", 8080)
          │               │
          └────── connect ┘

连接建立后：客户端 Socket ⇄ TCP ⇄ 服务器端 Socket
```

核心区别：**`ServerSocket` 用来监听/接受连接；`Socket` 用来收发数据**。`accept()` 返回新 `Socket`，以便服务器与这个客户端通信。

## 3. Java IO 与 Socket 如何配合

```java
InputStream in = socket.getInputStream();   // 读取对端发来的字节
OutputStream out = socket.getOutputStream(); // 向对端发送字节
```

Socket 传输的是**字节流**；可以用此前学过的 IO 类进行封装：

- `InputStreamReader`：字节流 → 字符流，指定字符集。
- `BufferedReader.readLine()`：按行读取文本。
- `PrintWriter.println()`：写入一行文本；设置 `autoFlush=true` 时，`println` 自动刷新。

**重要：TCP 不保留应用消息边界。** 一次 `write()` 不等于对端一次 `read()`。采用 `readLine()` 时，双方必须约定以换行符作为一条消息的结束标记；也可以使用长度前缀协议。

## 4. 最小可运行示例：TCP 请求与应答

### Server.java

```java
import java.io.*;
import java.net.*;
import java.nio.charset.StandardCharsets;

public class Server {
    public static void main(String[] args) throws IOException {
        try (ServerSocket server = new ServerSocket(8080)) {
            System.out.println("服务器监听 8080...");
            try (Socket client = server.accept();
                 BufferedReader reader = new BufferedReader(
                     new InputStreamReader(client.getInputStream(), StandardCharsets.UTF_8));
                 PrintWriter writer = new PrintWriter(
                     new OutputStreamWriter(client.getOutputStream(), StandardCharsets.UTF_8), true)) {

                String message = reader.readLine(); // 等待一行消息
                System.out.println("客户端：" + message);
                writer.println("收到：" + message); // 返回一行消息
            }
        }
    }
}
```

### Client.java

```java
import java.io.*;
import java.net.*;
import java.nio.charset.StandardCharsets;

public class Client {
    public static void main(String[] args) throws IOException {
        try (Socket socket = new Socket("127.0.0.1", 8080);
             BufferedReader reader = new BufferedReader(
                 new InputStreamReader(socket.getInputStream(), StandardCharsets.UTF_8));
             PrintWriter writer = new PrintWriter(
                 new OutputStreamWriter(socket.getOutputStream(), StandardCharsets.UTF_8), true)) {

            writer.println("Hello Server");
            System.out.println("服务器：" + reader.readLine());
        }
    }
}
```

在两个终端中先运行服务器，再运行客户端：

```bash
javac Server.java Client.java
java Server
# 在另一个终端执行：
java Client
```

运行效果：服务器打印 `客户端：Hello Server`；客户端打印 `服务器：收到：Hello Server`。

本例服务端只接受**一个客户端、处理一条消息**，用于认识 API，并非完整聊天室。

## 5. TCP 是全双工的

连接建立后两端都可以读写：

```text
客户端 ── Hello Server ──> 服务器
客户端 <── Hello Client ─── 服务器
```

**全双工**表示连接的两端可以同时发送和接收，不需要固定谁只能发送、谁只能接收。

## 6. 多客户端服务器与并发

单线程服务器如果只 `accept()` 一次，只能接受一个连接。想处理更多客户端，通常持续接受：

```java
while (true) {
    Socket client = server.accept();
    // 把该客户端的处理逻辑交给其他执行单元
}
```

学习阶段可以采用“**一个客户端由一个线程处理**”的简单模型：

```text
            ServerSocket
                 │
              accept()
      ┌──────────┼──────────┐
   Client1    Client2    Client3
      │          │          │
   Thread1    Thread2    Thread3
```

但频繁执行 `new Thread(...)` 会有线程创建开销；大量连接还可能耗尽内存、线程等资源。因此可引入学过的 **JUC 线程池**：

```java
ExecutorService pool = Executors.newFixedThreadPool(10);

while (true) {
    Socket client = server.accept();
    pool.submit(() -> handle(client)); // handle 内应正确关闭 Socket
}
```

**注意**：固定 10 个线程不意味着可以同时处理任意数量的长连接。如果 `handle()` 长时间阻塞在读取上，其他连接任务会排队；默认的 `newFixedThreadPool` 队列也可能积压。生产系统通常还需考虑限流、超时、拒绝策略，或改用 NIO/事件驱动模型。

## 7. TCP 与 UDP 的区别

| 维度 | TCP | UDP |
|---|---|---|
| 是否建立连接 | 面向连接 | 无连接 |
| 数据形式 | 有序字节流 | 数据报（保留报文边界） |
| 可靠性 | 提供有序、可靠传输机制 | 默认不保证到达、顺序及去重 |
| Java API | `Socket`、`ServerSocket` | `DatagramSocket`、`DatagramPacket` |
| 典型场景 | HTTP/1.1、HTTP/2、数据库连接等 | DNS、实时音视频、游戏通信等 |

TCP 的“可靠”并不意味着网络永远不故障；连接中断等情形仍需应用处理。UDP 不等于“一定更快”，只是协议开销与语义不同，实际性能取决于场景。

当前阶段优先掌握 **TCP**，UDP 的类及用途先了解即可。

## 8. BIO 与 NIO

**BIO（阻塞式 IO）**：如经典 `ServerSocket.accept()`、`BufferedReader.readLine()`，如果没有连接或足够的数据，调用线程会等待。

**NIO** 的常见核心组件：

- `Channel`：用于数据传输的通道。
- `Buffer`：读写数据的缓冲区。
- `Selector`：配合**非阻塞通道**在一个线程中关注多个连接的就绪事件。

NIO 能减少“每个连接固定占用一个阻塞线程”的限制，但也带来事件循环、缓冲区管理等复杂度。**Netty** 在 Java 网络服务中大量使用 NIO 思路。

## 9. Socket、HTTP、Tomcat、Spring Boot 的关系

```text
你的业务代码：@GetMapping("/user")
            ↓
         Spring MVC
            ↓
     Tomcat 等 Web 服务器
            ↓
       Socket / NIO
            ↓
          TCP/IP
            ↓
           网络
```

- **Socket**：Java 应用使用传输层服务的编程接口。
- **HTTP**：应用层协议，定义请求/响应的组织形式。
- **Tomcat**：负责连接管理、HTTP 解析等底层工作，使业务代码通常不需要亲自调用 `ServerSocket`。
- **Spring MVC**：将 HTTP 请求映射到控制器方法，例如 `@GetMapping`。

补充：上图针对常见的 **HTTP/1.1、HTTP/2 over TCP**；**HTTP/3 基于 QUIC，而 QUIC 使用 UDP**。

## 10. 建议学习顺序与动手目标

**推荐路径：**

```text
IP/端口 → TCP/UDP → Socket/ServerSocket → Java IO
         → 多线程/线程池 → BIO/NIO → HTTP
         → Tomcat/Spring Boot → Netty（按需）
```

**必须动手：**

1. 分别编写 TCP 服务端和客户端，传送一行文本。
2. 改造为**双向收发**，并验证 `readLine()` 与 `println()` 如何配合。
3. 给服务端添加 `while (true) + 线程池`，支持多个客户端。
4. 实现一个简易聊天室：客户端发送/接收并行；服务器按连接维护客户端，并向其他人转发文本。

**暂时只需理解概念：** UDP 详细 API、Selector 底层机制、复杂 TCP 算法、Netty 内核。

### 一句话总结

> **Java TCP 网络编程 = 通过 Socket 建立连接，利用 Java IO 收发字节，再使用并发机制处理多个连接；更上层的 Tomcat 和 Spring Boot 把大量底层通信细节封装了起来。**
