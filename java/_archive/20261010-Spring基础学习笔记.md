# Spring 基础学习笔记

> 学习主题：Spring 入门、IoC、DI、Bean、AOP、Spring MVC 与 Spring Boot  
> 日期：2026-10-10  
> 适用阶段：已掌握 Java 基础，刚开始学习 Java 后端框架

## 一、Spring 是什么？解决什么问题？

**Spring 是 Java 生态中的应用开发框架**，核心能力包括：

- **IoC（控制反转）**：由 Spring 容器负责管理对象，而不是业务代码自行组织所有对象的创建。
- **DI（依赖注入）**：容器把对象所需的依赖提供给它，实现松耦合。
- **AOP（面向切面编程）**：将日志、事务等横切逻辑与核心业务逻辑分离。
- 整合 Web、数据访问、事务管理等能力，减少重复开发。

不使用 Spring 时：

```java
public class UserService {
    private final UserDao userDao = new UserDao();
}
```

这里 `UserService` 直接负责创建 `UserDao`。如果要替换实现（如 MySQL、模拟实现），需要修改业务代码，依赖关系也更难测试。

引入 Spring 后，对象的创建和依赖组装交给容器：

```text
        Spring IoC 容器
          │       │
       UserDao  UserService
          └───────>│
              注入依赖
```

**核心思想：业务类专注业务，Spring 负责管理对象和组装依赖。**

## 二、IoC：控制反转

**IoC（Inversion of Control）**：将对象创建、依赖关系组装等控制权交给容器。

### 1. 什么是 Spring Bean？

**Bean 就是被 Spring IoC 容器管理的对象。** Bean 本质仍是普通 Java 对象，并非特殊的 Java 数据类型。

### 2. 什么是 Spring 容器？

Spring 容器负责：

1. 发现和注册 Bean 定义。
2. 创建 Bean，并注入其依赖。
3. 管理 Bean 的作用域和部分生命周期回调。
4. 按需提供 Bean 给其他代码。

常见容器接口：

- `BeanFactory`：基础容器接口。
- `ApplicationContext`：功能更丰富、开发中更常用的容器接口。

示例：

```java
@Component
public class UserManager {
}
```

当该类位于**组件扫描范围**内时，Spring 可以扫描到它并注册为 Bean。

获取 Bean 的示例：

```java
UserManager manager = context.getBean(UserManager.class);
```

> 注意：这里的 `context` 需要是已经创建好的 `ApplicationContext`；实际业务中通常优先使用依赖注入，而不是到处手动调用 `getBean()`。

## 三、DI：依赖注入

**DI（Dependency Injection）** 是实现 IoC 的常见方式：对象不自行创建依赖，而由外部容器将依赖传入。

```java
@Repository
public class UserDao {
    public String findName() {
        return "Alice";
    }
}

@Service
public class UserService {
    private final UserDao userDao;

    public UserService(UserDao userDao) {
        this.userDao = userDao;
    }

    public String getUserName() {
        return userDao.findName();
    }
}
```

**执行逻辑：**

1. Spring 扫描到 `UserDao` 和 `UserService`。
2. Spring 创建 `UserDao` Bean。
3. 创建 `UserService` 时，发现构造方法依赖 `UserDao`。
4. Spring 将已管理的 `UserDao` 注入 `UserService`。

### IoC 和 DI 的区别

| 概念 | 含义 | 侧重点 |
| --- | --- | --- |
| IoC | 控制反转 | **谁负责对象管理和依赖组装** |
| DI | 依赖注入 | **对象的依赖如何传入** |

**初学阶段优先使用构造器注入**：依赖关系明确，便于测试；对于只有一个构造方法的 Spring Bean，通常不需要写 `@Autowired`。

### 常见注解

| 注解 | 主要用途 |
| --- | --- |
| `@Component` | 通用组件，注册为 Bean |
| `@Service` | 业务逻辑层组件 |
| `@Repository` | 数据访问层组件 |
| `@Controller` | MVC 控制器 |
| `@RestController` | REST 风格接口控制器（相当于 `@Controller` + `@ResponseBody`） |
| `@Autowired` | 自动注入依赖；构造器注入在单构造器场景下可省略 |

`@Service`、`@Repository`、`@Controller` 等具有不同的语义，也都可参与组件扫描；并不是仅仅靠类名约定就能注册 Bean。

## 四、AOP：面向切面编程

**AOP（Aspect-Oriented Programming）** 用于把多个业务方法共同需要的横切关注点抽离出来，例如：

- 日志记录
- 方法执行时间统计
- 权限控制（视具体技术实现而定）
- 声明式事务

没有 AOP 时，日志可能写在每个业务方法中：

```java
public void createUser() {
    System.out.println("开始执行");
    // 创建用户
    System.out.println("执行结束");
}
```

使用 AOP 后，可以把公共处理组织为切面，典型调用流程：

```text
外部调用业务方法
      ↓
  Spring 代理对象
      ↓
 执行附加逻辑（如日志）
      ↓
    执行业务方法
      ↓
 执行附加逻辑（如日志）
```

### 事务案例：`@Transactional`

```java
@Service
public class TransferService {

    @Transactional
    public void transfer() {
        // 扣除 A 账户金额
        // 增加 B 账户金额
    }
}
```

对于符合 Spring 事务代理规则、且使用受支持事务资源的调用，Spring 能在业务方法前后完成事务的开启、提交或回滚。

**需要注意的三个细节：**

1. `@Transactional` 并非给任意方法加上就必然生效，需要 Spring 事务管理配置和通过适当的代理调用路径。
2. 默认情况下，通常对 `RuntimeException` 和 `Error` 回滚；受检异常需要按需配置 `rollbackFor`。
3. 在默认的代理模式下，同一个对象内部直接调用自身另一个带 `@Transactional` 的方法，可能绕过事务代理。

现阶段先理解 **“代理对象在调用业务方法前后添加功能”** 即可，不必立刻深入代理源码。

## 五、Spring、Spring MVC、Spring Boot 的关系

| 技术 | 主要解决的问题 |
| --- | --- |
| **Spring Framework** | IoC、DI、AOP、事务，以及一系列基础模块 |
| **Spring MVC** | 处理 HTTP 请求、路由映射、参数绑定、响应输出等 Web 开发工作；它是 Spring Framework 的 Web 模块 |
| **Spring Boot** | 基于 Spring 生态提供自动配置、Starter 依赖、嵌入式服务器等，简化项目搭建和运行 |

**易混点：Spring Boot 不是 Spring 的替代品，而是让 Spring 应用更容易启动、配置和部署的工具体系。**

Spring Boot 启动类通常如下：

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

`@SpringBootApplication` 主要组合了配置、自动配置和组件扫描相关能力。默认组件扫描以启动类所在包及其子包为范围。

## 六、Spring MVC：第一个 HTTP 接口

```java
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello Spring";
    }
}
```

启动带有 Spring Web 依赖的 Spring Boot 应用后，访问：

```text
GET http://localhost:8080/hello
```

响应体：

```text
Hello Spring
```

这里：

- `@RestController`：表示这是处理 Web 请求的控制器，方法返回值通常直接写入 HTTP 响应体。
- `@GetMapping("/hello")`：将 GET `/hello` 请求映射到 `hello()` 方法。

请求流转（简化）：

```text
浏览器 / 客户端
       │ GET /hello
       ▼
Spring MVC（DispatcherServlet）
       ▼
HelloController.hello()
       ▼
HTTP 响应：Hello Spring
```

## 七、典型后端三层结构

```text
src/main/java/com/example/demo/
├── DemoApplication.java
├── controller/
│   └── UserController.java      # 接收 HTTP 请求，返回响应
├── service/
│   └── UserService.java         # 编写业务逻辑
├── repository/
│   └── UserRepository.java      # 数据访问（或使用 mapper 包）
└── entity/
    └── User.java               # 领域 / 数据实体
```

典型调用路径：

```text
客户端
  ↓ HTTP 请求
Controller
  ↓
Service
  ↓
Repository / Mapper
  ↓
MySQL
```

**三层各自职责：**

- Controller：接收请求、参数校验、调用 Service、返回结果。
- Service：实现业务规则，协调多个数据访问操作，按需管理事务。
- Repository / Mapper：查询和修改数据。

注意：这种三层划分是**常见的架构组织方式**，不是 Spring 强制要求的目录结构。

## 八、学习顺序与动手练习

### 推荐顺序

1. **IoC → Bean → DI**：理解对象由谁创建、依赖由谁提供。
2. **组件扫描和注解**：会使用 `@Component`、`@Service`、`@Repository`。
3. **Spring Boot 启动**：能解释 `@SpringBootApplication`，理解组件扫描范围。
4. **Spring MVC**：熟悉 `@RestController`、`@GetMapping`、`@PostMapping`、请求参数与 JSON 响应。
5. **接入 MySQL**：通过 MyBatis 或其他数据访问方案完成 CRUD。
6. **AOP 和事务**：理解代理、`@Transactional` 的用途与常见失效场景。

### 最小实践任务

**练习 A：体会依赖注入**

- 创建 `UserDao`，返回一个固定用户名。
- 创建 `UserService`，用构造器接收 `UserDao`。
- 创建 `UserController`，调用 `UserService` 返回用户名。
- 全程不在业务类中手动 `new UserDao()`。

**练习 B：验证 Bean 是否由容器管理**

- 通过 `ApplicationContext.getBean(UserService.class)` 获取 Bean。
- 思考：它与手动 `new UserService(...)` 有什么不同？

**练习 C：体验 Web 接口**

- 启动 Spring Boot 服务。
- 使用浏览器或 API 调试工具访问 `GET /hello`。
- 观察 Controller 的返回值如何变成 HTTP 响应。

### 自检题

1. Bean 与普通 Java 对象有什么关系？
2. IoC 与 DI 各自强调什么？
3. 为什么推荐构造器注入？
4. `@Service` 和 `@RestController` 分别放在哪一层？
5. Spring MVC 与 Spring Boot 的区别是什么？
6. 为什么 `@Transactional` 可能在类内部自调用时失效？

## 九、考前速记

```text
Spring Framework：Java 应用框架及基础设施
IoC：对象管理与依赖组装交给容器
Bean：被 Spring 容器管理的对象
DI：容器将依赖注入对象（优先构造器注入）
AOP：把日志、事务等横切关注点从业务中抽离
Spring MVC：接收 HTTP 请求、映射控制器、组织响应
Spring Boot：自动配置 + Starter + 简化运行
三层：Controller → Service → Repository/Mapper → DB
```

**一句话总结：Spring 管对象和对象之间的关系，Spring MVC 处理 Web 请求，Spring Boot 让 Spring 应用更容易开发和启动。**
