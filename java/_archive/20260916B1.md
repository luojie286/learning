# 20260916B1｜Java `volatile` 学习笔记

## 1. `volatile` 是什么

`volatile` 是 Java 中用于多线程共享变量的关键字。

核心作用：

- 保证**可见性**
- 保证一定程度的**有序性**
- **不能保证复合操作的原子性**

可以先记住一句：

> `volatile = 可见性 + 禁止部分重排序，但不保证复合操作原子性。`

---

## 2. 可见性

### 2.1 什么叫可见性

多个线程访问同一个变量时，一个线程修改了变量，其他线程能够及时看到这个修改，就叫**可见性**。

例如：

```java
class Task {
    private volatile boolean running = true;

    public void stop() {
        running = false;
    }

    public void run() {
        while (running) {
            // 工作
        }
    }
}
```

假设：

```text
线程 A                     线程 B

while (running)           running = false
```

如果 `running` 是普通变量，线程 A 理论上可能一直看到旧值：

```text
running = true
```

即使线程 B 已经执行：

```java
running = false;
```

线程 A 也不一定能及时观察到变化。

加上：

```java
volatile boolean running;
```

之后，线程 B 修改 `running`，线程 A 后续读取这个变量时，可以看到新的值。

---

## 3. 从 JMM 角度理解

Java 内存模型（JMM）可以直观理解为：

```text
主内存

running = true
      ↑
 ┌────┴─────┐
线程 A      线程 B
true        true
```

每个线程都可能拥有自己当前观察到的变量值。

线程 B 执行：

```java
running = false;
```

如果 `running` 是 `volatile` 变量，那么 Java 内存模型会保证其他线程之后对该变量的读取能够观察到这个写入。

### 注意

常见说法：

> volatile 会把变量“立即刷新到主内存”。

这只是帮助理解的简化说法。

更准确的说法是：

> Java 内存模型为 `volatile` 的读写规定了特殊的内存可见性语义。

不能简单理解为“每一次 volatile 读写都一定直接访问物理 RAM”。

---

## 4. `volatile` 不能保证复合操作原子性

这是非常重要的考点。

例如：

```java
volatile int count = 0;
```

多个线程同时执行：

```java
count++;
```

仍然可能出错。

因为：

```java
count++;
```

并不是一步完成的，大致可以拆成：

```text
读取 count
↓
count + 1
↓
写回 count
```

例如初始：

```text
count = 0
```

线程 A 和线程 B 同时执行：

```text
线程 A：读取 0
线程 B：读取 0

线程 A：0 + 1 → 写入 1
线程 B：0 + 1 → 写入 1
```

最终：

```text
count = 1
```

而正确结果应该是：

```text
count = 2
```

所以：

```java
volatile int count;
count++;
```

仍然是**线程不安全**的。

---

## 5. 为什么 `count++` 不安全

关键点在于：

> `volatile` 只能保证其他线程能够看到最新值，但不能保证“读 → 改 → 写”这一整组操作不可被其他线程插入。

因此：

```java
count++;
```

属于典型的**复合操作**。

需要改用：

```java
AtomicInteger count = new AtomicInteger();

count.incrementAndGet();
```

或者：

```java
synchronized
```

或者：

```java
Lock
```

---

## 6. `volatile` 与原子性的关系

需要区分：

### 单次读写

```java
value = 10;
int x = value;
```

对于 `volatile` 变量，单次读写本身具有相应的 volatile 语义。

### 复合操作

```java
value++;
value += 10;
if (value == 0) {
    value = 1;
}
```

这些操作都包含多个步骤，因此不能只靠 `volatile` 保证线程安全。

判断时可以看：

```text
读
↓
修改
↓
写
```

只要存在这种复合过程，就需要警惕并发问题。

---

## 7. `volatile` 与有序性

为了优化程序，JVM 和 CPU 可能在不影响单线程执行结果的前提下，对部分指令进行重排序。

例如：

```java
int data = 0;
boolean ready = false;
```

线程 A：

```java
data = 100;
ready = true;
```

线程 B：

```java
if (ready) {
    System.out.println(data);
}
```

我们希望：

```text
data = 100
↓
ready = true
```

如果：

```java
volatile boolean ready;
```

那么对 `ready` 的 volatile 写和读具有特殊的内存语义，会限制某些指令重排序。

可以简单理解为：

```text
data = 100;

------------- volatile 相关内存屏障

ready = true;
```

这样，当另一个线程观察到：

```java
ready == true
```

时，它也应该能够观察到前面已经完成的：

```java
data = 100;
```

---

## 8. happens-before 规则

Java 内存模型规定：

> 对一个 `volatile` 变量的写，happens-before 后续其他线程对这个 `volatile` 变量的读。

例如：

```java
int data = 0;
volatile boolean ready = false;
```

线程 A：

```java
data = 100;
ready = true;
```

线程 B：

```java
if (ready) {
    System.out.println(data);
}
```

如果线程 B 读到：

```java
ready == true
```

那么线程 A 在：

```java
ready = true;
```

之前完成的操作，例如：

```java
data = 100;
```

对于线程 B 也是可见的。

---

## 9. `volatile` 与 `synchronized` 对比

| 特性 | `volatile` | `synchronized` |
|---|---|---|
| 可见性 | ✅ | ✅ |
| 有序性 | ✅ | ✅ |
| 复合操作原子性 | ❌ | ✅ |
| 是否互斥 | ❌ | ✅ |
| 是否可能等待锁 | ❌ | ✅ |
| 典型用途 | 状态标志 | 临界区、多步共享数据修改 |

---

## 10. 典型适用场景

`volatile` 很适合：

```java
private volatile boolean stopped = false;
```

线程 A：

```java
while (!stopped) {
    // 工作
}
```

线程 B：

```java
stopped = true;
```

特点是：

```text
一个或多个线程读取状态
另一个线程修改状态
```

没有复杂的：

```text
读 → 修改 → 写
```

所以非常适合使用 `volatile`。

---

## 11. 不适合 `volatile` 的场景

例如：

```java
volatile int money;

money -= 100;
```

`money -= 100` 大致包含：

```text
读取 money
↓
计算 money - 100
↓
写回 money
```

属于复合操作。

所以即使加了：

```java
volatile
```

也仍然可能发生并发问题。

---

## 12. 判断原则

可以快速记：

```text
只是：
一个线程修改状态
其他线程读取状态

→ 可以考虑 volatile
```

例如：

```java
volatile boolean shutdown;
```

而：

```text
涉及：
读 → 修改 → 写
多个线程同时修改共享数据

→ synchronized / Lock / Atomic
```

---

## 13. 常见陷阱

### 陷阱 1：认为 `volatile` 可以代替锁

错误。

`volatile` 不提供互斥。

---

### 陷阱 2：认为 `volatile int count; count++;` 是线程安全的

错误。

`count++` 是复合操作。

---

### 陷阱 3：把可见性理解成原子性

两者不同。

- 可见性：其他线程能不能看到最新值
- 原子性：一个操作能不能被其他线程插入执行

---

### 陷阱 4：把 volatile 简单理解成“直接访问主内存”

这只是教学模型。

更准确的是：

> `volatile` 通过 Java 内存模型规定的读写语义来建立线程间的可见性和有序性保证。

---

## 14. 面试回答模板

如果面试官问：

> `volatile` 有什么作用？

可以回答：

> `volatile` 主要保证共享变量在线程之间的可见性，并通过 JMM 的 happens-before 规则限制部分指令重排序，从而保证一定的有序性。但它不能保证像 `count++` 这种复合操作的原子性，所以涉及多个线程同时修改共享状态时，通常还需要使用 synchronized、Lock 或原子类。


## 16. 最终速记

```text
volatile

1. 保证可见性
2. 保证一定的有序性
3. 建立 volatile 写 → volatile 读 的 happens-before
4. 不提供互斥
5. 不保证复合操作原子性
6. count++ 即使加 volatile 仍然不安全
7. 最典型场景：线程停止标志、状态标志
```

一句话：

> `volatile` 适合“一个线程写状态，其他线程读状态”；涉及“读 → 改 → 写”时，通常要用 Atomic、synchronized 或 Lock。

本笔记中关于 `volatile` 的可见性、happens-before、有序性以及 `count++` 不具备原子性的描述符合 Java 内存模型。需要特别注意：“刷新到主内存”只是教学上的简化表述，不能理解为每次都直接读写物理内存。
