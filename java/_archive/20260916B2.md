# 20260916B2 Java 学习笔记

## 1. Java 类加载机制

Java 类从 `.class` 字节码文件进入 JVM 并最终可以被程序使用，大致经历：

```text
加载 Loading
    ↓
连接 Linking
    ├── 验证 Verification
    ├── 准备 Preparation
    └── 解析 Resolution
    ↓
初始化 Initialization
```

可以简记为：

```text
加载 → 验证 → 准备 → 解析 → 初始化
```

其中：

```text
连接 = 验证 + 准备 + 解析
```

### 1.1 加载 Loading

JVM 在加载阶段主要做三件事：

1. 找到类对应的字节码。
2. 把字节码转换成 JVM 内部的数据结构。
3. 为这个类创建对应的 `Class` 对象。

例如：

```java
class User {
}
```

编译后得到：

```text
User.class
```

JVM 加载后，就能得到这个类的运行时信息。

注意：

```java
User.class
```

表示类本身的运行时类型信息。

而：

```java
new User();
```

表示创建 `User` 对象。

二者不是一回事。

---

### 1.2 验证 Verification

验证阶段用于检查 `.class` 文件是否合法、安全。

例如检查：

- 文件格式是否正确
- 字节码是否合法
- 类型使用是否正确
- 是否存在破坏 JVM 安全性的操作

可以简单理解为：

> 验证阶段负责检查这个 class 文件“能不能安全地执行”。

---

### 1.3 准备 Preparation

准备阶段主要做：

> 为静态变量分配内存，并设置默认值。

例如：

```java
class User {
    static int age = 18;
}
```

准备阶段先得到：

```text
age = 0
```

而不是：

```text
age = 18
```

`18` 一般要到初始化阶段才真正赋值。

再比如：

```java
static int a = 10;
static String name = "Jack";
```

准备阶段：

```text
a = 0
name = null
```

初始化阶段：

```text
a = 10
name = "Jack"
```

#### 特殊情况：编译期常量

例如：

```java
static final int MAX = 100;
```

如果它属于编译期常量，可能通过 class 文件中的 `ConstantValue` 属性，在准备阶段就直接得到：

```text
MAX = 100
```

所以不能绝对地说：

> 准备阶段所有 static 变量都一定只得到默认值。

---

### 1.4 解析 Resolution

解析阶段的核心是：

```text
符号引用 → 直接引用
```

例如 `.class` 文件里可能只记录：

```text
com.example.User
```

这种“名字形式”的引用。

JVM 需要进一步把它解析到运行时真正对应的类、方法或字段。

现阶段记住：

> 解析就是把抽象的符号引用转换成可以真正定位目标的引用。

---

### 1.5 初始化 Initialization

初始化阶段主要执行：

- 静态变量的显式赋值
- `static {}` 静态代码块

编译器会把这些内容组织到类初始化方法：

```text
<clinit>()
```

例如：

```java
class Test {
    static int a = 10;

    static {
        System.out.println("hello");
        a = 20;
    }
}
```

逻辑上可理解为：

```java
<clinit>() {
    a = 10;
    System.out.println("hello");
    a = 20;
}
```

最终：

```text
a = 20
```

---

### 1.6 static 初始化顺序

静态变量赋值和静态代码块按照源码出现顺序执行。

例如：

```java
class Test {
    static int a = 10;

    static {
        System.out.println(a);
        a = 20;
    }

    static int b = 30;
}
```

执行顺序大致为：

```text
a = 10
打印 a
a = 20
b = 30
```

---

### 1.7 父类和子类初始化顺序

初始化子类之前，通常会先初始化父类。

例如：

```java
class Parent {
    static {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    static {
        System.out.println("Child");
    }
}
```

执行：

```java
new Child();
```

输出：

```text
Parent
Child
```

## 2. static 静态代码块

语法：

```java
static {
    // 代码
}
```

例如：

```java
class User {

    static {
        System.out.println("User 初始化");
    }
}
```

它的作用是：

> 在类初始化时执行一段静态初始化逻辑。

正常情况下，一个类在同一个类加载器中只初始化一次，因此静态代码块通常也只执行一次。

例如：

```java
new User();
new User();
```

静态代码块仍然只执行一次。

### 静态代码块 vs 普通代码块

```java
class User {

    static {
        System.out.println("静态代码块");
    }

    {
        System.out.println("普通代码块");
    }

    User() {
        System.out.println("构造方法");
    }
}
```

连续执行：

```java
new User();
new User();
```

大致输出：

```text
静态代码块
普通代码块
构造方法
普通代码块
构造方法
```

因此：

```text
static {}   → 类初始化时执行
{}          → 每次创建对象时执行
构造方法     → 每次创建对象时执行
```

## 3. Java 文件结构

一个典型 Java 文件：

```java
package com.example.demo;

import java.util.List;

public class User {

    private String name;

    public User(String name) {
        this.name = name;
    }

    public void hello() {
        System.out.println(name);
    }
}
```

基本顺序：

```text
package
↓
import
↓
class / interface / enum / record
↓
字段
↓
构造方法
↓
方法
```

---

### 3.1 package

例如：

```java
package com.example.demo;
```

表示当前类属于：

```text
com.example.demo
```

通常目录结构也应与包名对应：

```text
src
└── com
    └── example
        └── demo
            └── User.java
```

---

### 3.2 import

例如：

```java
import java.util.List;
```

表示：

> 当前源码文件中可以直接使用 `List`，它实际指向 `java.util.List`。

如果不写 `import`，也可以直接写完整类名：

```java
java.util.List<String> list;
```

---

### 3.3 自己写的不同包之间如何 import

例如项目结构：

```text
src
└── com
    └── example
        ├── app
        │   └── Main.java
        └── util
            └── UserUtil.java
```

`UserUtil.java`：

```java
package com.example.util;

public class UserUtil {
    public static void test() {
        System.out.println("test");
    }
}
```

`Main.java`：

```java
package com.example.app;

import com.example.util.UserUtil;

public class Main {
    public static void main(String[] args) {
        UserUtil.test();
    }
}
```

关键不是两个包必须挨在一起，而是：

```text
包结构正确
+
目标类位于当前项目可访问的源码路径 / classpath 中
```

---

### 3.4 同一个包通常不需要 import

例如：

```text
com.example.demo
├── Main.java
└── User.java
```

两者都写：

```java
package com.example.demo;
```

那么：

```java
User user = new User();
```

通常不需要再写：

```java
import com.example.demo.User;
```

---

### 3.5 java.lang 默认导入

例如：

```java
String s = "abc";
```

不需要：

```java
import java.lang.String;
```

因为 `java.lang` 会被自动导入。

---

### 3.6 一个 .java 文件可以有几个类

一个 `.java` 文件中可以有多个顶级类。

例如：

```java
public class Main {
}

class User {
}

class Student {
}
```

合法。

但：

> 一个 `.java` 文件中最多只能有一个 `public` 顶级类。

并且如果存在：

```java
public class Main
```

那么文件名必须是：

```text
Main.java
```

## 4. javap 与字节码

Java 源程序：

```text
.java
```

通过：

```text
javac
```

编译为：

```text
.class
```

`.class` 中存放 JVM 字节码。

关系：

```text
.java 源代码
    ↓ javac
.class 字节码
    ↓ JVM / JIT
机器指令
```

---

### 4.1 javap 是什么

`javap` 是 JDK 自带的 class 查看 / 反汇编工具。

常用命令：

```bash
javap Test
```

查看类结构。

```bash
javap -c Test
```

查看字节码。

```bash
javap -v Test
```

查看更详细的 class 信息，例如：

- 常量池
- class 版本
- 字段
- 方法
- 字节码
- LineNumberTable
- max_stack
- max_locals

---

### 4.2 示例：加法字节码

Java：

```java
int a = 1;
int b = 2;
int c = a + b;
```

可能看到：

```text
iconst_1
istore_1
iconst_2
istore_2
iload_1
iload_2
iadd
istore_3
```

含义：

```text
iconst_1  → 常量 1 入栈
istore_1  → 存到局部变量表 slot 1
iconst_2  → 常量 2 入栈
istore_2  → 存到 slot 2
iload_1   → a 入操作数栈
iload_2   → b 入操作数栈
iadd      → 弹出两个 int，相加后结果重新入栈
istore_3  → 结果存入 c
```

---

### 4.3 常见字节码

```text
iconst / bipush / sipush   加载整数常量
iload / aload              加载局部变量
istore / astore            保存局部变量
iadd / isub / imul         整数运算
getfield / putfield        访问对象字段
getstatic / putstatic      访问静态字段
invokevirtual              调用普通实例方法
invokestatic               调用静态方法
invokespecial              构造器、private、super 等
invokeinterface            调用接口方法
new                        创建对象
return / ireturn / areturn 返回
```

---

### 4.4 `<init>` 和 `<clinit>`

```text
<init>   → 对象初始化相关
<clinit> → 类初始化相关
```

例如：

```java
new User();
```

常见字节码会包含：

```text
new
dup
invokespecial User."<init>"
```

## 5. 字节码是不是原子操作

结论：

> 一条字节码指令不等于一个原子操作。

例如：

```java
count++;
```

可能对应：

```text
getstatic
iconst_1
iadd
putstatic
```

显然不是单一步骤。

即使某个 Java 操作只对应一条字节码，也不能直接判断它一定是原子操作，因为：

```text
字节码
↓
JVM 解释 / JIT 编译
↓
机器指令
```

一条字节码最终仍可能对应多条机器操作。

因此判断原子性应该依据：

```text
Java 内存模型 / 具体同步语义
```

而不是单纯数“字节码有几条”。

## 6. Java 原子操作

原子操作可以理解为：

> 一个操作在并发语义上不可再被拆分观察，不会暴露中间状态。

例如：

```java
int x = 10;
```

对普通 `int` 的单次读写具有原子性保证。

但：

```java
x++;
```

不是原子操作。

因为它包含：

```text
读 x
↓
x + 1
↓
写回 x
```

---

### 6.1 x++ 为什么会丢失更新

假设：

```text
x = 0
```

两个线程同时执行：

```java
x++;
```

可能发生：

```text
A 读取 0
B 读取 0

A 计算 1
B 计算 1

A 写回 1
B 写回 1
```

最终：

```text
x = 1
```

而不是 `2`。

---

### 6.2 volatile 不能保证 x++ 原子性

```java
volatile int count;
```

`volatile` 主要保证：

```text
可见性
+
一定程度的有序性
```

但：

```java
count++;
```

仍然是：

```text
读
+
改
+
写
```

所以仍然不是原子的。

---

### 6.3 synchronized 如何保证原子性

```java
synchronized (lock) {
    count++;
}
```

这里不是让 `count++` 变成了单条原子指令，而是：

> 保证同一时刻只有一个线程能进入这个临界区。

因此：

```text
读取
加一
写回
```

这整段在互斥意义上成为一个整体。

---

### 6.4 Atomic 原子类

常见类：

```java
AtomicInteger
AtomicLong
AtomicBoolean
AtomicReference
```

例如：

```java
AtomicInteger count = new AtomicInteger(0);
```

原子自增：

```java
count.incrementAndGet();
```

类似：

```java
++count;
```

但具有原子性。

常见方法：

```java
get()
set()
incrementAndGet()
getAndIncrement()
addAndGet()
getAndAdd()
compareAndSet()
```

---

### 6.5 CAS

CAS：

```text
Compare And Set
比较并交换
```

例如：

```java
count.compareAndSet(5, 6);
```

含义：

```text
如果当前值仍然是 5
→ 原子地修改为 6

否则
→ 修改失败
```

CAS 的核心思想：

```text
读到旧值
↓
准备新值
↓
比较当前值是否仍等于旧值
↓
相等 → 更新
不等 → 失败 / 重试
```

Atomic 原子类大量依赖 CAS。

---

### 6.6 CAS 与 synchronized 的思想区别

`synchronized`：

```text
先加锁
↓
一次只允许一个线程执行
```

属于比较典型的悲观并发控制思想。

CAS：

```text
先尝试修改
↓
如果发现别人改过
↓
重试
```

属于典型乐观并发控制思想。

---

### 6.7 多个原子操作组合后不一定原子

例如：

```java
AtomicInteger count = new AtomicInteger();

if (count.get() < 10) {
    count.incrementAndGet();
}
```

虽然：

```java
get()
```

和：

```java
incrementAndGet()
```

各自都是原子的，

但：

```text
判断 + 修改
```

整体不是原子的。

可能：

```text
count = 9

线程 A 判断 9 < 10
线程 B 判断 9 < 10

A → 10
B → 11
```

所以：

> 多个原子操作组合起来，不代表整个逻辑仍然是原子的。

## 7. 栈虚拟机与寄存器虚拟机

这两者可以理解为两种不同的虚拟 CPU 执行模型。

---

### 7.1 栈虚拟机

JVM 字节码属于典型的：

```text
基于栈的执行模型
```

例如：

```java
int c = a + b;
```

可能是：

```text
iload_1
iload_2
iadd
istore_3
```

过程：

```text
[]
↓ iload a
[a]
↓ iload b
[a, b]
↓ iadd
[a+b]
↓ istore c
[]
```

特点：

> 操作数通常通过栈顶隐式传递。

---

### 7.2 寄存器虚拟机

寄存器式执行模型中，指令显式指定虚拟寄存器。

例如：

```text
ADD R3, R1, R2
```

表示：

```text
R3 = R1 + R2
```

特点：

> 操作数通过寄存器编号显式指定。

---

### 7.3 栈式与寄存器式本质区别

栈式：

```text
iadd
```

含义：

```text
把栈顶两个数弹出并相加
```

寄存器式：

```text
ADD R3, R1, R2
```

含义：

```text
R3 = R1 + R2
```

所以核心区别：

> 栈式通过栈顶隐式指定操作数；寄存器式通过寄存器编号显式指定操作数。

---

### 7.4 栈虚拟机优点

- 指令简单
- 单条字节码通常较紧凑
- 编译器生成较简单
- 适合跨平台字节码设计

缺点：

- 同一个运算通常需要更多条指令
- 会出现大量 load/store/push/pop 类动作

---

### 7.5 寄存器虚拟机优点

- 同样逻辑通常需要更少指令
- 更接近真实 CPU
- 执行模型更直接

缺点：

- 指令编码更复杂
- 需要显式管理寄存器编号
- 编译器实现更复杂

---

### 7.6 JVM 虽然是栈式，但 CPU 仍使用寄存器

非常重要：

```text
JVM 字节码是栈式
≠
CPU 最终也是栈式执行
```

JIT 会把字节码编译成本地机器码，真实 CPU 仍会大量使用：

```text
CPU 寄存器
```

---

### 7.7 Dalvik

早期 Android 的 Dalvik VM 是经典的：

```text
基于寄存器的虚拟机
```

例如：

```text
add-int v2, v0, v1
```

表示：

```text
v2 = v0 + v1
```

---

## 8. JVM 栈帧结构

每次方法调用，JVM 都会为这次调用创建一个：

```text
栈帧 Stack Frame
```

栈帧可以理解成：

> 一次方法调用的运行时工作空间。

---

### 8.1 栈帧与 JVM 栈

每个 Java 线程都有自己的 JVM 虚拟机栈。

例如：

```text
main()
↓
test()
↓
add()
```

可能形成：

```text
栈顶
┌───────────────┐
│ add() 栈帧     │
├───────────────┤
│ test() 栈帧    │
├───────────────┤
│ main() 栈帧    │
└───────────────┘
栈底
```

方法调用：

```text
创建栈帧 → 入栈
```

方法结束：

```text
栈帧出栈 → 销毁
```

因此：

> 栈帧生命周期约等于一次方法调用的生命周期。

---

### 8.2 栈帧主要结构

可以记成：

```text
栈帧
├── 局部变量表 Local Variables
├── 操作数栈 Operand Stack
├── 动态链接 Dynamic Linking
└── 方法返回相关信息
```

---

## 9. 局部变量表

局部变量表主要保存：

- 方法参数
- 局部变量
- 对象引用
- 实例方法中的 `this`

例如：

```java
static int add(int a, int b) {
    int c = a + b;
    return c;
}
```

局部变量表可能：

```text
slot 0 → a
slot 1 → b
slot 2 → c
```

---

### 9.1 slot

局部变量表通过 `slot` 编号访问。

例如：

```text
iload_0
iload_1
iadd
istore_2
```

含义：

```text
读取 slot 0
读取 slot 1
相加
保存到 slot 2
```

---

### 9.2 实例方法中的 this

例如：

```java
class User {
    void test(int x) {
        int y = 10;
    }
}
```

局部变量表通常：

```text
slot 0 → this
slot 1 → x
slot 2 → y
```

所以实例方法可以粗略理解成：

```text
test(this, x)
```

---

### 9.3 static 方法没有 this

例如：

```java
static void test(int a) {
}
```

局部变量表：

```text
slot 0 → a
```

不会有 `this`。

这也是 static 方法中不能直接使用 `this` 的原因之一。

---

### 9.4 long / double 占两个 slot

在局部变量表中：

```text
int / float / reference 等 → 1 个 slot
long / double              → 2 个连续 slot
```

例如：

```java
static void test(int a, long b, int c) {
}
```

可能：

```text
slot 0 → a
slot 1 + slot 2 → b
slot 3 → c
```

---

## 10. 操作数栈

操作数栈用于：

```text
临时运算
方法调用传参
保存中间计算结果
接收返回值
```

例如：

```java
int c = a + b;
```

字节码：

```text
iload_0
iload_1
iadd
istore_2
```

操作数栈变化：

```text
[]
↓
[a]
↓
[a, b]
↓
[a+b]
↓
[]
```

因此可以简单记：

```text
局部变量表 = 放变量
操作数栈   = 做计算
```

## 11. 方法调用时栈帧之间的数据传递

例如：

```java
int result = add(10, 20);
```

调用前，调用者会把参数压入操作数栈。

随后创建 `add()` 的栈帧。

`add()` 的局部变量表：

```text
slot 0 → 10
slot 1 → 20
```

可以理解为：

```text
调用者操作数栈
↓
方法参数
↓
被调用者局部变量表
```

### 11.1 返回值

例如：

```java
static int add(int a, int b) {
    return a + b;
}
```

最后通过：

```text
ireturn
```

把结果返回给调用者。

调用者再把返回值保存到自己的局部变量中。

## 12. 动态链接

动态链接可以粗略理解为：

> 帮助当前方法从运行时常量池中的符号引用定位到实际要使用的类、字段、方法。

例如：

```java
user.sayHello();
```

class 文件中通常不会简单保存某个固定物理地址，而是保存相关符号信息。

JVM 在运行时需要完成对应解析与链接。

## 13. 方法返回与栈展开

方法正常返回，例如：

```java
return;
return 10;
```

对应字节码可能：

```text
return
ireturn
areturn
```

异常退出时，如果当前方法没有捕获异常：

```text
当前栈帧退出
↓
继续向调用者查找异常处理器
```

这个过程常称：

```text
stack unwinding
栈展开
```

## 14. StackOverflowError

例如：

```java
static void test() {
    test();
}
```

不断递归：

```text
test 栈帧
test 栈帧
test 栈帧
test 栈帧
...
```

会持续占用 JVM 栈空间。

最终可能：

```text
java.lang.StackOverflowError
```

本质：

> 同一个线程中存在过多尚未退出的方法栈帧。

---

## 15. 栈帧是线程私有的

每个线程都有自己的 JVM 栈：

```text
线程 A → JVM Stack A
线程 B → JVM Stack B
```

所以：

```java
void test() {
    int count = 0;
}
```

如果两个线程同时调用：

```java
test();
```

它们各自拥有自己的 `count`。

普通局部变量不会因为多个线程同时调用同一个方法就自动共享。

但是：

```java
class Counter {
    int count;

    void test() {
        count++;
    }
}
```

这里的 `count` 是对象字段。

如果多个线程共享同一个 `Counter` 对象，就可能发生并发竞争。

因此：

```text
局部变量 → 在线程自己的栈帧中，通常不共享
对象字段 → 对象位于堆中，可能被多个线程共享
```

## 16. javap 中的 stack 和 locals

使用：

```bash
javap -c -v Test
```

可能看到：

```text
stack=2, locals=3
```

例如：

```java
static int add(int a, int b) {
    int c = a + b;
    return c;
}
```

其中：

```text
locals=3
```

因为：

```text
slot 0 → a
slot 1 → b
slot 2 → c
```

而：

```text
stack=2
```

是因为计算 `a + b` 时，操作数栈最大同时需要两个值：

```text
[a, b]
```

# 18. 面试级简答

## 18.1 Java 类加载流程

> Java 类加载主要经历加载、验证、准备、解析和初始化。加载阶段把 class 文件读入 JVM；验证阶段检查字节码合法性；准备阶段给静态变量分配内存并设置默认值；解析阶段把符号引用转成直接引用；初始化阶段执行静态变量赋值和静态代码块形成的 `<clinit>`。

---

## 18.2 什么是 Java 原子性

> 原子性是指一个操作或一组操作在并发语义上不可再被观察为中间状态。比如 `count++` 实际包含读取、加一和写回，因此不是原子操作。Java 中可以通过 `synchronized`、Lock 或 Atomic 原子类保证所需的原子性。

---

## 18.3 AtomicInteger 如何实现原子性

> `AtomicInteger` 主要通过 CAS 实现原子更新。CAS 会比较当前值和期望值，只有一致时才执行更新；如果不一致，说明有其他线程修改过数据，通常会重新读取并重试。

---

## 18.4 栈虚拟机和寄存器虚拟机区别

> 栈虚拟机通过操作数栈隐式传递操作数，指令通常更简单；寄存器虚拟机通过寄存器编号显式指定操作数，同样逻辑通常需要更少指令。JVM 字节码是典型的栈式执行模型。

---

## 18.5 Java 栈帧里有什么

> 每次方法调用都会创建一个栈帧，主要包括局部变量表、操作数栈、动态链接和方法返回相关信息。局部变量表保存参数与局部变量，操作数栈负责字节码执行中的临时计算。实例方法的 slot 0 通常保存 `this`。

---
