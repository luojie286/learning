## 1. Java IO

Java IO（Input / Output）用于处理程序与外部数据之间的输入和输出，例如文件、网络、键盘、日志等。

### 1.1 四个核心抽象类

| 类型 | 输入 | 输出 |
|---|---|---|
| 字节流 | `InputStream` | `OutputStream` |
| 字符流 | `Reader` | `Writer` |

### 1.2 字节流

典型类：

```java
FileInputStream
FileOutputStream
```

适合处理：

- 图片
- 视频
- 压缩包
- PDF
- 其他二进制数据

读取文件时：

```java
try (FileInputStream fis = new FileInputStream("a.txt")) {
    byte[] buffer = new byte[1024];
    int len;

    while ((len = fis.read(buffer)) != -1) {
        System.out.println(new String(buffer, 0, len));
    }
}
```

重点：

- `read()` 返回 `-1` 表示读取结束。
- `read(byte[])` 返回本次实际读取的字节数。
- 最后一次读取可能不会填满整个数组，所以应使用 `new String(buffer, 0, len)`。

### 1.3 字符流

典型类：

```java
FileReader
FileWriter
```

主要用于文本数据。

```java
try (FileReader reader = new FileReader("a.txt")) {
    char[] buffer = new char[1024];
    int len;

    while ((len = reader.read(buffer)) != -1) {
        System.out.println(new String(buffer, 0, len));
    }
}
```

简单选择：

```text
文本数据 -> 字符流
二进制数据 -> 字节流
```

### 1.4 转换流

```java
InputStreamReader
OutputStreamWriter
```

作用：

```text
byte <-> char
```

同时可以指定字符编码。

```java
InputStreamReader reader =
        new InputStreamReader(
                new FileInputStream("a.txt"),
                StandardCharsets.UTF_8
        );
```

理解：

```text
编码：char -> byte
解码：byte -> char
```

### 1.5 缓冲流

常见类：

```java
BufferedInputStream
BufferedOutputStream
BufferedReader
BufferedWriter
```

作用：减少频繁访问磁盘或其他 IO 设备，提高效率。

`BufferedReader` 常用：

```java
String line;
while ((line = br.readLine()) != null) {
    System.out.println(line);
}
```

注意：

```text
InputStream.read()      -> -1 表示结束
BufferedReader.readLine() -> null 表示结束
```

### 1.6 装饰器模式

Java IO 经常出现“套娃”：

```java
BufferedReader br =
        new BufferedReader(
                new InputStreamReader(
                        new FileInputStream("a.txt"),
                        StandardCharsets.UTF_8
                )
        );
```

每层增加一种能力：

```text
FileInputStream    -> 从文件读取字节
InputStreamReader  -> 字节转字符
BufferedReader     -> 缓冲 + readLine()
```

### 1.7 try-with-resources

推荐：

```java
try (FileInputStream fis = new FileInputStream("a.txt")) {
    // 使用资源
}
```

离开 `try` 后自动调用 `close()`。

适用于实现了 `AutoCloseable` 的资源。

### 当前掌握要求

需要理解：

- 字节流 / 字符流的区别
- 输入 / 输出
- `read()` / `write()`
- 缓冲流
- 转换流
- try-with-resources

暂时不用背全部 IO API。

### 值得手写

建议至少亲手写一次：

1. `FileInputStream + byte[]` 复制文件
2. `BufferedReader.readLine()` 按行读取文本
3. `try-with-resources`

## 2. Java 日期时间 API

现代 Java 日期时间 API 位于：

```java
java.time
```

常见类：

```java
LocalDate
LocalTime
LocalDateTime
Instant
Duration
Period
DateTimeFormatter
```

典型用途：

- 用户注册时间
- 订单创建时间
- 会员过期时间
- 定时任务
- 日志时间
- 数据库时间字段
- 时间比较和时间计算

例如：

```java
LocalDate today = LocalDate.now();
LocalDate sevenDaysLater = today.plusDays(7);
```

比较：

```java
today.isAfter(expireDate);
today.isBefore(expireDate);
```

格式化：

```java
DateTimeFormatter formatter =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
```

### 当前掌握要求

这一块不需要系统钻研。

知道：

```text
LocalDate       -> 日期
LocalTime       -> 时间
LocalDateTime   -> 日期 + 时间
DateTimeFormatter -> 格式化
```

即可。

复杂 API 用到时查文档。

新代码优先使用 `java.time`，不必重点学习旧的 `Date` / `Calendar`。

### 值得手写

只需简单写一次：

```java
LocalDate.now()
LocalDateTime.now()
plusDays()
isAfter()
DateTimeFormatter
```

之后项目中用到再查 API。

## 3. JUnit 单元测试

单元测试用于自动验证代码是否符合预期。

核心流程：

```text
准备数据
  ↓
调用被测试方法
  ↓
得到实际结果
  ↓
断言
  ↓
判断是否符合预期
```

### 3.1 `@Test`

```java
@Test
void testAdd() {
    assertEquals(5, 2 + 3);
}
```

`@Test` 告诉 JUnit：这是一个测试方法。

### 3.2 断言

常见：

```java
assertEquals(expected, actual);
assertTrue(condition);
assertFalse(condition);
assertNull(obj);
assertNotNull(obj);
```

例如：

```java
assertEquals(5, calculator.add(2, 3));
```

### 3.3 Fixture

Fixture 指测试前后准备或清理环境。

```java
@BeforeEach
void setUp() {
    calculator = new Calculator();
}
```

```java
@AfterEach
void tearDown() {
    // 清理资源
}
```

执行关系：

```text
@BeforeEach
↓
某个 @Test
↓
@AfterEach
```

每个测试方法都会经历一次。

### 3.4 异常测试

```java
assertThrows(
        IllegalArgumentException.class,
        () -> divide(10, 0)
);
```

这里“抛异常”本身是预期结果，因此测试可以通过。

### 3.5 条件测试

例如：

```java
@EnabledOnOs(OS.WINDOWS)
```

表示满足指定条件才运行。

当前了解即可。

### 3.6 参数化测试

同一测试逻辑使用多组输入：

```java
@ParameterizedTest
@ValueSource(ints = {2, 4, 6, 8})
void testEven(int n) {
    assertTrue(n % 2 == 0);
}
```

### 当前掌握要求

重点掌握：

```java
@Test
@BeforeEach
@AfterEach
assertEquals()
assertTrue()
assertFalse()
assertThrows()
```

参数化测试知道基本用法即可。

### 值得手写

建议自己写一个简单的 `Calculator`：

```java
add()
sub()
divide()
```

然后手写对应测试：

- 正常结果测试
- 异常测试
- `@BeforeEach`

JUnit 比日期 API 更值得现在亲手练习。

## 4. Java 正则表达式

正则表达式用于描述字符串匹配规则。

例如：

```java
"123".matches("\\d{3}")
```

表示：字符串必须恰好是 3 个数字。

### 4.1 常见规则

```text
\d      数字
\w      字母、数字、下划线
\s      空白字符
.       任意字符

*       0 次或多次
+       1 次或多次
?       0 次或 1 次

{3}     恰好 3 次
{2,5}   2~5 次

[abc]   a、b、c 中任意一个
[a-z]   小写字母
```

Java 字符串中反斜杠本身需要转义：

```java
"\\d"
```

而不是：

```java
"\d"
```

### 4.2 分组匹配

```regex
(\d{4})-(\d{2})-(\d{2})
```

匹配：

```text
2026-09-14
```

三个分组：

```text
2026
09
14
```

括号 `()` 用于把一部分规则作为一个整体，并可捕获该部分结果。

### 4.3 贪婪和非贪婪

```regex
.*
```

尽可能多匹配，属于贪婪。

```regex
.*?
```

尽可能少匹配，属于非贪婪。

当前知道区别即可。

### 4.4 搜索和替换

```java
String s = "abc123def456";
String result = s.replaceAll("\\d+", "#");
```

结果：

```text
abc#def#
```

### 当前掌握要求

重点：

- 基本匹配规则
- Java 中 `\\` 转义
- `matches()`
- `replaceAll()`
- 分组概念

复杂正则用到再查。

### 值得手写

手写 3 个小例子即可：

1. 判断是否全为数字
2. 匹配简单日期格式
3. 用 `replaceAll()` 替换连续数字

不需要背复杂邮箱、URL 正则。

## 5. 加密与安全

这一章 API 不需要全背，但概念比较重要。

### 5.1 编码

典型：

```text
Base64
```

Base64 只是编码，不是加密。

```text
hello
↓
aGVsbG8=
```

别人可以直接解码恢复原文。

---

### 5.2 哈希

典型：

```text
SHA-256
SHA-512
```

哈希用于产生数据“指纹”。

```text
任意长度数据
↓
固定长度摘要
```

特点：

- 很难从哈希值反推出原文
- 原文轻微变化通常导致结果明显变化
- 用于完整性校验、数字签名等

MD5、SHA-1 已不适合安全相关用途。

Java：

```java
MessageDigest md =
        MessageDigest.getInstance("SHA-256");
```

---

### 5.3 HMAC

HMAC 可以理解为：

```text
数据 + 密钥
↓
HMAC
```

主要用于验证：

- 数据有没有被篡改
- 对方是否持有共享密钥

常见场景：

- API 签名
- Webhook
- 支付接口

---

### 5.4 对称加密

典型：

```text
AES
```

特点：

```text
同一把密钥
负责加密
也负责解密
```

优点：

- 快
- 适合大量数据

主要问题：

- 如何安全交换密钥

---

### 5.5 非对称密码学

使用：

```text
公钥
私钥
```

基本概念：

```text
公钥 -> 可以公开
私钥 -> 必须自己保存
```

典型体系：

```text
RSA
ECC
```

非对称密码体系可以用于加密、签名或密钥协商等场景，具体取决于所使用的算法。

---

### 5.6 数字签名

核心记忆：

```text
私钥签名
公钥验证
```

目的：

- 验证数据是否被篡改
- 验证签名者是否持有对应私钥

区别：

```text
加密 -> 解决“别人能不能看”
签名 -> 解决“是不是你发的、有没有被改”
```

---

### 5.7 密码存储

用户密码不应该：

```text
明文保存
```

也不推荐直接：

```text
SHA-256(password)
```

通常使用专门的密码哈希 / KDF：

```text
bcrypt
Argon2
PBKDF2
scrypt
```

并结合随机 `salt`。

基本过程：

```text
password + salt
↓
密码哈希算法
↓
hash
```

数据库保存哈希结果，而不是保存可以直接还原的密码。

---

### 5.8 Salt

如果两个用户密码都为：

```text
123456
```

使用不同随机 Salt 后：

```text
123456 + saltA
123456 + saltB
```

产生不同哈希值。

作用之一是防止相同密码直接表现为相同哈希，并增强对预计算攻击的抵抗能力。

---

### 5.9 密钥交换

典型：

```text
Diffie-Hellman
ECDH
```

作用：

双方可以通过公开网络协商出共享秘密，而不需要直接发送最终秘密本身。

目前理解作用即可，不需要学习数学推导。

---

### 5.10 数字证书

数字证书用于证明：

```text
“这个公钥属于谁”
```

证书通常包含：

- 域名或主体信息
- 公钥
- 有效期
- 颁发机构
- CA 的数字签名

HTTPS / TLS 会大量使用证书机制。

## 6. `InterruptedException`

正确类名：

```java
InterruptedException
```

主要发生在线程处于阻塞 / 等待状态时，被其他线程调用 `interrupt()` 中断。

常见可能抛出 `InterruptedException` 的操作：

```java
Thread.sleep()
thread.join()
object.wait()
```

例如：

```java
try {
    Thread.sleep(5000);
} catch (InterruptedException e) {
    System.out.println("线程被中断");
}
```

另一个线程：

```java
thread.interrupt();
```

如果目标线程正在 `sleep()`，就可能抛出 `InterruptedException`。

核心理解：

```text
interrupt()
不是强制杀死线程
而是向线程发送“中断请求”
```

线程收到中断后，应根据程序逻辑决定退出、恢复中断状态、清理资源等。

### 当前掌握要求

记住一句：

> `InterruptedException` 通常表示线程在 `sleep / wait / join` 等阻塞等待过程中收到了中断请求。

### 值得手写

多线程学习时建议亲手写一次：

1. 一个线程 `sleep(5000)`
2. 主线程调用它的 `interrupt()`
3. 在子线程捕获 `InterruptedException`

这个例子值得自己运行观察。
