# 三、CAS

CAS 全称：

```text
Compare And Swap
比较并交换
```

核心思想：

> 修改数据之前，先检查当前值是否仍然等于自己之前读取到的值。

逻辑近似：

```java
if (当前值 == 预期值) {
    当前值 = 新值;
}
```

例如：

```text
线程 A 读取 count = 10
线程 B 读取 count = 10

A：
期望值 = 10
当前仍为 10
修改为 11
成功

B：
期望值 = 10
发现现在已经是 11
修改失败
重新读取
```

与 `synchronized` 的区别：

```text
synchronized：
先加锁，只允许一个线程操作

CAS：
不先加锁，尝试修改，失败后重试
```

CAS 常被归为一种乐观并发控制思想。

### ABA 问题

如果一个值经历：

```text
A → B → A
```

CAS 只看到：

```text
之前是 A
现在还是 A
```

可能认为它没有变化。

当前阶段知道 ABA 问题存在即可，不必深入。

```java

```

例如：


含义：

```text
如果 count 当前仍然是 10
就把它改成 20
```

# 五、ReentrantLock

`ReentrantLock` 是 JUC 中的重要锁实现。

基本写法：

```java
Lock lock = new ReentrantLock();

lock.lock();

try {
    count++;
} finally {
    lock.unlock();
}
```

注意：

> `unlock()` 最好放在 `finally` 中，保证发生异常时仍然能够释放锁。

### synchronized 与 ReentrantLock

`synchronized`：

```java
synchronized (obj) {
    // 临界区
}
```

特点：

- 语法简单
- JVM 自动释放锁
- 日常开发中很常用

`ReentrantLock`：

```java
lock.lock();

try {
    // 临界区
} finally {
    lock.unlock();
}
```

特点：

- 需要手动释放锁
- 功能更加灵活
- 支持 `tryLock()`
- 支持可中断等待等能力

例如：

```java
if (lock.tryLock()) {
    try {
        // 操作
    } finally {
        lock.unlock();
    }
}
```

`tryLock()` 的意思是：

```text
能拿到锁 → 执行
拿不到锁 → 不一直等待
```

# 七、生产者-消费者模型

这是理解 `BlockingQueue` 的关键。

可以想象：

```text
生产者线程
   ↓
[ 任务1 任务2 任务3 ]
   ↓
消费者线程
```

生产者负责：

```text
生成数据 / 任务
```

消费者负责：

```text
处理数据 / 任务
```

队列负责：

```text
暂存生产出来、还没来得及消费的内容
```

### 为什么需要队列

如果没有队列：

```text
生产者生成任务
↓
必须马上交给消费者
↓
消费者处理完
↓
生产者才能继续
```

耦合很强。

有了队列以后：

```text
生产者
→ 只负责生产并放入队列

消费者
→ 只负责从队列获取并处理
```

生产者和消费者因此解耦。

# 八、BlockingQueue

`BlockingQueue`：

```text
Blocking = 阻塞
Queue = 队列
```

它的核心价值：

1. 保证队列操作的线程安全
2. 队列空时，可以让消费者等待
3. 队列满时，可以让生产者等待
4. 减少自己使用 `wait / notify` 的复杂度

例如：

```java
BlockingQueue<Integer> queue =
        new ArrayBlockingQueue<>(5);
```

---

## 1. put()

```java
queue.put(x);
```

如果队列没有满：

```text
正常放入
```

如果队列满：

```text
当前生产者线程阻塞
等待队列出现空位
```

---

## 2. take()

```java
int x = queue.take();
```

如果队列有数据：

```text
正常取出
```

如果队列为空：

```text
消费者线程阻塞
等待新数据进入
```

---

## 3. offer()

```java
queue.offer(x);
```

如果队列满：

```text
不阻塞
直接返回 false
```

---

## 4. poll()

```java
queue.poll();
```

如果队列为空：

```text
不阻塞
返回 null
```

因此可以简记：

```text
put / take
→ 会等待

offer / poll
→ 默认不等待
```

---

# 九、BlockingQueue 示例

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

public class Demo {

    public static void main(String[] args) {

        BlockingQueue<Integer> queue =
                new ArrayBlockingQueue<>(5);

        Thread producer = new Thread(() -> {
            try {
                for (int i = 1; i <= 10; i++) {
                    queue.put(i);
                    System.out.println("生产：" + i);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        Thread consumer = new Thread(() -> {
            try {
                for (int i = 1; i <= 10; i++) {
                    int value = queue.take();
                    System.out.println("消费：" + value);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        producer.start();
        consumer.start();
    }
}
```

核心关注：

```java
queue.put(i);
```

生产。

```java
queue.take();
```

消费。

# 十、wait / notify 与 BlockingQueue 的关系

如果不用 BlockingQueue，自己实现生产者消费者通常需要：

```text
synchronized
wait()
notify() / notifyAll()
```

例如：

```text
消费者发现没有数据
→ wait()

生产者放入数据
→ notify()
```

反过来：

```text
生产者发现队列已满
→ wait()

消费者取走数据
→ notify()
```

自己控制这些细节很容易出错。

所以可以理解成：

```text
wait / notify
→ 理解底层线程协作思想

BlockingQueue
→ 已封装好的高级并发工具
```

当前学习阶段：

> `wait / notify` 理解原理，`BlockingQueue` 要会用。

# 十一、BlockingQueue 在线程池中的作用

线程池本质上也包含生产者-消费者思想。

例如：

```java
executor.execute(task);
```

提交任务的线程可以看成：

```text
生产者
```

线程池中的工作线程可以看成：

```text
消费者
```

中间通常存在：

```text
BlockingQueue<Runnable>
```

结构：

```text
提交任务
   ↓
BlockingQueue
   ↓
工作线程1
工作线程2
工作线程3
```

所以 `ThreadPoolExecutor` 中的重要参数之一就是：

```java
BlockingQueue<Runnable> workQueue
```

# 十二、ThreadPoolExecutor

线程池避免：

```text
每来一个任务
→ new Thread()
```

带来的线程创建和销毁开销。

基本思想：

```text
提前准备工作线程
任务来了先提交
线程从任务队列中不断取任务执行
```

核心构造参数：

```java
new ThreadPoolExecutor(
        corePoolSize,
        maximumPoolSize,
        keepAliveTime,
        unit,
        workQueue,
        threadFactory,
        handler
);
```

### 线程池任务处理流程

假设：

```text
core = 2
max = 4
queue = 3
```

任务持续到来：

```text
任务1 → 核心线程1
任务2 → 核心线程2

任务3 → 队列
任务4 → 队列
任务5 → 队列

任务6 → 创建额外线程3
任务7 → 创建额外线程4

任务8 → 触发拒绝策略
```

记住顺序：

```text
核心线程
↓
任务队列
↓
非核心线程
↓
拒绝策略
```

### 常见拒绝策略

```java
AbortPolicy
CallerRunsPolicy
DiscardPolicy
DiscardOldestPolicy
```

重点：

```text
AbortPolicy
→ 直接抛异常

CallerRunsPolicy
→ 由提交任务的线程自己执行任务
```

# 十三、CompletableFuture

# 十九、TCP 最简单示例

## 服务端

```java
import java.io.*;
import java.net.*;

public class Server {

    public static void main(String[] args) throws Exception {

        ServerSocket serverSocket =
                new ServerSocket(9999);

        System.out.println("服务器启动");

        Socket socket = serverSocket.accept();

        BufferedReader reader =
                new BufferedReader(
                        new InputStreamReader(
                                socket.getInputStream()
                        )
                );

        String message = reader.readLine();

        System.out.println("客户端说：" + message);

        socket.close();
        serverSocket.close();
    }
}
```

---

## 客户端

```java
import java.io.*;
import java.net.*;

public class Client {

    public static void main(String[] args) throws Exception {

        Socket socket =
                new Socket("127.0.0.1", 9999);

        PrintWriter writer =
                new PrintWriter(
                        socket.getOutputStream(),
                        true
                );

        writer.println("hello");

        socket.close();
    }
}
```

运行顺序：

```text
先启动 Server

Server：
accept()
↓
等待

再启动 Client

Client：
连接服务器
↓
发送 hello

Server：
收到 hello
```

# 二十二、为什么网络服务器需要多线程

如果服务器只用一个线程处理：

```text
客户端 A
↓
服务器处理 A 很久

客户端 B
↓
只能继续等待
```

传统思路：

```java
while (true) {

    Socket socket = serverSocket.accept();

    new Thread(() -> {
        handle(socket);
    }).start();
}
```

变成：

```text
客户端 A → 线程 A
客户端 B → 线程 B
客户端 C → 线程 C
```

这就是：

> 多线程和网络编程结合的典型场景。

# 三十、本次学习重点总结

本次聊天真正需要记住的核心：

```text
BlockingQueue
= 线程安全队列
+ 队列满时生产者可阻塞
+ 队列空时消费者可阻塞
```

```text
线程池
= 工作线程
+ BlockingQueue
+ 任务调度与拒绝策略
```

```text
Socket
= Java 对网络连接的封装
```

```text
ServerSocket.accept()
= 等待客户端建立 TCP 连接
```

```text
Socket.getInputStream()
= 从网络读数据

Socket.getOutputStream()
= 向网络写数据
```

最终可以把目前的知识连接起来：

```text
Java IO
   ↓
Socket 网络 IO
   ↓
多个客户端
   ↓
多线程
   ↓
线程池
   ↓
BlockingQueue
```

这条链路是后续学习 Java 后端非常重要的一条基础主线。
