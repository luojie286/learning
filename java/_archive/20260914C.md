# 20260914C 学习笔记：线程、进程与锁

## 1. 线程的概念

线程（Thread）是**进程中的一个执行流，也是 CPU 调度和执行的基本单位**。

可以把进程和线程理解为：

- **进程**：资源容器
- **线程**：真正执行代码的单位

一个进程至少包含一个线程，也可以包含多个线程。

```text
进程
├── 线程1
├── 线程2
└── 线程3
```

同一进程中的多个线程可以并发执行，甚至可以分别运行在多个 CPU 核心上。

---

## 2. 线程与进程的关系

进程通常拥有：

- 独立的虚拟地址空间
- 代码段
- 数据段
- 堆
- 打开的文件
- 网络连接等系统资源

同一进程中的线程会共享这些资源。

### 线程共享的内容

- 代码段
- 数据段
- 堆
- 全局变量
- 打开的文件
- 进程地址空间

### 每个线程独有的内容

- 程序计数器 PC
- 寄存器
- 栈
- 线程运行状态

因此可以记住：

> 进程负责资源，线程负责执行。

---

## 3. PCB 与 TCB

PCB（Process Control Block）用于描述一个进程，保存：

- 进程 ID
- 进程状态
- 地址空间
- 资源信息
- 打开的文件等

线程也需要自己的控制信息，一般使用 TCB（Thread Control Block），保存：

- 线程 ID
- 线程状态
- 程序计数器
- 寄存器
- 栈指针
- 调度信息

可以简单理解：

```text
PCB → 描述进程
TCB → 描述线程
```

---

## 4. 为什么需要锁

同一进程中的线程会共享数据。

例如：

```java
int count = 0;
```

两个线程同时执行：

```java
count++;
```

`count++` 并不是一个不可分割的操作，大致可以拆成：

```text
1. 读取 count
2. count + 1
3. 写回 count
```

如果两个线程交叉执行：

```text
线程A：读取 count = 0
线程B：读取 count = 0
线程A：写回 1
线程B：写回 1
```

最终结果可能是：

```text
count = 1
```

而不是预期的：

```text
count = 2
```

这种问题称为：

> **竞态条件（Race Condition）**

---

## 5. 锁的核心概念

锁（Lock）的目的，是：

> **控制多个线程对共享资源的并发访问。**

最简单的理解：

> 某段受保护的代码，同一时刻只允许一个线程执行。

例如：

```java
synchronized (lock) {
    count++;
}
```

线程要进入这段代码，必须先获得 `lock` 对应的锁。

如果线程 A 已经获得：

```text
线程A：进入临界区
线程B：等待
```

当 A 退出并释放锁后，B 才有机会继续执行。

---

## 6. 什么是“拿到锁”

“拿到锁”并不是线程真的拿到了一个实体物品。

它表示：

> **线程获得了执行某段受保护代码的资格。**

例如：

```java
synchronized (lock) {
    count++;
}
```

可以理解为：

```text
线程执行到 synchronized(lock)
↓
尝试获得 lock 的所有权
↓
成功
↓
进入临界区
```

因此下面这些说法基本表达同一个意思：

- 获取锁
- 拿到锁
- 持有锁
- 占有锁

核心都是：

> 当前线程拥有这把锁，因此可以进入对应的临界区。

---

## 7. 什么是临界区

临界区（Critical Section）是：

> **访问共享资源，并且可能产生线程安全问题的一段代码。**

例如：

```java
count++;
```

如果 `count` 会被多个线程同时访问，那么这里就是典型临界区。

加锁通常是为了保护临界区，而不是把整个程序都锁住。

---

## 8. 为什么必须使用同一把锁

假设：

```java
Object lock1 = new Object();
Object lock2 = new Object();
```

线程 A：

```java
synchronized (lock1) {
    count++;
}
```

线程 B：

```java
synchronized (lock2) {
    count++;
}
```

此时并不能实现互斥，因为：

```text
A 竞争 lock1
B 竞争 lock2
```

它们使用的是两把不同的锁，因此仍然可能同时执行 `count++`。

真正应该是多个线程执行同一段代码，并竞争同一把锁：

```java
class Counter {
    int count = 0;
    Object lock = new Object();

    void add() {
        synchronized (lock) {
            count++;
        }
    }
}
```

多个线程都调用：

```java
counter.add();
```

此时才会形成真正的互斥。

所以要记住：

> **互斥是否成立，关键不在于代码写了几份，而在于多个线程竞争的是不是同一把锁。**

---

## 9. synchronized

Java 中最基础的加锁方式是：

```java
synchronized
```

### 代码块写法

```java
synchronized (lock) {
    // 临界区
}
```

### 实例方法写法

```java
public synchronized void add() {
    count++;
}
```

普通 `synchronized` 实例方法使用的是：

```text
this
```

作为锁。

也就是大致相当于：

```java
public void add() {
    synchronized (this) {
        count++;
    }
}
```

### static synchronized

```java
public static synchronized void add() {
}
```

锁的是对应的 `Class` 对象。

例如：

```java
synchronized (Counter.class) {
}
```

---

## 10. Lock 与 ReentrantLock

Java 还提供显式锁：

```java
Lock lock = new ReentrantLock();
```

使用方式：

```java
lock.lock();

try {
    count++;
} finally {
    lock.unlock();
}
```

通常必须把 `unlock()` 写在 `finally` 中，因为即使临界区发生异常，也要保证锁能够释放。

当前阶段可以先简单记：

```text
synchronized
→ 使用简单
→ 自动释放锁

Lock / ReentrantLock
→ 手动 lock / unlock
→ 使用更灵活
```

---

## 11. 死锁

死锁（Deadlock）是多个线程互相等待对方释放资源，导致所有线程都无法继续执行。

经典情况：

```text
线程A：
先拿 lock1
再尝试拿 lock2

线程B：
先拿 lock2
再尝试拿 lock1
```

最终：

```text
线程A：持有 lock1，等待 lock2
线程B：持有 lock2，等待 lock1
```

于是：

```text
A 等 B
B 等 A
```

两边都无法继续。

---

## 12. 线程是不是必须同时拿两把锁才能运行

不是。

线程本身并不要求必须获得两把锁才能运行。

只有当某段代码本身设计成嵌套获取多把锁时，线程才可能需要同时持有多把锁。

例如：

```java
synchronized (lock1) {
    synchronized (lock2) {
        doSomething();
    }
}
```

执行到最里面时，线程同时持有：

```text
lock1 + lock2
```

所以死锁的本质不是：

> 线程天生需要两把锁

而是：

> 某些代码路径会让线程在已经持有一把锁时继续等待另一把锁。

如果多个线程之间形成循环等待，就可能产生死锁。

---

## 13. 整体逻辑总结

把线程和锁连起来，可以理解为：

```text
同一进程中的线程
↓
共享堆、全局变量等资源
↓
多个线程可能同时修改共享数据
↓
产生竞态条件
↓
划分临界区
↓
使用锁保证互斥
```

核心关系：

```text
共享资源
   ↓
并发访问
   ↓
线程安全问题
   ↓
临界区
   ↓
锁
   ↓
互斥执行
```

---

## 14. 必须掌握的结论

### 进程与线程

> 进程是资源分配和保护的重要单位，线程是 CPU 调度和执行的基本单位。

### 锁

> 锁用于控制多个线程对共享资源的并发访问。

### 拿到锁

> 拿到锁 = 获得进入对应临界区执行代码的资格。

### 临界区

> 临界区 = 访问共享资源且可能产生线程安全问题的代码区域。

### 同一把锁

> 多个线程想要实现互斥，必须竞争同一把锁。

### 死锁

> 一个线程持有部分锁并等待其他锁，多个线程之间形成循环等待时，可能发生死锁。

## 15. 手写练习建议

### 必须手写

写一个计数器：

```java
class Counter {

    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}
```

创建两个线程，每个线程执行：

```java
10000 次 increment()
```

分别测试：

1. 不加 `synchronized`
2. 加 `synchronized`

观察最终结果的差别。

### 建议手写一次

手写：

```java
ReentrantLock
lock()
try
finally
unlock()
```

理解显式锁的基本使用方法。

再手写一次经典死锁：

```java
synchronized (lock1) {
    synchronized (lock2) {
    }
}
```

另一个线程反过来：

```java
synchronized (lock2) {
    synchronized (lock1) {
    }
}
```

用于直观理解死锁。
