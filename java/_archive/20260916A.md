# 20260916A：Java 线程池、Future 与异步编程学习笔记

## 一、线程池是什么

线程池（Thread Pool）的核心思想是：

> **提前准备一批可复用的工作线程，任务到来时把任务交给线程池，而不是每次都重新创建线程。**

如果每来一个任务就执行：

```java
new Thread(() -> {
    System.out.println("处理任务");
}).start();
```

那么任务很多时，就会频繁创建和销毁线程。

线程的创建和销毁都有开销，而且线程过多会造成：

- 内存占用增加
- 上下文切换频繁
- CPU 调度压力增加
- 极端情况下可能导致系统资源耗尽

线程池的执行模式可以理解为：

```text
任务1 ─┐
任务2 ─┼──> 任务队列 ───> 工作线程1
任务3 ─┤                 工作线程2
任务4 ─┘                 工作线程3
```

工作线程完成一个任务以后不会马上销毁，而是继续处理后续任务。

因此：

> **线程池最核心的价值是线程复用 + 统一管理线程资源。**

---

## 二、为什么需要线程池

线程池主要解决三个问题。

### 1. 减少线程创建和销毁的开销

普通方式：

```text
任务来了
↓
创建线程
↓
执行
↓
销毁线程
```

线程池方式：

```text
线程提前存在
↓
任务来了
↓
线程执行
↓
线程保留
↓
继续处理下一个任务
```

---

### 2. 限制线程数量

如果同时来了 10000 个任务：

```text
10000 个任务
↓
10000 个 Thread
```

可能给系统造成很大压力。

线程池可以限制：

```text
10000 个任务
↓
固定数量的工作线程
↓
其他任务进入队列等待
```

---

### 3. 统一管理线程

线程池可以统一处理：

- 线程创建
- 线程复用
- 任务排队
- 最大线程数
- 空闲线程回收
- 拒绝策略
- 线程工厂
- 任务调度

---

# 三、ExecutorService

Java 中可以通过 `ExecutorService` 使用线程池。

例如：

```java
ExecutorService pool = Executors.newFixedThreadPool(3);

pool.submit(() -> {
    System.out.println(Thread.currentThread().getName());
});

pool.submit(() -> {
    System.out.println(Thread.currentThread().getName());
});

pool.shutdown();
```

这里：

```java
Executors.newFixedThreadPool(3);
```

表示创建一个固定大小为 3 的线程池。

而：

```java
pool.submit(task);
```

表示：

> **把任务提交给线程池。**

注意：

```text
submit() ≠ 创建新线程
```

线程到底由谁执行，由线程池决定。

---

## 四、从“管理线程”到“提交任务”

以前写：

```java
Thread thread = new Thread(task);
thread.start();
```

本质上是：

```text
自己创建线程
自己启动线程
自己管理线程
```

使用线程池以后：

```java
pool.submit(task);
```

变成：

```text
自己只负责任务
线程池负责线程管理
```

这是 Java 并发编程里一个很重要的思想变化：

> **将“任务”和“线程”分离。**

---

# 五、BlockingQueue 与线程池的关系

线程池内部通常会维护一个任务队列。

可以粗略理解为：

```text
提交任务的线程
     ↓
BlockingQueue
     ↓
线程池工作线程
```

因此线程池本质上和生产者—消费者模型非常相似：

```text
生产者：提交任务
消费者：线程池中的 Worker 线程
缓冲区：BlockingQueue
```

所以 `BlockingQueue` 是理解线程池的重要基础。

# 六、ThreadPoolExecutor

实际开发中，Java 线程池最核心的实现类是：

```java
ThreadPoolExecutor
```

其常见关键参数包括：

```text
corePoolSize
maximumPoolSize
keepAliveTime
workQueue
threadFactory
handler
```

含义：

| 参数 | 含义 |
|---|---|
| corePoolSize | 核心线程数 |
| maximumPoolSize | 最大线程数 |
| keepAliveTime | 非核心空闲线程存活时间 |
| workQueue | 任务队列 |
| threadFactory | 创建线程的方式 |
| handler | 拒绝策略 |

## 七、ThreadPoolExecutor 的基本执行流程

假设：

```text
核心线程数 = 2
最大线程数 = 5
任务队列容量 = 10
```

任务到来时，大致按照下面的顺序处理：

```text
任务到来
↓
核心线程是否达到 corePoolSize？
↓否
创建核心线程执行
↓是
任务队列是否已满？
↓否
进入任务队列
↓是
当前线程数是否小于 maximumPoolSize？
↓是
创建新线程执行
↓否
执行拒绝策略
```

需要记住：

> **通常是先用核心线程，再入队，队列满了以后才继续扩容线程。**

# 八、Future 是什么

`Future` 是 Java 中表示：

> **一个未来可能才会得到的异步任务结果。**

例如：

```java
ExecutorService pool = Executors.newFixedThreadPool(2);

Future<Integer> future = pool.submit(() -> {
    Thread.sleep(2000);
    return 100;
});
```

这里不会立刻拿到 `100`。

而是先得到：

```java
Future<Integer>
```

可以把它理解为：

> **未来获取 Integer 结果的凭证。**

---

# 九、Future.get()

获取异步任务结果：

```java
Integer result = future.get();
```

它的行为：

```text
任务已经完成
↓
立即返回结果
```

如果任务尚未完成：

```text
当前线程调用 get()
↓
阻塞等待
↓
任务完成
↓
返回结果
```

所以：

> `submit()` 本身通常不会等待任务完成，但 `future.get()` 可能会阻塞。

---

# 十、Future 常用方法

### 1. get()

```java
future.get();
```

获取结果。

任务未完成时会阻塞。

---

### 2. isDone()

```java
future.isDone();
```

判断任务是否已经完成。

---

### 3. cancel()

```java
future.cancel(true);
```

尝试取消任务。

其中 `true` 表示：

> 如果任务正在运行，允许通过中断尝试取消它。

注意：这只是“尝试取消”，并不保证任务一定终止。

---

### 4. isCancelled()

```java
future.isCancelled();
```

判断任务是否已经被取消。

# 十一、Runnable 和 Callable

## Runnable

```java
Runnable task = () -> {
    System.out.println("hello");
};
```

特点：

```text
没有返回值
```

---

## Callable

```java
Callable<Integer> task = () -> {
    return 100;
};
```

特点：

```text
可以返回结果
可以抛出异常
```

---

## Callable + Future

典型组合：

```java
Callable<Integer> task = () -> {
    return 1 + 2;
};

Future<Integer> future = pool.submit(task);

Integer result = future.get();
```

关系：

```text
Callable
↓
定义一个有返回值的任务
↓
submit()
↓
Future
↓
get()
↓
拿到最终结果
```

一句话记忆：

> **Callable 定义任务，Future 保存未来结果。**

---

# 十二、什么是同步

同步执行：

```java
int result = calculate();
System.out.println(result);
```

执行流程：

```text
调用 calculate()
↓
当前线程等待
↓
calculate() 执行完成
↓
获取结果
↓
继续执行
```

也就是说：

> **必须等待当前操作完成，才能继续往下执行。**

---

# 十三、什么是异步

异步编程的核心是：

> **任务交给其他执行者处理，当前线程不必立即等待结果，可以先继续处理其他事情。**

例如：

```java
Future<Integer> future = pool.submit(() -> calculate());

System.out.println("先做其他事情");

Integer result = future.get();
```

执行过程：

```text
主线程                        工作线程

submit(task)
   ├────────────────────────→ calculate()
   │
继续做其他事情
   │
需要结果时
future.get()
```

因此异步并不是：

```text
永远不等待
```

而是：

> **将等待推迟到真正需要结果的时候。**

---

# 十四、为什么后端需要异步

例如一个请求需要执行：

```text
查询数据库：500 ms
调用远程接口：1000 ms
读取文件：300 ms
```

如果三个任务互不依赖，同步执行大约需要：

```text
500 + 1000 + 300 = 1800 ms
```

如果可以并行执行：

```text
数据库查询 ─────────┐
远程接口 ───────────┼──> 汇总结果
文件读取 ───────────┘
```

理论总耗时会更接近最慢的任务：

```text
≈ 1000 ms
```

实际耗时还会受到线程调度、IO、网络等因素影响。

# 十五、最原始的异步方式：Thread

```java
new Thread(() -> {
    System.out.println("异步任务");
}).start();

System.out.println("主线程继续执行");
```

两个线程会并发运行。

但实际后端开发一般不推荐大量直接：

```java
new Thread(...)
```

因为不方便统一控制线程数量和生命周期。

所以通常使用：

```text
线程池 + 任务
```

# 十六、ExecutorService + Future 的异步模型

基础异步模型：

```text
ExecutorService
+
Callable
+
Future
```

例如：

```java
ExecutorService pool = Executors.newFixedThreadPool(2);

Future<Integer> future = pool.submit(() -> {
    Thread.sleep(2000);
    return 100;
});

System.out.println("主线程继续工作");

Integer result = future.get();

System.out.println(result);

pool.shutdown();
```

# 十七、Future 的局限

虽然 `Future` 可以表示异步结果，但使用起来比较被动。

典型代码：

```java
Future<Integer> future = pool.submit(task);

Integer result = future.get();
```

问题在于：

```text
get()
↓
如果没完成
↓
当前线程阻塞
```

如果任务之间存在复杂依赖：

```text
任务 A 完成
↓
处理结果
↓
再执行任务 B
↓
任务 B 完成
↓
再执行任务 C
```

只使用 `Future` 会比较麻烦。

于是 Java 8 提供了：

```java
CompletableFuture
```

---

# 十八、CompletableFuture

`CompletableFuture` 是 Java 异步编程中非常重要的类。

它可以：

- 执行异步任务
- 获取异步结果
- 串联多个任务
- 合并多个异步任务
- 处理异常
- 注册任务完成后的回调

最重要的区别：

> **Future 更像“以后主动来拿结果”，CompletableFuture 更像“结果完成以后自动继续执行下一步”。**

---

# 十九、runAsync()

没有返回值的异步任务：

```java
CompletableFuture.runAsync(() -> {
    System.out.println("异步执行");
});
```

对应概念：

```text
Runnable
```

特点：

```text
异步执行
无返回值
```

---

# 二十、supplyAsync()

需要返回值时：

```java
CompletableFuture<Integer> future =
        CompletableFuture.supplyAsync(() -> {
            return 100;
        });
```

特点：

```text
异步执行
有返回值
```

可以把它理解成类似：

```text
Callable
```

---

# 二十一、thenApply()

`thenApply()` 用于：

> **接收前一个任务的结果，并生成一个新的结果。**

例如：

```java
CompletableFuture<Integer> future =
        CompletableFuture.supplyAsync(() -> 10);

CompletableFuture<Integer> future2 =
        future.thenApply(x -> x * 2);
```

执行流程：

```text
10
↓
thenApply
↓
10 * 2
↓
20
```

所以：

```text
thenApply
有输入
有输出
```

---

# 二十二、thenAccept()

`thenAccept()`：

> **接收前一个任务的结果，但不再产生新的结果。**

例如：

```java
CompletableFuture
        .supplyAsync(() -> 100)
        .thenAccept(result -> {
            System.out.println(result);
        });
```

特点：

```text
有输入
无输出
```

常见用途：

```text
打印
保存
发送
消费结果
```

---

# 二十三、thenRun()

`thenRun()`：

> **等前面的任务完成后执行，但不关心前一个任务的结果。**

例如：

```java
CompletableFuture
        .supplyAsync(() -> 100)
        .thenRun(() -> {
            System.out.println("任务完成");
        });
```

特点：

```text
无输入
无输出
```

---

# 二十四、thenApply / thenAccept / thenRun 对比

| 方法 | 接收前面的结果 | 返回新结果 |
|---|---:|---:|
| thenApply | 是 | 是 |
| thenAccept | 是 | 否 |
| thenRun | 否 | 否 |

记忆：

```text
thenApply   ：拿结果 → 加工 → 产生新结果
thenAccept  ：拿结果 → 消费
thenRun     ：只关心前面是否完成
```

---

# 二十五、异步任务链

`CompletableFuture` 可以把多个步骤串起来：

```java
CompletableFuture
        .supplyAsync(() -> 10)
        .thenApply(x -> x * 2)
        .thenApply(x -> x + 5)
        .thenAccept(System.out::println);
```

执行过程：

```text
10
↓
20
↓
25
↓
打印 25
```

这就是：

> **异步任务链 / 异步编排。**

---

# 二十六、thenCombine()

当两个异步任务互不依赖时，可以并行执行，最后合并。

```java
CompletableFuture<String> userFuture =
        CompletableFuture.supplyAsync(() -> "用户信息");

CompletableFuture<String> orderFuture =
        CompletableFuture.supplyAsync(() -> "订单信息");

CompletableFuture<String> result =
        userFuture.thenCombine(
                orderFuture,
                (user, order) -> user + " " + order
        );
```

执行流程：

```text
查询用户 ─────────┐
                  ├──> 两边完成 → 合并
查询订单 ─────────┘
```

适合：

```text
两个互不依赖的异步任务
↓
最终结果需要同时依赖两边
```

---

# 二十七、allOf()

如果有很多任务：

```java
CompletableFuture<Void> all =
        CompletableFuture.allOf(
                future1,
                future2,
                future3
        );
```

表示：

> **等待所有 CompletableFuture 都完成。**

流程：

```text
任务1 ─────┐
任务2 ─────┼──> 全部完成
任务3 ─────┘
```

注意：

`allOf()` 本身返回：

```java
CompletableFuture<Void>
```

不会直接把各任务结果组合成 List，需要再分别获取。

---

# 二十八、exceptionally()

异步任务也可能抛异常。

```java
CompletableFuture<Integer> future =
        CompletableFuture
                .supplyAsync(() -> {
                    int x = 1 / 0;
                    return x;
                })
                .exceptionally(ex -> {
                    System.out.println("发生异常：" + ex.getMessage());
                    return 0;
                });
```

执行逻辑：

```text
任务成功
↓
正常继续
```

如果失败：

```text
任务异常
↓
exceptionally()
↓
处理异常
↓
返回一个备用值
```

# 二十九、异步不等于多线程

这两个概念要区分。

## 多线程

关注：

> **有多个线程参与执行。**

## 异步

关注：

> **调用者是否需要立即等待结果。**

可以粗略记为：

```text
多线程：执行机制
异步：编程模式
```

两者经常一起出现，但不是同一个概念。

# 三十五、手写练习建议

## 必须手写

### 练习 1：固定线程池

```java
ExecutorService pool =
        Executors.newFixedThreadPool(3);

for (int i = 0; i < 10; i++) {
    int taskId = i;

    pool.submit(() -> {
        System.out.println(
                Thread.currentThread().getName()
                        + " 执行任务 "
                        + taskId
        );
    });
}

pool.shutdown();
```

观察：

> 10 个任务并不会创建 10 个线程，而是固定几个线程反复执行任务。

### 练习 2：Callable + Future

```java
ExecutorService pool =
        Executors.newFixedThreadPool(2);

Future<Integer> future =
        pool.submit(() -> {
            Thread.sleep(1000);
            return 10 + 20;
        });

System.out.println("主线程先做其他事情");

System.out.println(future.get());

pool.shutdown();
```

重点观察：

### 练习 3：CompletableFuture 基础任务链

```java
CompletableFuture
        .supplyAsync(() -> 10)
```

```text
10
↓

25
```
