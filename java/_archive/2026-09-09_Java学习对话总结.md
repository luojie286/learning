## 二、继承与对象模型

### 1. `new Dog()` 到底创建了什么

例如：

```java
class Animal {
    int age;
    void eat() {}
}

class Dog extends Animal {
    String name;
    void bark() {}
}

Dog d = new Dog();
```

核心理解：

- `new Dog()` 在堆中创建的是 **一个 Dog 对象**。
- 父类的实例字段也属于这个 Dog 对象的一部分。
- 方法不会随着每次 `new` 被复制到对象中。
- 类的方法、字段信息以及继承关系由类的元数据进行描述。

因此不要理解成：

> Dog 对象里又单独 new 了一个 Animal 对象。

更准确的是：

> Dog 对象包含从 Animal 继承来的实例状态，同时 Dog 与 Animal 的方法实现由类层面的信息管理。

---

## 三、父类引用指向子类对象

典型代码：

```java
Animal a = new Dog();
```

这里有两个不同的“类型”：

- `a` 这个引用的**编译时类型**是 `Animal`
- 实际对象的**运行时类型**是 `Dog`

因此：

```java
a.eat();
```

如果 `Dog` 重写了 `eat()`，最终可以调用 `Dog.eat()`。

这就是 Java 多态的重要基础。

---

## 四、成员变量没有多态

成员变量和方法要分开理解。

例如：

```java
class Animal {
    int age = 10;
}

class Dog extends Animal {
    int age = 20;
}
```

然后：

```java
Animal a = new Dog();
Dog d = new Dog();

System.out.println(a.age); // 10
System.out.println(d.age); // 20
```

原因：

> **字段访问主要根据引用的编译时类型确定，不存在方法那样的动态多态。**

子类声明与父类同名字段，严格来说叫：

> **字段隐藏（field hiding）**

而不是字段重写。

可以记成：

> **方法看对象，字段看引用类型。**

---

## 五、`invokevirtual` 和 `invokespecial`

在 JVM 字节码层面，普通实例方法调用通常涉及：

```text
invokevirtual
```

它与普通的虚方法动态分派有关。

而：

```text
invokespecial
```

主要用于一些“特殊调用”，例如：

- 构造方法 `<init>`
- `super.xxx()`
- `private` 方法等特殊场景

例如：

```java
Dog() {
    super();
}
```

创建 Dog 对象时，会进入：

```text
Dog.<init>
    ↓
Animal.<init>
```

父类构造方法的调用属于特殊调用，因此使用 `invokespecial`。

## 六、方法重写与访问权限

今天特别区分了两个容易混淆的概念。

### 1. “子类权限不能比父类低”针对的是方法重写

例如父类：

```java
class Animal {
    protected void eat() {}
}
```

子类重写：

```java
class Dog extends Animal {
    public void eat() {}
}
```

这是合法的，因为：

```text
protected → public
```

权限扩大了。

但是：

```java
class Dog extends Animal {
    private void eat() {}
}
```

是不允许的，因为权限缩小了。

### 2. 常见访问权限强弱

可以粗略记忆：

```text
private
    ↓
默认（package-private）
    ↓
protected
    ↓
public
```

重写时不能降低可见性，可以保持或扩大。

---

## 七、方法重写的返回值类型

### 基本类型

基本类型必须保持一致。

例如：

```java
Animal get()
```

不能重写成：

```java
int get()
```

或者其他不同的基本类型。

### 引用类型

引用类型允许**协变返回类型**。

例如：

```java
class Animal {
    Animal get() {
        return new Animal();
    }
}

class Dog extends Animal {
    @Override
    Dog get() {
        return new Dog();
    }
}
```

这是合法的。

因为：

```text
Dog 是 Animal 的子类
```

所以可以记忆：

> **重写时，基本类型必须相同；引用类型可以返回更具体的子类型。**

# 八、抽象类与接口

## 1. 抽象类

抽象类本质上仍然是一个：

> **class**

它可以拥有：

- 实例字段
- 构造方法
- 普通方法
- 抽象方法

例如：

```java
abstract class Animal {
    protected String name;

    public Animal(String name) {
        this.name = name;
    }

    abstract void eat();

    void sleep() {
        System.out.println("sleep");
    }
}
```

抽象类适合表达：

> **“它是什么”**

也就是典型的 `is-a` 关系。

---

## 2. 接口

接口更偏向：

> **“它能做什么”**

例如：

```java
interface Flyable {
    void fly();
}
```

一个类可以：

```java
class Bird implements Flyable {
    public void fly() {}
}
```

接口非常重要的优势是：

> **一个类可以实现多个接口。**

例如：

```java
class Bird implements Flyable, Runnable {
}
```

而 Java 类只能直接：

```java
extends 一个父类
```

---

# 九、现代 Java 接口

现代 Java 的接口已经不只是“纯抽象方法”。

### Java 8

引入：

```java
default
static
```

例如：

```java
interface A {
    default void test() {
        System.out.println("default");
    }

    static void hello() {
        System.out.println("hello");
    }
}
```

调用方式不同：

```java
obj.test();
A.hello();
```

### Java 9

接口还可以拥有：

```java
private
```

方法。

主要用于给接口内部的 `default` / `static` 方法复用代码。

因此现代接口可以拥有：

- 抽象方法
- `default` 方法
- `static` 方法
- `private` 方法
- 常量字段

但它和普通 class 依然不是同一种东西。

---

# 十、接口字段

接口中的字段默认具有：

```java
public static final
```

例如：

```java
interface Config {
    int MAX = 100;
}
```

实际上相当于：

```java
public static final int MAX = 100;
```

所以它是一个**常量**，不是每个对象独立拥有的实例字段。

# 十一、JavaBean

JavaBean 不是：

- 新的数据类型
- 新的关键字
- 一个必须继承的父类

而是一套编程约定。

典型 JavaBean：

```java
public class User {

    private String name;

    public User() {
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

常见特征：

- public class
- private 成员变量
- public 无参构造
- getter / setter

现代 Java 开发中，JavaBean 思想依然非常常见，尤其是在：

- Spring
- ORM
- DTO
- 配置对象
- 数据传输对象

等场景。

# 十二、内部类

今天整理了 Java 常见的四种内部/嵌套类。

## 1. 成员内部类

```java
class Outer {

    class Inner {
    }
}
```

创建：

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
```

它与外部类对象存在关联。

可以直接访问外部类实例成员：

```java
class Outer {
    private int x = 10;

    class Inner {
        void test() {
            System.out.println(x);
        }
    }
}
```

如果需要明确指出当前关联的外部对象，可以使用：

```java
Outer.this
```

---

## 2. 静态嵌套类

```java
class Outer {

    static class Inner {
    }
}
```

创建：

```java
Outer.Inner inner = new Outer.Inner();
```

不需要：

```java
new Outer()
```

因为它不绑定某一个具体的 Outer 实例。

它可以直接访问 Outer 的静态成员，但不能直接访问 Outer 的实例字段。

---

## 3. 局部内部类

定义在方法或代码块内部：

```java
void test() {

    class Inner {
        void hello() {
            System.out.println("hello");
        }
    }

    Inner inner = new Inner();
}
```

作用域主要就在对应的方法/代码块中。

它可以访问外部成员以及满足要求的局部变量。

局部变量如果被内部类捕获，需要是：

> final 或 effectively final（实际上没有被重新赋值）

---

## 4. 匿名内部类

没有名字，直接创建：

```java
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("run");
    }
};
```

常用于：

- 临时继承一个类
- 临时实现一个接口
- 回调
- 老式事件处理等

需要注意：

> Lambda 和匿名内部类很相似，但 Lambda 并不是简单地“把匿名内部类换了一种写法”。

Lambda 主要针对函数式接口。

# 十八、今天最值得记住的几个结论

### ① 字段没有多态，方法有多态

```text
字段 → 看引用类型
方法 → 看运行时对象
```

### ② 子类重写方法时不能降低访问权限

```text
可以扩大，不能缩小
```

### ③ 重写的返回值

```text
基本类型 → 必须相同
引用类型 → 可以协变
```

### ④ 抽象类 vs 接口

```text
抽象类 → 更强调“是什么”
接口   → 更强调“能做什么”
```

### ⑤ 接口字段

```text
public static final
```

### ⑥ 内部类主要四类

```text
成员内部类
静态嵌套类
局部内部类
匿名内部类
```

### ⑦ 学 Java 不需要把所有示例逐行抄一遍

真正应该追求：

```text
理解 → 动手验证 → 变式练习 → 应用
```

而不是：

```text
抄代码 → 机械记忆
```
