# 1. Map

`Map` 用于存储 **键值对（key-value）**：

```java
key -> value
```

例如：

```java
"Tom" -> 18
"Jerry" -> 20
```

与 `List` 的区别：

- `List`：通过下标访问元素。
- `Map`：通过 `key` 查找 `value`。
- `Map` 中 key 不能重复。
- value 可以重复。

## 1.1 基本定义

```java
Map<K, V>
```

其中：

- `K`：Key 的类型。
- `V`：Value 的类型。

例如：

```java
Map<String, Integer> map = new HashMap<>();
```

---

## 1.2 常用 API

### put()

```java
map.put(key, value);
```

如果 key 不存在，则添加。

如果 key 已存在，则覆盖旧值，并返回旧值：

```java
Map<String, Integer> map = new HashMap<>();

System.out.println(map.put("Tom", 18)); // null
System.out.println(map.put("Tom", 20)); // 18
```

---

### get()

```java
map.get(key);
```

key 不存在时返回：

```java
null
```

---

### getOrDefault()

```java
map.getOrDefault(key, defaultValue);
```

典型算法题写法：

```java
Map<Integer, Integer> cnt = new HashMap<>();

for (int x : nums) {
    cnt.put(x, cnt.getOrDefault(x, 0) + 1);
}
```

等价于 C++ 中常见的：

```cpp
mp[x]++;
```

---

### containsKey()

```java
map.containsKey(key);
```

用于判断 key 是否存在。

HashMap 平均复杂度：

```text
O(1)
```

---

### containsValue()

```java
map.containsValue(value);
```

通常需要遍历整个 Map：

```text
O(n)
```

---

### remove()

```java
map.remove(key);
```

或者：

```java
map.remove(key, value);
```

第二种只有 key-value 同时匹配时才删除。

---

### size() / isEmpty() / clear()

```java
map.size();
map.isEmpty();
map.clear();
```

---

## 1.3 Map 遍历

### 遍历 key

```java
for (String key : map.keySet()) {
    System.out.println(key);
}
```

`keySet()` 返回：

```java
Set<K>
```

---

### 遍历 value

```java
for (Integer value : map.values()) {
    System.out.println(value);
}
```

`values()` 返回：

```java
Collection<V>
```

---

### 同时遍历 key 和 value

推荐：

```java
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey());
    System.out.println(entry.getValue());
}
```

`entrySet()` 返回：

```java
Set<Map.Entry<K, V>>
```

`Map.Entry<K, V>` 就代表一个键值对。

---

## 1.4 HashMap 底层实现

现代 Java 中，`HashMap` 可以概括为：

```text
数组 + 链表 + 红黑树
```

底层核心数组：

```text
Node[] table
```

每一个数组位置称为一个桶：

```text
bucket
```

大致结构：

```text
table

[0]
[1] -> Node -> Node
[2]
[3]
[4] -> Node -> Node -> Node
...
```

---

## 1.5 HashMap 的 put() 流程

```java
map.put(key, value);
```

大致过程：

```text
key
 ↓
计算 hashCode()
 ↓
HashMap 再做 hash 扰动
 ↓
计算数组下标
 ↓
定位桶
 ↓
如果桶为空，直接插入
 ↓
如果桶中已有元素，处理冲突
```

桶下标的核心思想可以理解为：

```java
index = hash & (table.length - 1);
```

---

## 1.6 hashCode() 和 equals()

HashMap 判断 key 时：

```text
hashCode：帮助定位桶
equals：确认是不是同一个 key
```

所以：

```text
hashCode 相同
≠
对象一定相同
```

因为存在哈希冲突。

但如果：

```java
a.equals(b) == true
```

那么必须保证：

```java
a.hashCode() == b.hashCode()
```

因此自定义对象作为 HashMap key 时，通常要同时重写：

```java
equals()
hashCode()
```

---

## 1.7 红黑树化

如果一个桶中的冲突元素太多，链表会变得很长。

链表查找最坏：

```text
O(n)
```

因此 Java 8 以后，当桶中节点达到一定数量时，会考虑转成红黑树：

```text
O(log n)
```

重要阈值：

```java
TREEIFY_THRESHOLD = 8
MIN_TREEIFY_CAPACITY = 64
```

也就是说：

- 链表节点较多时考虑树化。
- 但如果数组容量还太小，优先扩容，而不是立即树化。

---

## 1.8 HashMap 扩容

常见默认：

```text
初始容量：16
负载因子：0.75
```

阈值：

```text
16 × 0.75 = 12
```

容量一般按 2 倍扩展：

```text
16 -> 32 -> 64 -> 128
```

容量保持为 2 的幂，有利于：

```java
hash & (length - 1)
```

快速计算下标。

---

## 1.9 HashMap 的 null

HashMap：

- 允许一个 `null` key。
- 允许多个 `null` value。

因此：

```java
map.get(key) == null
```

不能完全说明 key 不存在。

可能：

1. key 不存在。
2. key 存在，但对应 value 就是 `null`。

想严格判断 key 是否存在：

```java
map.containsKey(key);
```

---

## 1.10 常见 Map 实现

| 实现 | 底层/特点 | 典型复杂度 |
|---|---|---|
| `HashMap` | 数组 + 链表 + 红黑树 | 平均 O(1) |
| `LinkedHashMap` | HashMap + 双向链表 | 平均 O(1)，可维护顺序 |
| `TreeMap` | 红黑树 | O(log n) |
| `ConcurrentHashMap` | 并发哈希结构 | 面向多线程 |
| `EnumMap` | 枚举索引 + 数组 | 非常高效 |

---

## 1.11 TreeMap

```java
Map<Integer, Integer> map = new TreeMap<>();
```

特点：

- key 自动排序。
- 底层红黑树。
- `put/get/remove`：`O(log n)`。

C++ 中最接近：

```cpp
std::map
```

---

## 1.12 Java Map 与 C++ 对照

| C++ | Java |
|---|---|
| `unordered_map<K,V>` | `HashMap<K,V>` |
| `map<K,V>` | `TreeMap<K,V>` |
| `mp[key]` | `map.get(key)` |
| `mp[key]++` | `map.put(key, map.getOrDefault(key, 0) + 1)` |
| `mp.count(key)` | `map.containsKey(key)` |
| `mp.erase(key)` | `map.remove(key)` |
| `mp.size()` | `map.size()` |

# 2. EnumMap

`EnumMap` 专门用于：

> key 是枚举类型的 Map。

例如：

```java
enum Status {
    TODO,
    DOING,
    DONE
}
```

使用：

```java
Map<Status, String> map = new EnumMap<>(Status.class);

map.put(Status.TODO, "未开始");
map.put(Status.DOING, "进行中");
map.put(Status.DONE, "已完成");
```

---

## 2.1 EnumMap 特点

- key 必须是同一种枚举类型。
- 不允许 `null` key。
- 可以有 `null` value。
- 遍历顺序按照枚举定义顺序。
- 对 enum key 比 `HashMap<Enum, V>` 更合适。

---

## 2.2 EnumMap 底层思想

每个 enum 常量都有：

```java
ordinal()
```

例如：

```java
enum Level {
    LOW,       // 0
    MEDIUM,    // 1
    HIGH       // 2
}
```

EnumMap 可以利用枚举的固定序号来映射数组位置。

可以近似理解为：

```text
values[0] -> LOW 对应的值
values[1] -> MEDIUM 对应的值
values[2] -> HIGH 对应的值
```

因此不需要：

- hash 计算。
- 哈希冲突。
- 链表。
- 红黑树。

所以 EnumMap 对 enum key 非常高效。

---

## 2.3 典型场景

```text
枚举状态 -> 配置
枚举状态 -> Handler
枚举权限 -> 处理逻辑
```

例如：

```java
EnumMap<OrderStatus, Handler> handlers =
        new EnumMap<>(OrderStatus.class);
```

一句话：

> Map 的 key 是 enum 时，优先考虑 EnumMap。

---

# 3. Properties

`Properties` 是 Java 中专门用于处理配置项的类。

实际使用中通常理解为：

```text
String key -> String value
```

典型文件：

```properties
username=root
password=123456
url=jdbc:mysql://localhost:3306/test
```

---

## 3.1 基本使用

```java
Properties properties = new Properties();

properties.setProperty("name", "Tom");
properties.setProperty("age", "18");
```

读取：

```java
String name = properties.getProperty("name");
```

提供默认值：

```java
String value =
        properties.getProperty("xxx", "default");
```

---

## 3.2 读取 properties 文件

```java
Properties properties = new Properties();

try (FileInputStream fis =
         new FileInputStream("config.properties")) {

    properties.load(fis);
}
```

之后：

```java
String username =
        properties.getProperty("username");
```

注意：

```properties
age=18
```

读取出来仍然是：

```java
String
```

如果需要 int：

```java
int age =
        Integer.parseInt(properties.getProperty("age"));
```

---

## 3.3 写入配置文件

```java
Properties properties = new Properties();

properties.setProperty("username", "root");
properties.setProperty("password", "123456");

try (FileOutputStream fos =
         new FileOutputStream("config.properties")) {

    properties.store(fos, "database config");
}
```

---

## 3.4 遍历

推荐：

```java
for (String key : properties.stringPropertyNames()) {
    String value = properties.getProperty(key);
    System.out.println(key + "=" + value);
}
```

`stringPropertyNames()` 返回：

```java
Set<String>
```

---

## 3.5 Properties 的继承关系

```text
Object
  ↓
Dictionary
  ↓
Hashtable<Object, Object>
  ↓
Properties
```

虽然理论上可以：

```java
properties.put(123, 456);
```

但不推荐。

实际使用应坚持：

```text
String -> String
```

并优先使用：

```java
setProperty()
getProperty()
```

---

## 3.6 classpath 下读取资源

配置文件如果在：

```text
src/main/resources
```

可以：

```java
InputStream inputStream =
        getClass()
            .getClassLoader()
            .getResourceAsStream("config.properties");

Properties properties = new Properties();
properties.load(inputStream);
```

这种方式打包成 jar 后更合适。

---

## 3.7 中文和编码

传统的：

```java
load(InputStream)
```

涉及 ISO-8859-1 兼容行为。

如果要明确 UTF-8，可以使用 Reader：

```java
try (Reader reader =
         new InputStreamReader(
             new FileInputStream("config.properties"),
             StandardCharsets.UTF_8)) {

    properties.load(reader);
}
```

---

## 3.8 HashMap 与 Properties

| 特点 | HashMap | Properties |
|---|---|---|
| 通用键值存储 | 是 | 不是主要用途 |
| 配置文件 | 一般不用 | 常用 |
| key/value | 任意类型 | 通常 String/String |
| `load()` | 无 | 有 |
| `store()` | 无 | 有 |
| 线程安全 | 否 | 继承 Hashtable，同步 |

# 4. Set

`Set` 表示：

> 不允许重复元素的集合。

例如：

```java
Set<Integer> set = new HashSet<>();

set.add(1);
set.add(2);
set.add(1);
```

最终只保留：

```text
1
2
```

---

## 4.1 Set 和 List 的区别

| 特点 | List | Set |
|---|---|---|
| 重复元素 | 允许 | 不允许 |
| 下标 | 有 | 没有 |
| 顺序 | 看具体实现 | 看具体实现 |
| 常见用途 | 顺序存储 | 去重、判重 |

---

## 4.2 常见 Set 实现

```text
Set
├── HashSet
├── LinkedHashSet
├── TreeSet
└── EnumSet
```

---

## 4.3 HashSet

```java
Set<Integer> set = new HashSet<>();
```

常用：

```java
set.add(x);
set.contains(x);
set.remove(x);
set.size();
set.isEmpty();
set.clear();
```

`add()` 返回 boolean：

```java
System.out.println(set.add(1)); // true
System.out.println(set.add(1)); // false
```

---

## 4.4 HashSet 底层

HashSet 底层本质上使用：

```java
HashMap
```

可以近似理解为：

```java
class HashSet<E> {
    private HashMap<E, Object> map;
}
```

执行：

```java
set.add("Tom");
```

底层类似：

```java
map.put("Tom", PRESENT);
```

所以：

> HashSet 的元素，就是 HashMap 的 key。

这也是 HashSet 元素不能重复的原因。

---

## 4.5 HashSet 如何判断重复

使用：

```text
hashCode + equals
```

所以自定义对象放入 HashSet，通常也需要正确重写：

```java
equals()
hashCode()
```

---

## 4.6 HashSet 复杂度

平均：

| 操作 | 复杂度 |
|---|---|
| `add()` | O(1) |
| `contains()` | O(1) |
| `remove()` | O(1) |
| 遍历 | O(n) |

---

## 4.7 LinkedHashSet

特点：

```text
去重 + 保持插入顺序
```

```java
Set<Integer> set =
        new LinkedHashSet<>();
```

---

## 4.8 TreeSet

特点：

```text
去重 + 自动排序
```

```java
TreeSet<Integer> set =
        new TreeSet<>();
```

底层：

```text
红黑树
```

复杂度：

```text
add      O(log n)
contains O(log n)
remove   O(log n)
```

---

## 4.9 TreeSet 判断重复

TreeSet 主要根据：

```java
compareTo()
```

或者：

```java
Comparator
```

如果：

```java
compare(a, b) == 0
```

TreeSet 就认为它们重复。

这与 HashSet 的：

```text
hashCode + equals
```

不同。

---

## 4.10 TreeSet 常用有序操作

```java
set.first();
set.last();

set.ceiling(x); // >= x 的最小元素
set.floor(x);   // <= x 的最大元素

set.higher(x);  // > x
set.lower(x);   // < x
```

---

## 4.11 EnumSet

如果 Set 存的都是 enum，优先考虑：

```java
EnumSet
```

例如：

```java
enum Permission {
    READ,
    WRITE,
    DELETE
}
```

```java
Set<Permission> set =
        EnumSet.of(
            Permission.READ,
            Permission.WRITE
        );
```

全部枚举值：

```java
EnumSet<Permission> set =
        EnumSet.allOf(Permission.class);
```

EnumSet 针对枚举做特殊优化，底层通常可以通过位向量思想实现。

---

## 4.12 C++ Set 对照

| C++ | Java |
|---|---|
| `unordered_set<T>` | `HashSet<T>` |
| `set<T>` | `TreeSet<T>` |
| `insert(x)` | `add(x)` |
| `count(x)` | `contains(x)` |
| `erase(x)` | `remove(x)` |
| `size()` | `size()` |

# 5. Queue

Queue 表示：

```text
FIFO
First In First Out
先进先出
```

现代 Java 普通队列常写：

```java
Queue<Integer> queue =
        new ArrayDeque<>();
```

---

## 5.1 Java 与 C++ queue 对照

| C++ | Java |
|---|---|
| `queue<int>` | `Queue<Integer>` |
| `push(x)` | `offer(x)` |
| `front()` | `peek()` |
| `pop()` | `poll()` |
| `empty()` | `isEmpty()` |
| `size()` | `size()` |

---

## 5.2 基本使用

```java
Queue<Integer> queue =
        new ArrayDeque<>();

queue.offer(1);
queue.offer(2);
queue.offer(3);

System.out.println(queue.peek()); // 1

int x = queue.poll(); // 删除并返回 1
```

Java 的：

```java
poll()
```

与 C++ `pop()` 最大区别：

- C++ `pop()`：只删除。
- Java `poll()`：删除并返回元素。

---

## 5.3 Queue 两套 API

| 操作 | 抛异常版本 | 特殊值版本 |
|---|---|---|
| 入队 | `add()` | `offer()` |
| 查看队头 | `element()` | `peek()` |
| 出队 | `remove()` | `poll()` |

一般推荐：

```java
offer()
peek()
poll()
```

---

## 5.4 ArrayDeque

普通队列推荐：

```java
Queue<Integer> queue =
        new ArrayDeque<>();
```

底层：

```text
可扩容循环数组
```

常见操作均摊：

```text
offer O(1)
poll  O(1)
peek  O(1)
```

相比 LinkedList：

- 内存更紧凑。
- 少链表节点开销。
- 缓存局部性通常更好。

---

## 5.5 BFS

C++：

```cpp
queue<int> q;
q.push(start);

while (!q.empty()) {
    int cur = q.front();
    q.pop();
}
```

Java：

```java
Queue<Integer> queue =
        new ArrayDeque<>();

queue.offer(start);

while (!queue.isEmpty()) {
    int cur = queue.poll();
}
```

---

## 5.6 Deque

`Deque` 是：

```text
Double Ended Queue
双端队列
```

Java：

```java
Deque<Integer> deque =
        new ArrayDeque<>();
```

常用：

```java
deque.offerFirst(x);
deque.offerLast(x);

deque.peekFirst();
deque.peekLast();

deque.pollFirst();
deque.pollLast();
```

与 C++ `deque`：

| C++ deque | Java Deque |
|---|---|
| `push_front(x)` | `offerFirst(x)` |
| `push_back(x)` | `offerLast(x)` |
| `front()` | `peekFirst()` |
| `back()` | `peekLast()` |
| `pop_front()` | `pollFirst()` |
| `pop_back()` | `pollLast()` |

---

## 5.7 PriorityQueue

Java：

```java
PriorityQueue<Integer> pq =
        new PriorityQueue<>();
```

默认：

```text
小根堆
```

而 C++：

```cpp
priority_queue<int> pq;
```

默认：

```text
大根堆
```

这是很重要的差异。

Java 大根堆：

```java
PriorityQueue<Integer> pq =
        new PriorityQueue<>(
            Comparator.reverseOrder()
        );
```

复杂度：

```text
offer O(log n)
poll  O(log n)
peek  O(1)
```

# 6. Stack

Java 中虽然存在：

```java
Stack<E>
```

但现代 Java 一般更推荐：

```java
Deque<E> + ArrayDeque
```

来实现栈。

栈：

```text
LIFO
Last In First Out
后进先出
```

---

## 6.1 推荐写法

```java
Deque<Integer> stack =
        new ArrayDeque<>();

stack.push(1);
stack.push(2);
stack.push(3);

System.out.println(stack.peek()); // 3
System.out.println(stack.pop());  // 3
```

---

## 6.2 与 C++ stack 对比

| C++ | Java |
|---|---|
| `stack<int>` | `Deque<Integer> = new ArrayDeque<>()` |
| `push(x)` | `push(x)` |
| `top()` | `peek()` |
| `pop()` | `pop()` |
| `empty()` | `isEmpty()` |
| `size()` | `size()` |

Java `pop()`：

```text
删除 + 返回栈顶
```

C++ `pop()`：

```text
只删除
```

---

## 6.3 为什么不优先用 Stack

旧式：

```java
Stack<Integer> stack =
        new Stack<>();
```

`Stack` 继承：

```java
Vector
```

关系：

```text
Object
  ↓
Vector
  ↓
Stack
```

不推荐的主要原因：

1. `Vector` 是较老的集合类。
2. 很多方法带同步，单线程场景有额外成本。
3. `Stack` 通过继承 Vector 实现栈，历史包袱较重。
4. Java 官方现代 API 更推荐 `Deque` 作为栈接口。

注意：

> 不推荐 Stack 的核心原因并不是“Stack 能删除栈底”。

因为 Deque 作为双端队列，本来就可以操作两端。

关键是：

- Deque 的双端操作是它本身合理的设计目标。
- 当把 Deque 当栈使用时，只使用 `push/pop/peek` 即可。
- `Stack` 则是旧式 Vector 子类设计。

---

## 6.4 Deque 作为栈

当使用：

```java
Deque<Integer> stack =
        new ArrayDeque<>();
```

通常把头部作为栈顶：

```text
栈顶
 ↓
3
2
1
```

`push()` 相当于：

```java
addFirst()
```

`pop()` 相当于：

```java
removeFirst()
```

`peek()` 相当于：

```java
peekFirst()
```

虽然也可以：

```java
pollLast()
```

删除“栈底”，但把它当栈使用时，不这么用即可。

---

## 6.5 ArrayDeque 的 null

ArrayDeque 不允许存 `null`：

```java
stack.push(null); // NullPointerException
```

一个重要原因是：

```java
peek()
```

在空栈时用 `null` 表示没有元素。

---

## 6.6 算法场景

### 括号匹配

```java
Deque<Character> stack =
        new ArrayDeque<>();
```

### 单调栈

```java
Deque<Integer> stack =
        new ArrayDeque<>();
```

通常栈中存下标。

### 手写 DFS

```java
Deque<Integer> stack =
        new ArrayDeque<>();

stack.push(start);

while (!stack.isEmpty()) {
    int cur = stack.pop();
}
```

# 7. Iterator

`Iterator` 是 Java 中用于：

> 按顺序遍历集合元素的接口。

可以理解为一个“游标”。

最核心方法：

```java
hasNext()
next()
remove()
```

---

## 7.1 基本使用

```java
List<String> list =
        new ArrayList<>();

list.add("A");
list.add("B");
list.add("C");

Iterator<String> it =
        list.iterator();

while (it.hasNext()) {
    String s = it.next();
    System.out.println(s);
}
```

---

## 7.2 hasNext()

```java
it.hasNext();
```

表示：

> 后面是否还有元素。

---

## 7.3 next()

```java
it.next();
```

作用：

```text
返回下一个元素
+
让迭代器继续向后移动
```

如果已经没有元素，再调用：

```java
next()
```

会抛：

```text
NoSuchElementException
```

---

## 7.4 Iterator 的价值

不同集合底层不同：

```text
ArrayList  -> 数组
LinkedList -> 双向链表
HashSet    -> HashMap
TreeSet    -> 红黑树
```

Iterator 提供统一遍历方式：

```java
hasNext()
next()
```

外部代码不用关心底层怎么遍历。

---

## 7.5 Iterable 与 Iterator

`Collection` 继承：

```java
Iterable<E>
```

`Iterable` 核心方法：

```java
Iterator<E> iterator();
```

关系：

```text
Iterable
   ↓
负责产生 Iterator

Iterator
   ↓
负责真正遍历
```

---

## 7.6 增强 for 与 Iterator

```java
for (String s : list) {
    System.out.println(s);
}
```

对于 Iterable 类型，本质可以理解为：

```java
Iterator<String> it =
        list.iterator();

while (it.hasNext()) {
    String s = it.next();
    System.out.println(s);
}
```

所以 HashSet 没有下标，也能 for-each。

---

## 7.7 LinkedList 为什么更适合 Iterator 遍历

对 `LinkedList`：

```java
for (int i = 0; i < list.size(); i++) {
    list.get(i);
}
```

最坏可能：

```text
O(n²)
```

因为每次 `get(i)` 都可能需要沿链表移动。

Iterator 可以顺着节点走：

```text
O(n)
```

---

## 7.8 iterator.remove()

遍历过程中删除元素：

```java
Iterator<Integer> it =
        list.iterator();

while (it.hasNext()) {
    int x = it.next();

    if (x % 2 == 0) {
        it.remove();
    }
}
```

`remove()` 删除：

> 最近一次 `next()` 返回的元素。

---

## 7.9 ConcurrentModificationException

错误写法：

```java
for (Integer x : list) {
    if (x % 2 == 0) {
        list.remove(x);
    }
}
```

可能抛：

```text
ConcurrentModificationException
```

原因是：

- Iterator 正在遍历。
- 你绕过 Iterator 直接修改了集合结构。
- Iterator 检测到结构发生了不符合预期的变化。

注意：

> ConcurrentModificationException 并不意味着一定发生在多线程。

单线程中也可能出现。

---

## 7.10 fail-fast

以 ArrayList 为例，内部有类似：

```java
modCount
```

Iterator 创建时记录：

```java
expectedModCount
```

遍历过程中如果发现：

```text
expectedModCount != modCount
```

可能立即抛：

```text
ConcurrentModificationException
```

这就是 fail-fast 思想。

通过：

```java
iterator.remove()
```

删除时，Iterator 能同步自己的状态，所以可以正常继续遍历。

---

## 7.11 Map 和 Iterator

Map 本身不是 Collection，所以不能直接：

```java
map.iterator();
```

但可以：

```java
map.keySet().iterator();
map.values().iterator();
map.entrySet().iterator();
```

例如：

```java
Iterator<Map.Entry<String, Integer>> it =
        map.entrySet().iterator();

while (it.hasNext()) {
    Map.Entry<String, Integer> entry =
            it.next();

    System.out.println(
        entry.getKey() + " " + entry.getValue()
    );
}
```

---

## 7.12 ListIterator

`ListIterator` 是专门针对 List 的增强版 Iterator。

除了：

```java
hasNext()
next()
```

还有：

```java
hasPrevious()
previous()
```

可以双向遍历。

还支持：

```java
add()
set()
remove()
```

---

## 7.13 与 C++ Iterator 对比

C++：

```cpp
for (auto it = v.begin();
     it != v.end();
     ++it) {

    cout << *it;
}
```

Java：

```java
Iterator<Integer> it =
        list.iterator();

while (it.hasNext()) {
    System.out.println(it.next());
}
```

对应：

| C++ | Java |
|---|---|
| `v.begin()` | `collection.iterator()` |
| `it != v.end()` | `it.hasNext()` |
| `*it` | `it.next()` 返回值 |
| `++it` | `next()` 内部顺便前进 |
| `erase(it)` | `it.remove()` |

最关键差别：

```text
C++:
*it     取值
++it    前进

Java:
it.next()
= 取值 + 前进
```

# 8. Collection

`Collection` 是 Java 集合框架中非常核心的接口。

可以理解为：

> 一组对象的统一抽象。

大致体系：

```text
                Iterable
                    ↑
                Collection
          ┌─────────┼─────────┐
          ↓         ↓         ↓
         List      Set       Queue
```

注意：

```text
Map 不属于 Collection。
```

---

## 8.1 Collection 是接口

```java
public interface Collection<E>
        extends Iterable<E>
```

例如：

```java
Collection<Integer> collection =
        new ArrayList<>();
```

合法。

但不能：

```java
new Collection<>();
```

因为 Collection 是接口。

---

## 8.2 为什么需要 Collection

不同集合虽然底层不同，但都有共同操作：

```text
添加
删除
判断包含
获取大小
清空
遍历
```

Java 把这些共有能力统一抽象成 Collection。

---

## 8.3 常用方法

### add()

```java
collection.add(e);
```

返回 boolean，表示集合是否发生变化。

---

### remove()

```java
collection.remove(o);
```

返回 boolean。

---

### contains()

```java
collection.contains(o);
```

复杂度取决于实现：

```text
ArrayList.contains() -> O(n)
HashSet.contains()   -> 平均 O(1)
TreeSet.contains()   -> O(log n)
```

Collection 只规定“有这个能力”，不规定具体实现复杂度。

---

### size()

```java
collection.size();
```

---

### isEmpty()

```java
collection.isEmpty();
```

---

### clear()

```java
collection.clear();
```

---

### iterator()

```java
Iterator<E> it =
        collection.iterator();
```

因为 Collection 继承 Iterable。

---

### addAll()

```java
a.addAll(b);
```

把 b 中元素加入 a。

---

### containsAll()

```java
a.containsAll(b);
```

判断 a 是否包含 b 中的所有元素。

---

### removeAll()

```java
a.removeAll(b);
```

删除 a 中所有同时存在于 b 的元素。

可理解为：

```text
a = a - b
```

---

### retainAll()

```java
a.retainAll(b);
```

只保留交集：

```text
a = a ∩ b
```

---

### removeIf()

```java
list.removeIf(x -> x % 2 == 0);
```

删除满足条件的元素。

---

### toArray()

```java
Object[] arr =
        collection.toArray();
```

类型化：

```java
String[] arr =
        collection.toArray(new String[0]);
```

现代写法：

```java
String[] arr =
        collection.toArray(String[]::new);
```

---

### stream()

```java
collection.stream()
```

可以创建 Stream。

---

## 8.4 List<Integer>.remove() 易错点

```java
List<Integer> list =
        new ArrayList<>(List.of(10, 20, 30));
```

```java
list.remove(1);
```

这里会调用：

```java
remove(int index)
```

删除下标 1，也就是 `20`。

如果想删除 Integer 值：

```java
list.remove(Integer.valueOf(1));
```

---

## 8.5 Collection 和 Collections

不要混淆。

### Collection

```java
Collection
```

是：

```text
集合接口
```

### Collections

```java
Collections
```

是：

```text
集合工具类
```

例如：

```java
Collections.sort(list);
Collections.reverse(list);
Collections.shuffle(list);
Collections.max(list);
Collections.min(list);
```

记忆：

```text
Collection
没有 s
→ 接口

Collections
有 s
→ 工具类
```

---

## 8.6 Collection 与 Map

Collection：

```text
单个元素
```

泛型：

```java
Collection<E>
```

Map：

```text
key -> value
```

泛型：

```java
Map<K, V>
```

所以 Map 没有继承 Collection。

但 Map 可以暴露集合视图：

```java
Set<K> keySet();

Collection<V> values();

Set<Map.Entry<K, V>> entrySet();
```

注意：

```java
values()
```

返回的是：

```java
Collection<V>
```

而不是 Set，因为 value 可以重复。

---

## 8.7 面向接口编程

常见推荐：

```java
List<Integer> list =
        new ArrayList<>();

Set<Integer> set =
        new HashSet<>();

Queue<Integer> queue =
        new ArrayDeque<>();
```

左边写接口，右边写具体实现。

这样代码依赖的是：

```text
需要的抽象能力
```

而不是某一个具体类。

例如：

```java
Collection<Integer> c =
        new ArrayList<>();
```

此时只能调用 Collection 定义的方法。

即使右边实际是 ArrayList，也不能：

```java
c.get(0);
```

因为变量静态类型 `Collection` 没有 `get()`。

同理：

```java
Collection<Integer> c =
        new ArrayDeque<>();
```

不能：

```java
c.poll();
```

如果需要 Queue 能力，应写：

```java
Queue<Integer> queue =
        new ArrayDeque<>();
```

# 10. 高频易错点总结

## 10.1 Map

```text
hashCode：帮助定位桶
equals：确认是不是同一个 key
```

自定义对象做 HashMap key 时：

```java
equals()
hashCode()
```

通常一起重写。

---

## 10.2 HashSet

HashSet 本质上依赖：

```text
HashMap 的 key 不重复
```

因此：

```text
HashSet<E>
≈
HashMap<E, 固定对象>
```

---

## 10.3 TreeSet

HashSet 判断重复：

```text
hashCode + equals
```

TreeSet 判断重复：

```text
Comparator / Comparable 比较结果是否为 0
```

---

## 10.4 EnumMap / EnumSet

如果 key 或元素就是 enum：

```text
Map<Enum, V>
→ 优先考虑 EnumMap

Set<Enum>
→ 优先考虑 EnumSet
```

---

## 10.5 Queue

普通队列：

```java
Queue<Integer> queue =
        new ArrayDeque<>();
```

记：

```text
push  -> offer
front -> peek
pop   -> poll
empty -> isEmpty
```

Java `poll()`：

```text
删除 + 返回
```

---

## 10.6 PriorityQueue

非常容易和 C++ 搞反：

```text
Java PriorityQueue
默认小根堆

C++ priority_queue
默认大根堆
```

---

## 10.7 Stack

现代 Java：

```java
Deque<Integer> stack =
        new ArrayDeque<>();
```

推荐：

```java
push()
peek()
pop()
```

不推荐 Stack 的核心原因：

```text
Stack 是基于旧式 Vector 的历史设计
```

而不是因为它能删除栈底。

Deque 本来就是双端队列，所以它能操作两端是合理能力；当作栈使用时，只使用栈 API 即可。

---

## 10.8 Iterator

标准写法：

```java
Iterator<Integer> it =
        collection.iterator();

while (it.hasNext()) {
    Integer x = it.next();
}
```

Java：

```java
it.next()
```

同时完成：

```text
取值 + 向后移动
```

而 C++：

```cpp
*it
++it
```

是两个操作。

---

## 10.9 遍历时删除

容易出错：

```java
for (Integer x : list) {
    list.remove(x);
}
```

可能：

```text
ConcurrentModificationException
```

更安全：

```java
Iterator<Integer> it =
        list.iterator();

while (it.hasNext()) {
    Integer x = it.next();

    if (...) {
        it.remove();
    }
}
```

或者：

```java
list.removeIf(...);
```

## 10.10 Collection 与 Map

一定记住：

```text
Collection
├── List
├── Set
└── Queue

Map
└── 不属于 Collection
```

但 Map 可以通过：

```java
keySet()
values()
entrySet()
```

获得 Collection 体系的视图。
