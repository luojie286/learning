# 22 · 类加载机制

> 一句话概括：`.class` 进入 JVM 到能用，经历 **加载 → 验证 → 准备 → 解析 → 初始化**；类只在**首次主动使用**时初始化一次，`static` 赋值与静态块被编译器收进 `<clinit>()` 按源码顺序执行。
> （本篇对应此前待补清单中的「JVM 类加载机制」；字节码与栈帧 → `23-JVM字节码与栈帧.md`）

---

## 一、五个阶段

```text
加载 Loading
   ↓
连接 Linking ── 验证 Verification
             ├─ 准备 Preparation
             └─ 解析 Resolution
   ↓
初始化 Initialization
```

| 阶段 | 做什么 |
|---|---|
| **加载** | 找到字节码 → 转成 JVM 内部数据结构 → 生成 `Class` 对象 |
| **验证** | 检查 `.class` 是否合法安全（文件格式、字节码、类型、是否破坏 JVM） |
| **准备** | 为**静态变量分配内存并设默认值** |
| **解析** | **符号引用 → 直接引用**（名字 → 真正能定位的目标） |
| **初始化** | 执行静态变量显式赋值 + `static {}` 块，即 `<clinit>()` |

> **`Class` 对象 ≠ 实例对象**：`User.class` 是类的运行时类型信息，`new User()` 才是创建对象。**类加载/初始化 ≠ new 对象**。

---

## 二、准备阶段：默认值，不是你写的值

```java
static int a = 10;
static String name = "Jack";
```

| 阶段 | a | name |
|---|---|---|
| 准备 | `0` | `null` |
| 初始化 | `10` | `"Jack"` |

> **例外——编译期常量**：`static final int MAX = 100;` 可能通过 class 的 `ConstantValue` 属性**在准备阶段**就直接得到 100。所以「准备阶段一定只给默认值」不是绝对的。

---

## 三、初始化顺序

静态变量赋值与静态块**按源码出现顺序**执行，编译器统一放进 `<clinit>()`：

```java
class Test {
    static int a = 10;
    static { System.out.println(a); a = 20; }   // 打印 10，然后 a=20
    static int b = 30;
}
// 逻辑上：<clinit>() { a = 10; 打印 a; a = 20; b = 30; }  → 最终 a=20, b=30
```

**父类优先**：初始化子类前先初始化父类。

```java
class Parent { static { System.out.println("Parent"); } }
class Child extends Parent { static { System.out.println("Child"); } }
new Child();   // 输出：Parent 然后 Child
```

## 四、static 块 vs 普通块 vs 构造方法

```java
class User {
    static { System.out.println("静态代码块"); }   // 类初始化时，只执行一次
    {        System.out.println("普通代码块"); }   // 每次 new 都执行
    User() { System.out.println("构造方法"); }     // 每次 new 都执行
}
```

连着 `new User()` 两次：

```text
静态代码块 / 普通代码块 / 构造方法 / 普通代码块 / 构造方法
```

| | 执行时机 | 次数 |
|---|---|---|
| `static {}` | 类初始化 | 一个类通常**一次** |
| `{}` | 每次创建对象 | 每次 |
| 构造方法 | 每次创建对象 | 每次 |

---

## 📌 易错点

1. **把类加载/初始化当成 new 对象** ✗——`User.class` 只触发类信息，不创建对象。
2. **以为准备阶段就赋了程序员写的值** ✗——默认先给零值，`static final` 编译期常量是例外。
3. **以为静态块每次 new 都执行** ✗——它是类初始化逻辑，只一次。
4. **忘了父类先初始化**——子类初始化前父类已初始化完毕。
5. **以为静态变量和静态块按「先变量后块」执行** ✗——按**源码顺序**混合执行。

---

## 🧠 速记口诀

```text
加载 → 验证 → 准备 → 解析 → 初始化（连接 = 验 + 准 + 解）
准备给零值，初始化才赋真值；static final 常量可能提前
<clinit> = 静态赋值 + 静态块，按源码顺序
父先于子；static{} 一次，{} 和构造每次
```
