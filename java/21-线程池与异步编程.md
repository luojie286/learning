# 21 · 线程池与异步编程

> 一句话概括：线程池解决「谁来跑」，`Future`/`Callable` 解决「结果怎么取」，`CompletableFuture` 解决「多个异步任务怎么编排」——三者串起 Java 异步编程。
> （线程池的构造参数与 `BlockingQueue` 底层关系见 → `17-JUC并发工具.md`，本篇侧重**使用模型与异步编排**）

---

## 一、为什么需要线程池

每来一个任务就 `new Thread()` 的问题：频繁创建销毁有开销、线程过多导致内存占用上升、上下文切换频繁、极端情况资源耗尽。

线程池的三个价值：**复用线程 + 限制数量 + 统一管理**（创建/复用/排队/回收/拒绝/工厂/调度）。

```java
ExecutorService pool = Executors.newFixedThreadPool(3);
pool.submit(() -> System.out.println(Thread.currentThread().getName()));
pool.shutdown();          // 关闭：不再收新任务，等已提交任务跑完
```

> **`submit()` ≠ 创建新线程。** 任务由池里哪个线程执行，由线程池决定。

---

## 二、思想转变：任务与线程分离

```java
// 以前：自己管线程
new Thread(task).start();

// 现在：只管任务
pool.submit(task);
```

> **把「任务」和「线程」分离**——你描述「做什么」，线程池决定「谁来做、什么时候做」。

## 三、Runnable vs Callable vs Future

| | 返回值 | 抛异常 | 用途 |
|---|---|---|---|
| `Runnable` | 无 | 不能抛受检异常 | 单纯执行 |
| `Callable<V>` | **有** | **可以抛** | 需要结果的任务 |

`Future` = 「未来结果的**凭证**」，不是结果本身：

```java
Future<Integer> future = pool.submit(() -> { Thread.sleep(2000); return 100; });

System.out.println("主线程先做别的");   // submit 不阻塞
Integer result = future.get();          // 需要结果时才阻塞
```

常用方法：

| 方法 | 作用 |
|---|---|
| `get()` | 取结果，**未完成则阻塞**（也有超时重载） |
| `isDone()` | 是否完成 |
| `cancel(true)` | 尝试取消（`true` 表示允许中断正在运行的任务；不保证一定终止） |
| `isCancelled()` | 是否已取消 |

> 一句话：**Callable 定义任务，Future 保存未来结果。**

---

## 四、同步 vs 异步

- **同步**：调用后**等结果**才能继续。
- **异步**：任务交给别人，**把等待推迟到真正需要结果的那一刻**——不是「永远不等」。

后端为什么需要异步：三个互不依赖的任务（查库 500ms、调接口 1000ms、读文件 300ms）同步要 ~1800ms，并行后接近**最慢那个** ~1000ms。

典型场景：发邮件/短信、写日志、文件处理、调第三方 API、并行查询多个服务、后台任务。用户注册后「立即返回注册成功，邮件后台发」就是异步。

---

## 五、Future 的局限 → CompletableFuture

`Future` 很被动：只能 `get()` 阻塞拿，任务链（A 完成 → 加工 → B → C）写起来很别扭。

> **Future 像「以后自己来取」；CompletableFuture 像「结果出来自动继续下一步」。**

### 创建与三步回调

```java
CompletableFuture.runAsync(() -> System.out.println("无返回值"));      // Runnable 型
CompletableFuture<Integer> f = CompletableFuture.supplyAsync(() -> 100); // Callable 型

CompletableFuture
    .supplyAsync(() -> 10)
    .thenApply(x -> x * 2)        // 10 → 20
    .thenApply(x -> x + 5)        // 20 → 25
    .thenAccept(System.out::println);  // 消费 25
```

| 方法 | 接收前面结果 | 返回新结果 |
|---|---:|---:|
| `thenApply` | 是 | 是（加工） |
| `thenAccept` | 是 | 否（消费） |
| `thenRun` | 否 | 否（只在乎完成） |

### 合并与异常处理

```java
// 两个互不依赖的任务并行，都完成后合并
userFuture.thenCombine(orderFuture, (user, order) -> user + " " + order);

// 等多个任务全部完成（返回 Void，各结果要自己再 get）
CompletableFuture.allOf(f1, f2, f3);

// 异常兜底
CompletableFuture.supplyAsync(() -> 1 / 0)
                 .exceptionally(ex -> 0);      // 出错时返回备用值
```

### 默认线程池

不指定线程池时用 `ForkJoinPool.commonPool()`。生产环境**建议显式传入自己的线程池**，才能控制线程数、命名、资源隔离、队列和拒绝策略：

```java
CompletableFuture.supplyAsync(() -> 100, executor);
```

## 六、异步 ≠ 多线程

| | 关注点 |
|---|---|
| 多线程 | **执行机制**（有没有多个线程参与） |
| 异步 | **编程模式**（调用者是否立即等结果） |

两者常一起出现，但不是一回事（单线程也能异步，如事件循环）。

---

## 📌 易错点

1. **以为 `submit()` 会等任务跑完** ✗——阻塞发生在 `get()`。
2. **线程池用完不 `shutdown()`**——非守护线程会让 JVM 不退出。
3. **`cancel(true)` 当成强制杀死**——只是尝试中断，任务不理就没用（同 `14` 的 `interrupt()`）。
4. **把 `allOf()` 当「合并结果」** ✗——它只等全部完成，返回 `Void`，各结果要分别取。
5. **`CompletableFuture` 不指定线程池**——默认 commonPool，可能与别的代码抢线程。
6. **把异步理解成「永远不等待」** ✗——只是把等待推迟到取结果时。

## 🧠 速记口诀

```text
线程池：复用 + 限流 + 统一管理；submit 不等于建线程
submit 不阻塞，get 才阻塞
Callable 定义任务，Future 保存结果
thenApply 加工 / thenAccept 消费 / thenRun 只管完成
thenCombine 合并两个，allOf 等全部（返回 Void），exceptionally 兜底
异步 = 把等待推迟到需要结果时
```
