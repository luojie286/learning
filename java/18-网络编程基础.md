# 18 · 网络编程基础

> 一句话概括：网络通信三要素 = IP（哪台主机）+ 端口（哪个程序）+ 协议（怎么说话）；Java 用 `Socket` 封装 TCP 连接，本质还是流的读写。

---

## 一、三要素：IP / 端口 / 协议

| 要素 | 回答的问题 | 类比 |
|---|---|---|
| **IP 地址** | 哪一台主机 | 哪栋楼 |
| **端口号** | 这台机器上的哪个程序 | 哪个房间 |
| **协议** | 按什么规则传数据 | 说什么语言 |

- 回环地址 `127.0.0.1`（或 `localhost`）：永远指本机，本地测试首选。
- 常见端口：HTTP `80`、HTTPS `443`、MySQL `3306`；自己测试常用 `8080`、`8888`、`9999`。
- 端口取值 0～65535，一台机器上同一端口同一时刻只能被一个程序监听。

---

## 二、TCP vs UDP

| 对比项 | TCP | UDP |
|---|---|---|
| 是否建立连接 | 面向连接（先握手） | 无连接（拿起就发） |
| 可靠性 | 可靠，丢失重传 | 不保证到达 |
| 顺序 | 保证 | 不保证 |
| 开销 | 相对较大 | 相对较小 |
| Java 核心类 | `Socket` / `ServerSocket` | `DatagramSocket` / `DatagramPacket` |
| 典型场景 | 网页、文件传输、数据库、聊天 | DNS、实时音视频、部分游戏 |

选择依据：**要准确 → TCP；要快、能容忍丢包 → UDP。**

## 三、TCP 编程模型

```text
服务端                              客户端
ServerSocket serverSocket =        Socket socket =
    new ServerSocket(9999);            new Socket("127.0.0.1", 9999);
        ↓                                  ↓
socket = serverSocket.accept();    ← 客户端 connect
（阻塞，直到有连接进来）                ↓
        ↓                           socket.getOutputStream() 写数据
socket.getInputStream() 读数据
```

- `new ServerSocket(9999)`：在本机 9999 端口监听。
- `accept()`：**阻塞等待**，没有客户端连接就一直等；有连接时**返回一个新的 `Socket`**，代表「服务端与该客户端之间的这条 TCP 连接」。
- 客户端 `new Socket(ip, port)`：连接指定主机的指定端口。

---

## 四、最简 TCP 示例

**服务端**：

```java
ServerSocket serverSocket = new ServerSocket(9999);
System.out.println("服务器启动");

Socket socket = serverSocket.accept();          // 阻塞等连接

BufferedReader reader = new BufferedReader(
        new InputStreamReader(socket.getInputStream()));  // 网络流 → 字符流（IO 套娃）

String message = reader.readLine();             // 读一行
System.out.println("客户端说：" + message);

socket.close();
serverSocket.close();
```

**客户端**：

```java
Socket socket = new Socket("127.0.0.1", 9999);

PrintWriter writer = new PrintWriter(
        socket.getOutputStream(), true);        // 第二个参数 true = 自动 flush

writer.println("hello");
socket.close();
```

运行顺序：**先启动 Server**（它在 `accept()` 处等待）→ 再启动 Client → Server 收到 `hello`。

## 五、Socket 与 IO 的关系

`Socket` 是 Java 对 TCP 连接的封装，它只暴露两条流：

```java
InputStream in  = socket.getInputStream();    // 从网络读
OutputStream out = socket.getOutputStream();  // 往网络写
```

所以网络编程没有新的 IO 语法——`13-IO与资源管理` 里的**装饰器套娃**（`BufferedReader(new InputStreamReader(...))`）在这里原样适用：

```text
文件 IO：程序 ↔ 文件
网络 IO：程序 ↔ 网络    ← 只是流的两端从文件换成了网络连接
```

---

## 六、阻塞与多线程服务器

两处典型阻塞：`accept()`（等连接）、`readLine()`（等数据发完整）。单线程服务器处理客户端 A 时，客户端 B 只能干等：

```java
while (true) {
    Socket socket = serverSocket.accept();     // 每来一个连接
    new Thread(() -> handle(socket)).start();  // 开一个线程去处理
}
```

**一连接一线程**。但无限 `new Thread()` 不可取（创建开销 + 资源耗尽），实际开发用线程池：

```java
ExecutorService pool = Executors.newFixedThreadPool(10);

while (true) {
    Socket socket = serverSocket.accept();
    pool.submit(() -> handle(socket));         // 连接处理作为任务交给线程池
}
```

> 这里把 `13`（IO）、`14`（线程）、`17`（线程池）全部串起来了——也是手写练习的重点。

## 七、UDP 基本模型

UDP 不建连接，数据自己打包成 `DatagramPacket`（包里带地址）。

**发送端**：

```java
DatagramSocket socket = new DatagramSocket();
byte[] data = "hello".getBytes();
DatagramPacket packet = new DatagramPacket(
        data, data.length,
        InetAddress.getByName("127.0.0.1"), 9999);  // 目标地址写在包里
socket.send(packet);
```

**接收端**：

```java
DatagramSocket socket = new DatagramSocket(9999);   // 绑定端口收包
byte[] buf = new byte[1024];
DatagramPacket packet = new DatagramPacket(buf, buf.length);
socket.receive(packet);                              // 阻塞等包
```

当前阶段知道基本模型即可。

## 八、从 Socket 到 Spring Boot

以后写 `@GetMapping("/user")`，表面是「浏览器请求 → Controller 执行」，底层链路：

```text
浏览器 → TCP → HTTP → 服务器网络层 → Tomcat（Web 容器）→ Spring MVC → Controller
```

Tomcat 替你做的事，本质就是本篇的「`accept()` + 线程池 + 流读写」。后续的 HTTP、Netty、RPC、WebSocket、Redis、MySQL 连接，全部建立在这套网络通信基础之上。

---

## 九、底层四步：socket → bind → listen → accept

Java 的 `new ServerSocket(9999)` 封装了底层一套流程：

```text
socket()   创建一个套接字（通信端点）
   ↓
bind()     绑定本地 IP + 端口 ——「我占用哪个地址」
   ↓
listen()   变成监听 socket，告诉 OS「有客户端连这个端口就交给我」——「我开始等客户端」
   ↓
accept()   取出（阻塞等待）一个具体客户端连接 ——「接到一个具体客户端」
   ↓
read/write 在这条已建立的连接上收发数据
```

**只 bind 不 listen 收不到 TCP 数据**：TCP 数据不是直接「扔到端口」，而是先建立连接、再通过连接传数据。服务端因此有两类 socket：

```text
监听 socket（ServerSocket）  负责等新连接
已连接 socket（accept 返回）  负责和某个客户端 read/write
```

> UDP 没有 listen/accept：`bind → recvfrom/sendto`，因为无连接。

`accept()` 返回后监听 socket 保持监听，需要**再次调用 `accept()`** 才会取出下一个连接——所以服务器主循环就是反复 `accept()`。

## 十、TCP 四元组与端口占用

一个 TCP 连接由**四元组**唯一区分：**源 IP、源端口、目标 IP、目标端口**。

```text
客户端：192.168.1.10:52341  <==== TCP ====>  服务端：192.168.1.100:8888
             本地临时端口（OS 自动分配）          服务端固定监听端口
```

三个推论：

1. **服务端 8888 可以同时服务多个客户端连接**——每条连接四元组不同，不需要给每个客户端开新端口。
2. **客户端也必须有自己的本地端口**，由 OS 自动选临时端口；响应沿已建立的连接返回，应用层不必再指定。
3. **同一 IP+协议+端口只能被一个监听 socket 独占**，重复启动服务端会抛 `BindException: Address already in use`。但 TCP 8888 和 UDP 8888 互不冲突（不同协议空间）。

Windows 查谁占了端口：

```powershell
netstat -ano | findstr :8888
tasklist /FI "PID eq 1234"   # 换成实际 PID
```

## 十一、readLine() 阻塞的细节

`BufferedReader.readLine()` 在**尚未收到一整行**时会一直等待。完整一行需要换行符，或到达流结尾返回剩余字符（没有剩余则返回 `null`）。

因此：**发送端只写了 `hello`、没写换行、也没关流 → 接收端 `readLine()` 永远卡住**。这是双向聊天程序最容易踩的坑。

配套规则：

- 用 `println()`（自动带 `\n`）配 `readLine()`，一对好搭档；`print()` 不配换行会让对方阻塞。
- `PrintWriter` 的 `autoFlush=true` 只对 `println/printf/format` 生效，不是对所有 `write` 都自动刷新。

---

## 十二、编码一致性

`InputStreamReader/OutputStreamWriter` 的编解码规则是：**字节流 + 字符集 = 字符流**。两端字符集不一致，中文立刻变乱码：

```java
new InputStreamReader(socket.getInputStream(), StandardCharsets.UTF_8)
new OutputStreamWriter(socket.getOutputStream(), StandardCharsets.UTF_8), true
```

约定：本机测试统一 `StandardCharsets.UTF_8`，收发两端一致。这和 `13-IO与资源管理` 里文件读写的编码问题同源——**网络只是流的另一端，规则不变**。

---

## 📌 易错点

1. **先启动客户端**——`connect` 被拒绝（Connection refused）。必须先起 Server。
2. **以为 `accept()` 返回的是 `ServerSocket`**——返回的是与该客户端的**连接 `Socket`**，读写都在它上面。
3. **`new PrintWriter(out)` 忘了第二个参数 `true`**——没有自动 flush，数据憋在缓冲区，对方一直收不到。
4. **服务端/客户端用同一个端口互抢**——同一端口只能被一个进程监听；本地测试两端必须能区分。
5. **把 UDP 当可靠传输用**——发出去不代表对方收到，顺序也不保证。
6. **只 bind 不 listen 就等客户端**——没有 listen，OS 不会把连接请求交给你；TCP 数据必须先有连接。
7. **`print("hello")` 后怪对方 `readLine()` 不返回**——没换行符就没「一行」，readLine 只能继续等。
8. **两端字符集不一致**——一方 UTF-8 一方 GBK，中文必乱码；务必显式指定同一 charset。

## 🧠 速记口诀

```text
IP 是楼，端口是房间，回环 127.0.0.1
TCP 连了再传、可靠有序；UDP 拿起就发、尽力而为
socket bind listen accept：占地址、等连接、接客户端
监听 socket 等新连接，accept 返回的连接 socket 才读写
四元组（源IP:源端口-目的IP:目的端口）区分每条 TCP 连接
网络 IO 还是流：getInputStream 读、getOutputStream 写，套娃照旧
println 配 readLine，print 不换行对方就卡住；两端编码要一致
一个连接一个线程，线程多了用线程池
```
