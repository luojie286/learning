# 12 · 泛型

> 一句话概括：**泛型默认不变**（`Pair<Integer>` 不是 `Pair<Number>`），运行时**类型擦除**，但类结构声明里的泛型信息能用反射读出来。

---

## 一、泛型是不变的（invariant）

前提：`Integer extends Number`。

但**不能**推出：

```java
Pair<Integer> extends Pair<Number>   // ❌ 不成立
```

```java
Pair<Integer> p1 = new Pair<>();
Pair<Number>  p2 = p1;    // ❌ 编译错误
```

**为什么不让它通过**——因为一旦允许，类型安全就崩了：

```java
Pair<Integer> p1 = new Pair<>();
Pair<Number>  p2 = p1;
p2.setFirst(3.14);        // Double 也是 Number，却塞进了「只该装 Integer」的容器
```

所以记住这个结论：

```text
A extends B
   ↓ 不能推出
Generic<A> extends Generic<B>
```

> 类比：`List<Object>` 不是 `List<String>` 的父类型。数组是「协变」的（`Object[] = String[]` 合法，但运行时会抛 `ArrayStoreException`），泛型则从编译期就堵死了这条路——这是泛型比数组更安全的地方。

---

## 二、通配符：`? extends` 与 `? super`

### `? extends Number`（上界通配符）

```java
Pair<? extends Number> p = new Pair<Integer>();
```

含义：`?` 可以是 `Number` **本身或它的任意子类**，因此下面这些都能赋值给它：

```text
Pair<? extends Number>  ←  Pair<Number> / Pair<Integer> / Pair<Double> / Pair<Float> ...
```

**但不能写入**：

```java
Pair<? extends Number> p = new Pair<Integer>();
p.setFirst(123);          // ❌ 编译错误
```

因为编译器只知道「它是某个 Number 子类的容器」，具体是 `Integer` 还是 `Double` 无从得知——贸然写入就可能放错类型。

> **`? extends` 适合读，不适合写。**

### `? super Integer`（下界通配符）

反过来，`? super Integer` 表示 `?` 是 `Integer` **本身或它的父类**：

```java
List<? super Integer> list = new ArrayList<Number>();
list.add(123);   // ✅ 可以写
Object o = list.get(0);   // 读出来只能是 Object（不知道具体是哪个父类）
```

> **`? super` 适合写，读出来只能当 `Object`。**

### PECS 原则

```text
Producer Extends, Consumer Super
生产者用 extends（只往外读）
消费者用 super（只往里写）
```

| 场景 | 写法 |
|------|------|
| 只读数据源 | `List<? extends Number>` |
| 只写目标容器 | `List<? super Integer>` |
| 既读又写 | 别用通配符，直接用具体类型参数 `<T>` |

典型例子：

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (T t : src) dest.add(t);   // src 读（extends），dest 写（super）
}
```

## 三、类型擦除（Type Erasure）

```java
class Box<T> {
    private T value;
}
```

运行时：

```java
Box<Integer> a = new Box<>();
Box<String>  b = new Box<>();

System.out.println(a.getClass() == b.getClass());   // true
```

**结果 `true`**——因为擦除后它们本质上是同一个 `Box` 类（`T` 被擦成 `Object` 或其上界）。

推论：`box.getClass()` **拿不到**对象原本是 `Box<Integer>` 还是 `Box<String>`。

```text
编译期：泛型信息用来做类型检查
运行期：泛型信息被擦除，只剩原始类型
```

> 这也是为什么 `new T[]`、`new T()`、`list instanceof List<String>` 都不合法。

---

## 四、泛型与反射

关键结论：

> **类型擦除并不彻底**——凡是**写在类结构声明里**的泛型信息（字段类型、方法签名、父类/接口声明）都会保留在 `.class` 元数据里，因此反射**有时能**读到它；而**实例本身**的泛型参数则读不到。

### 4.1 字段上的泛型信息

```java
class Student {
    private List<String> names;
}
```

```java
Field field = Student.class.getDeclaredField("names");

System.out.println(field.getType());          // interface java.util.List
System.out.println(field.getGenericType());   // java.util.List<java.lang.String>
```

| 方法 | 能拿到什么 |
|------|-----------|
| `getType()` | 原始类型 `List` |
| `getGenericType()` | 完整签名 `List<String>` |

### 4.2 解析 `ParameterizedType`

```java
Type type = field.getGenericType();

if (type instanceof ParameterizedType pt) {
    pt.getRawType();                 // List
    Type[] args = pt.getActualTypeArguments();
    System.out.println(args[0]);     // class java.lang.String
}
```

```text
List<String>
 │    │
 │    └── getActualTypeArguments() → String
 └────── getRawType() → List
```

### 4.3 方法上的泛型信息

```java
class UserService {
    public List<String> getNames(Map<Integer, String> map) { return null; }
}
```

```java
Method m = UserService.class.getMethod("getNames", Map.class);

m.getGenericReturnType();       // List<String>
m.getGenericParameterTypes();   // [Map<Integer, String>]
```

| 普通反射 | 泛型反射 |
|---|---|
| `getType()` | `getGenericType()` |
| `getReturnType()` | `getGenericReturnType()` |
| `getParameterTypes()` | `getGenericParameterTypes()` |

### 4.4 父类上的泛型参数（框架常用）

```java
class Parent<T> { }
class Son extends Parent<String> { }
```

```java
Type type = Son.class.getGenericSuperclass();   // Parent<java.lang.String>

ParameterizedType pt = (ParameterizedType) type;
System.out.println(pt.getActualTypeArguments()[0]);   // class java.lang.String
```

> 这就是 Spring 等框架能「自动知道你继承的是 `Dao<User>` 还是 `Dao<Order>`」的原理——**泛型信息不会丢在子类的类声明里**，反射顺着父类签名就能读出来。

### 4.5 总结

- **实例**的泛型参数 → 类型擦除，读不到
- **字段 / 方法 / 父类 / 接口声明**上的泛型信息 → 可以用反射读

---

## 📌 易错点

1. **`Integer extends Number` 推不出 `Pair<Integer> extends Pair<Number>`**——泛型默认不变，这是最常见的思维惯性错误。
2. **`? extends T` 只读不写**——往里 `set` 编译就报错；别以为「extends 就是可以随便塞子类」。
3. **`? super T` 读出来只能是 `Object`**——它能写，但读出信息量少。
4. **不能 `new T[]` / `new T()`**——类型擦除的直接后果；需要时用 `Array.newInstance` 或反射。
5. **`list instanceof List<String>` 编译不过**——运行时没有 `List<String>` 这个类型，只能 `instanceof List`。
6. **`getType()` 拿不到泛型参数**——要 `getGenericType()`，并且强转成 `ParameterizedType` 才能取到实际类型参数。
7. **对象实例的泛型参数拿不回来**——`new Box<Integer>()` 和 `new Box<String>()` 是同一个类。

---

## 🧠 速记口诀

```text
泛型不变：A extends B ≠ Generic<A> extends Generic<B>
上界 extends 只读，下界 super 只写 —— PECS：生产者 extends，消费者 super
编译期检查，运行期擦除；实例泛型丢了，声明泛型还在
字段 getGenericType()、方法 getGenericReturnType()、父类 getGenericSuperclass()
拿到 Type 后 instanceof ParameterizedType，再 getActualTypeArguments()
```
