# 01 · 嵌入式与 STM32 基础

> 一句话概括：**单片机是嵌入式控制的核心，STM32 是其中基于 ARM Cortex-M 内核的一类 32 位单片机**，而寄存器是你能直接拨动的、最底层的开关。
>
> ⚠️ 说明：原始笔记（`arm 寄存器介绍.md`）已覆盖单片机 / STM32 / 寄存器 / 两种编程方式四块，本文在其基础上规范化并补全。

---

## 一、什么是单片机

- **定义**：一种把**计算、控制、存储**等功能集成在一块芯片上的微型计算机系统
- **别名**：MCU（Microcontroller Unit，微控制器）
- **地位**：**嵌入式控制的核心**，同时也是程序的执行者

和 PC 的区别：PC 是「通用计算」，单片机是「**专用控制**」——它通常只干一件事，但要长期稳定、低功耗地干下去。

---

## 二、什么是 STM32

| 维度 | 说明 |
|---|---|
| 分类 | 属于 **32 位单片机**的一类 |
| 内核 | 基于 **ARM Cortex-M** 内核 |
| 特点 | **高性能、低功耗、外设资源丰富** |

### 两个容易搞混的点

**① ARM 和 STM32 不是一回事**

```text
ARM   → 设计「内核」（IP 授权），自己不生产芯片
ST    → 买 ARM 内核，加上自己的外设和 Flash，做成 STM32 芯片
```

所以会说「STM32 用的是 ARM Cortex-M 内核」，而不是「STM32 就是 ARM」。

**② Cortex-M 内核家族**

| 内核 | 定位 |
|---|---|
| Cortex-M0 / M0+ | 低端、超低功耗、成本敏感 |
| Cortex-M3 | 主流通用 |
| Cortex-M4 | 带 **DSP 与浮点（FPU）**指令，适合信号处理 |
| Cortex-M7 | 高性能 |

STM32 各系列大致对应：`F0/L0 → M0`、`F1/F2 → M3`、`F3/F4/L4/G4 → M4`、`F7/H7 → M7`。

> STM32 型号名通常由「系列 + 子系列 + 引脚数 + Flash 容量 + 封装 + 温度等级」拼接而成，例如 `STM32F103C8T6`——需要精确含义时查选型手册，不必死记。

---

## 三、什么是寄存器

- **定义**：CPU 内部一小块**临时存储区**，用于存放运行中要使用的数据
- **作用**：在 STM32 中，用于**快速存储当前正在使用的数据**

### 一个必须理解的本质

在 STM32 这类单片机里，**外设寄存器其实是「映射到特定内存地址的硬件单元」**——你往某个地址写一个值，对应外设的引脚电平/工作模式就真的变了。

```text
写内存地址 → 硬件动作
（不是"把数据存起来"，而是"命令硬件做什么"）
```

这就是为什么「寄存器编程」能精确控制硬件：**你直接操纵的是硬件的行为**，中间没有任何库在替你翻译。

---

## 四、寄存器编程 vs HAL 库编程

| 编程方式 | 特点 | 优点 | 缺点 |
|------|------|------|------|
| **寄存器编程** | 直接操作底层硬件寄存器 | 控制精度高、性能最大化、代码体积小 | 开发复杂、难度大、可读性差、换芯片要重写 |
| **HAL 库编程** | 调用 ST 提供的 HAL 库接口 | 开发更简单、**移植性好**、可读性高 | 性能有所牺牲（比寄存器多几层封装） |

### 怎么选

```text
学原理、抠性能、资源极度受限  → 寄存器编程
做项目、赶进度、要跨型号移植  → HAL 库编程（主流选择）
```

> **推荐的学习路线**：先用 HAL 把功能跑通，再挑一两个外设（如 GPIO、串口）回去看寄存器版本，理解 HAL 到底帮你做了什么——**这样既会用工具，也知道工具背后是什么**。

---

## 📌 易错点

1. **把「ARM」和「STM32」当成一回事**——ARM 卖的是内核 IP，STM32 是 ST 用 ARM 内核做的芯片。
2. **以为寄存器只是「存数据的地方」**——在单片机里它更是**控制硬件的开关**，写值 = 下命令。
3. **一上手就啃寄存器编程**——容易卡死在手册里，先用 HAL 跑通功能再回头理解更高效。
4. **以为 HAL「性能差」是缺点**——它是**用性能换开发效率**的自觉取舍，多数项目完全够用。
5. **混用寄存器和 HAL 却不处理冲突**——HAL 初始化过的外设，你再去裸写寄存器可能互相覆盖。
6. **Cortex-M0 与 M4 混淆**——不是所有 STM32 都带浮点单元；没有 FPU 的型号做浮点运算会慢很多。

---

## 🧠 速记口诀

```text
单片机 = 计算 + 控制 + 存储集成在一块芯片上，是嵌入式控制的核心
STM32 = 32 位单片机 + ARM Cortex-M 内核 + 高性能低功耗外设丰富
ARM 卖内核，ST 做芯片 —— 两者不是一回事
寄存器 = 映射到内存地址的硬件单元，写值就是下命令
寄存器编程：精度高、难度大、难移植
HAL 编程：开发快、易移植、性能有牺牲
先 HAL 跑通，再回看寄存器
```
